# 觀察點機制（Observer）與空間 LOD

> 決定「世界的哪些部分現在需要高解析度」。**取代了先前「同時只有一個 Active Site」的簡化假設。**
> 姊妹機制是 [significance.md](significance.md)（決定哪些**實體**需要個別計算）。
> 生命週期的落地見 [interface-lifecycle.md](interface-lifecycle.md)。
> 通用原則見 [principles.md](principles.md)；用詞以 [glossary.md](glossary.md) 為準。

## 一句話

> **Observer 是一個「這裡需要看清楚」的理由。** 它從某個位置向外輻射，
> 讓周圍以及上下層的地圖獲得較高的模擬解析度。

沒有任何 observer 照到的地方，就退回 Region 層的低解析度權威模擬——
那正是 [interface-world-mid.md](interface-world-mid.md) 說的「Region 是唯一真相」。

## 只有一個根，其餘都是子觀察點

> **真正的觀察點只有一個：玩家。** 其餘全部是從它**分出去**的子觀察點，
> 掛在事件、物件、地點上。

```
玩家（根 observer，恆 pinned）
├─ 子：劇情「勇者覺醒」        ← 事件產生的
├─ 子：被 mark 的「商人瑪莎」   ← 玩家在乎產生的
├─ 子：進行中的「石橋鎮圍城」   ← 大事件產生的
└─ 子：玩家擁有的「北關要塞」   ← 所有權產生的
     └─ 孫：要塞裡的守將        ← 子觀察點還能再分
```

這是一棵**樹**，不是一個平坦的來源清單。這個結構買到四件事：

| 好處 | 說明 |
|---|---|
| **可追溯** | 每個子觀察點都能回答「為什麼這裡值得算？」——順著父鏈走回玩家 |
| **可回收** | 父消失（劇情結束、mark 撤銷）→ 整棵子樹一起回收，不會留下孤兒 |
| **預算可分配** | 從根往下分配 LOD 預算，而不是所有來源平等競爭 |
| **強度有來源** | 子的 `strength` 由父衰減而來，不是各自拍腦袋定的常數 |

| 子觀察點的產生原因 | 何時消失 |
|---|---|
| 玩家 mark 某個對象 | 撤銷 mark，或超出 mark 預算而降級 |
| 進行中的大事件（攻城、災變、劇情場景） | 事件結束 |
| 高 significance 實體所在處 | 該實體 significance 掉到門檻以下 |
| 玩家的所有權（城市、部隊） | 失去所有權 |
| 劇情腳本顯式掛上 | 腳本撤除或劇情推進 |

**子觀察點不需要玩家在場**——這正是重點。它讓「玩家不在場但仍在推進的重要劇情」成為可能，
也讓玩家 mark 過的遠方城市持續被模擬。

**觀察點還是獨特物件的登記處**——見 [unique-objects.md](unique-objects.md)。
它不只輻射解析度，它同時**持有**因它而變得獨特的那些人事物的記錄。

而且 observer 不只決定「哪些地方要載入」，也決定**事件要算多細**——
見 [events.md](events.md) 的主場層。三條 LOD 軸全部掛在 observer 底下。
玩家自己**站在哪一層**則是另一回事，由他主動選擇，見 [player-residence.md](player-residence.md)。

## 輻射：三個方向

一個 observer 掛在某個 zone 的某個位置上，向三個方向輻射：

```
        ↑ 向上：所屬的上層 zone（Site observer → 其 Region）
   ← 同層鄰域 ●observer 同層鄰域 →
        ↓ 向下：其下方的若干 Local zone
```

| 方向 | 範圍 | 說明 |
|---|---|---|
| **同層** | 半徑 R 格（依強度） | 玩家在某 Site，鄰近數個 Site 也被拉起來 |
| **向上** | 恆為 1 層 | 上層 zone 必定 active。Region 本來就永遠在跑，所以這條多半是免費的 |
| **向下** | 玩家腳下與鄰近的數格 | 開放世界式串流：只載入周邊的 Local |

**向上永遠比向下便宜**，因為上層格數少。所以「一個 observer 拉起整條垂直鏈」的成本主要在向下那一段。

## LOD 等級

輻射的結果不是布林的「active / 不 active」，而是四個解析度等級：

| 等級 | 記憶體 | 每回合做什麼 |
|---|---|---|
| `L_FULL` | 完整三層資料 | 逐回合模擬，個別實體都算 |
| `L_COARSE` | 骨架 + 持久層 | 只跑聚合統計，個體合併進團體算 |
| `L_FROZEN` | 只有 `SiteDigest` | 不跑。被查詢時才即時投影出答案 |
| `L_ABSENT` | 0 | 不在記憶體，只有磁碟上的 digest |

用四級而不是兩級的理由：玩家所在 Site 的鄰居應該「有在動」（商隊會來、敵軍會逼近），
但不值得逐格逐人地算。`L_COARSE` 就是給它們的。

## 場強計算

每個 zone 的 LOD 由所有 observer 的最大貢獻決定：

```
score(zone) = max over observers of ( obs.strength − travel_cost(obs, zone) )
```

- `travel_cost` 用**跨層的距離**：同層走格數、跨層加一個固定的層間代價。
- 分數落在門檻區間決定 LOD 等級。門檻是可調參數。
- Region 層恆為 `L_FULL`（它是權威模擬，格數少、必須一直跑）。
  這條機制只實際作用在 L2 與 L3。

計算時機：Region 回合結算時重算一次全域場；Site 回合時只增量更新玩家附近。
**場的計算本身必須是確定的**——它決定了哪些 zone 被模擬，因此直接影響遊戲結果。

## 預算與逐出

場強再怎麼算，記憶體還是有限。所以在場強之上還有一層硬預算：

- `L_FULL` 的 zone 數有上限，超過就按 `score` 由低到高逐出到 `L_COARSE`。
- `L_COARSE` 同理往下降到 `L_FROZEN`。
- **`pinned` 的 zone 永不逐出**（玩家所在、進行中的大事件）。
- 逐出只在**回合結算的尾端**執行，絕不在模擬途中——避免懸置指標與同回合的迭代器失效。

這比單純的 LRU 好：LRU 逐出的是「最久沒碰的」，場強逐出的是「最不重要的」，
語意直接對應玩法。medps 的 `zone-addressing-lifecycle-design.md` §3.6 用的是
LRU + `pinned`，aetheria 把 `last_touch` 換成 `score`，其餘機制（tick 尾端逐出、
pinned 第二道防線、id tie-break 使逐出順序可測）照抄。

## 成長軸不變量

直接繼承 medps 的驗收準則，不打折：

> **任何持久或常駐結構的成長軸，只允許是「已載入 zone 數」（RAM）
> 或「已造訪 zone 數」（磁碟），絕不允許是世界總 zone 數。**

推論：observer 清單掛在**產生它的實體**上，不維護全域索引；
場強是**每回合算出來的暫態**，不序列化；zone 的磁碟路徑由 id 推導，不存清單。

## 一個 observer 拉起多少東西

粗估玩家單獨一個 observer 的規模：

| 層 | `L_FULL` | `L_COARSE` |
|---|---|---|
| Region | 1（恆為 FULL） | — |
| Site | 1（腳下） | 鄰近 4～8 |
| Local | 腳下 + 鄰近 8 | 再外一圈 16 |

加上數個 mark 產生的次要 observer，同時 `L_FULL` 的 zone 大致在 20～40 個量級。
這是預算參數的初始估計，實際值等 M4 實測。
