# 事件升級與「不會算兩次」

> 從 [interface-world-mid.md](interface-world-mid.md) 拆出。那份講**兩層狀態怎麼對應**，
> 這份只回答一件事：**兩條通道同時存在，為什麼帳不會被計兩次。**
> 通用原則見 [principles.md](principles.md)。

## 第二條通道：事件升級

歸約量表處理的是**連續量**（人口、產出、戰力）。但有些事不是量的變化，
而是離散的、當下就該讓世界知道的：城破了、領主死了、神器被挖出來了。

這類事走**事件升級**通道，機制與實體共用同一套重要性等級（見 [significance.md](significance.md)）：

> Site 內發生的事件，若重要性 ≥ `Region` 級，**立即**升級成 Region 事件並改變 Region 狀態，
> 不等每旬的數值歸約。

| Site 事件 | 重要性 | 後果 |
|---|---|---|
| 某工坊完工 | `Site` | 併進每旬歸約的數字 |
| 糧倉焚毀 | `Site`～`Region` | 依規模決定是否升級 |
| 城破、領主被殺 | `Region` | 立即改 `tile.owner`，觸發外交連鎖 |
| 神器出土 | `World` | 進世界圖，所有勢力都收到消息 |

**兩條通道加起來才是完整的 L2 → L1 界面。** 只有歸約通道的話，
玩家會發現「城池已經淪陷，但外面的世界要到下個旬才反應過來」——那是設計錯誤。

升級的事件同樣要走「不算兩次」規則：升級事件已經改過的量，該旬的歸約不得重複計入。

## 為什麼不會算兩次

這是最容易出錯的地方，規則只有一條：

> **產出由 Site 算的那一旬，Region 就不自己算。**

`RegionTile` 上有 `bool has_live_site`。Region 的第 5 步世界模擬遇到 `has_live_site == true`
的格子時，**跳過自己的產出公式，直接採用 Site 歸約上來的數字**。
Site 不在時才用 Region 自己的近似公式。

這也意味著兩套公式必須**校準**：對同一個 Region 狀態，
`reduce(project(state))` 應該約等於 Region 自己的近似公式算出來的值。
差太多會造成「玩家一進城，城市產出就跳一階」的荒謬感。

**這是一條必須自動化的測試**：對隨機取樣的 1000 個 Region tile 狀態，
`|reduce(project(s)) − region_formula(s)| / region_formula(s) < 5%`。
