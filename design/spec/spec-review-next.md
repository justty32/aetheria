## 後續怎麼用

- 討論整體方向時用收斂主線；問到某種行為才進所屬領域。
- 只有典型情境無法接到下一步，或兩篇對同一結果說法衝突時，才補那個缺口；不為湊更多案例持續擴張。
- 既有案例是不同選擇的推演，不是固定劇本。DQ 是暫定背景，不因此加入固定勇者、必勝故事或所有原作機制。
- [選項表](spec-decisions.md) 是比較材料，D01–D05 沿 [簡單方向](spec-foundations-review.md)。數值、少見例外與具體算法留到需要時；沒有一串必須先請使用者作答的題目。

## 保留的界線

最新使用者方向在 [規劃尺度](spec-planning-scope.md)：先有三層世界與 NPC 自主行為，再讓使用者提供人物的決策；世界與人物分檔、同世界多人物已定。普通任務用 sol，簡單整理用 terra／luna，對話與文件用繁體中文、大白話。

- 本次只做設計。玩家操作體驗與程式實作後置，不自動開實作任務；`spec-play-*` 留作備考。
- 三層共用人貨與時間，真實結果和各自知情分開。粗算不能憑空補國力，無人類命令不代表全員常駐或新增 observer。
- 純 C++ 玩法／Godot 呈現分工、mark 與 root 擱置、M10 全 def 與 M11 腳本追加邊界保留。範例不縮小原開發範圍。
- 每份文件不超過 8 KB；沿現有層級維護。進度只改實作者區塊，保留尚未完成的工作。
- 使用者已授權 commit／push；驗證後同步。公司 WSL 五點關機前若仍有工作，留下可接續的 open 狀態。
