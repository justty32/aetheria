## 原七情境的驗證入口

**目前先跑純 NPC 的推演：**每個情境先讓相關 NPC／組織完成察覺、決定、執行、回報與重議，包含失敗和無可行方案的出口，不接受「等玩家來做」補缺口。三層運作完整後，再比較使用者替換同一人物的決策來源；不是現在先做 UI 或手感驗收。流程入口見 [共用運作](../common/README.md)。

[世界情境](../../../wf/workflows/plan/living-world/world-scenarios.md) 仍是需求來源，不重新編另一組故事。

原七情境的自主行為串接見 [純 NPC 推演](../common/cases/spec-world-cases.md)。另查照護消息是否真正進入人物選擇，以及機構失去師資後是否停止相關服務；文件推演不代替可執行測試。

1. 乾旱到遷徙：另加整合 A 的洪災 fixture；區分庫存、暴露、在途與稅債。
2. 繼承戰爭：整合 C；另測同時死亡、空缺、和平承接，不只內戰成功分支。
3. 修牆到守城：固定建物版本，Local 修復成本由 Site 工作領出；未參戰區仍結算，退出後缺口仍在。
4. 遺跡知識到社會改變：整合 B；另測書已取但不懂、懂但缺設備、傳送改供需及停供。
5. 工作到人物經歷：材料 10 中 4 已耗，取消只返未耗 6；傷者不能繼續滿額生產，關係更新一次。
6. 進行中加入新文明：全 def／各實體使用端加獨立 M11 腳本案，兩角色、壞引用、來源不足、重送與崩潰分開驗。
7. 長期無人觀看：相同總 Tick，比較純 Region、固定駐留、頻繁切層；保持策略與資訊條件可比，記錄外部因果與成本。

原情境四／七另查野外與超常來源：Local 領出的野獸不再參加同段群落捕食；沒有探險者時，遺跡居民仍有需求與行動；召喚搬運者失效後不得繼續交貨。三者均要核對回到粗算及讀檔後的同一份數量、貨物與未完工作。

四塊行為另依 [整體核對](spec-behavior-review.md) 比較選擇與後果。只驗帳目無重複還不夠：永遠等待也可能帳目正確；須查相關條件改變後，候選、理由及後續安排能否合理回應。

## 反例注入與故障點

為每個正測加入一個刻意違規版本：多返一份材料、重複 receipt、使用過期知識版本、跳過死亡、改冷卻、亂數換全域來源。至少一條相應斷言必須紅，否則測試可能沒有辨識力。

在日誌寫入前後、快照／角色檔寫入間、commit marker 前後模擬中止。恢復只承認可驗的完整提交，對尾筆截斷、manifest 不一致、規則 hash 不符有明示錯誤／恢復點。不能先吞檔再宣稱重放一致。

需要保留 fixtures 的基底版本、命令、時間、控制角色、注入、預期不變量與容差理由；浮動 golden hash 不是領域守恆的替代品。跨版本若無相容承諾，測明確拒絕而非硬比較同 hash。
