## 四類正確性不要混用

| 類別 | 比較條件 | 判準 |
|---|---|---|
| 精確領域帳 | 相同已提交效果與交接 | 人貨位置、預算、義務、唯一結果及時距精確相符；明示創設／赤字另有來源 |
| 重放 | 相同基底、版本、輸入／注入日誌、控制交接與規則配置 | 世界／角色／規則摘要相同；拒絕命令保持未套用 |
| 粗細近似 | 相同世界條件、知識、總 Tick、策略及無額外介入 | 預先列統計量、配對樣本與容差；均值、尾部風險及方向偏差分開 |
| 玩家介入 | 同起點但不同合法策略／指令 | 改變來自合法成本與行為，符合相應 δ 政策；不強求同一結果 |

不同觀察路徑若改了模型或決策，不可宣稱必有逐 bit 同 hash；也不能用近似容差原諒精確帳多出一份糧。δ 是否適用某一非戰鬥系統須明示，不讓所有玩家行動都被一個通用上限裁掉。

## 效能與長局成長

量測配置需記地圖數、人口／羣組、具名人物、活躍 Site／Local、在途任務、歷史長度、內容量及硬體。先做可重複的基準，再定門檻，不編造已達標數字。

| 成本 | 量什麼 | 可接受的降成本方式／不能做的事 |
|---|---|---|
| 推進 | 各階段耗時、到期隊列、AI 候選數、最長切段 | 合併安全區間／減搜索；不能漏外部到期效果 |
| 切層 | 準備、交接、生成、首快照、峯值記憶體 | 分塊準備與可取消；不能先顯示未提交世界 |
| 長局記憶 | 羣組／具名／主張／因果／工作隨時間增長 | 壓縮無未完引用的歷史；不能丟債、血緣與任務錨點 |
| 存檔與恢復 | bytes、檔數、增量、冷載、重放與首分歧定位 | 可驗 checkpoint、既有 store 窄介面；不先改 SQLite |
| 畫面 | snapshot bytes、dirty 區、列表、幀延遲與素材佔用 | 虛擬化／降視覺細節；不減真實部隊或玩法效果 |

root 成長只量測與標記風險，不藉效能規格解除擱置。長期歷史能否安全壓縮須用仍被引用的繼承、財產、知識和事件測例證明。

## 執行狀態與放行

目前只做文件檢查與桌上推演，沒有在本輪跑上述 runtime 測試。實作基線已有多角色重放、拒絕命令與損毀恢復等缺口；應在後續 plan 的前置列出，不讓玩法展示掩蓋。

放行順序建議：先選 D01–D05 → 共用契約反例可驗 → 一條完整世界鏈 → 其他領域整合 → 長局校準及正常 UI 驗收。這是規格驗證依賴，不是本輪開工或另起里程碑的授權。
