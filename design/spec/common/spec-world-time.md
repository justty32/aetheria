# S1：時間、效果提交與中斷

## 範圍

草案；依 [時鐘權威](../../simulation/time-clock-authority.md)、[時間型別](../../simulation/time-model.md) 與 [S0](spec-world-handoff.md)。步長只引用 [大綱](../../outline.md)，不新增一條戰爭／生活時鐘。

**Done when：**長途等待、Local 插入、跨旬及途中存檔有唯一時間線；遠方到貨與斷路不遲到；同一段工作不因切換步長多產出。

## 推進與因果

每個系統登記：上次已算時點、下一到期時點、輸入依賴、輸出領域、可否延後、可能中斷條件。這些是游標／時戳，不是可自行前進的現在時間。

協調器把請求推進區間切在已知到期事件、旬界或合法中斷點。到邊界 `t` 時：

1. 各責任範圍結算 `[前一邊界,t)`，先完成被其他系統讀取的前置輸出。
2. 對 `t` 的到期效果依明訂依賴排序；同階段同優先使用穩定鍵，不能用容器位置或執行緒完成順序。
3. 驗證並提交效果及後續通知；只有成功結果進入世界事實。
4. 旬界報表／財政讀取已完成且應納入的結果，不重新算已委派區間。
5. 在既有回合尾執行結構變更順序，再提供可保存狀態與玩家觀測。

此順序是共用因果約束，不裁定方陣出手序。現存 callback 能否直接符合須留實作對照，不能當成現況保證。

同時生效的「橋修好」與「商隊到橋」要由旅行規格明訂：建議先套環境通行變更，再判進入合法性。不是任意排序鍵碰巧令修橋先跑。未有因果規則的領域競爭須顯式仲裁。

## 命令與結果

命令記錄發令者、授權、提出時點、目標、已知前提及識別；結果分拒絕、接受待執行、部分執行、完成、取消／失敗。接受不代表成功，玩家／AI／腳本共用此區分。

- 預驗證失敗：不產生成功代價或產物，記原因；不以拒絕訊息透露未知敵情。
- 執行途中路斷：保留已移動、已耗工時與材料，停止未完成部分；退款政策由領域規格決定。
- 跨領域一次提交：先預驗證所有效果，再提交一致結果。提交失敗回到前一一致點；不得以遊戲內「退款」掩蓋半筆寫入。
- 任務獎勵、政治變更等由成功事實衍生，在具名後續階段執行，不遞迴無限觸發同一事件。

依賴環不是把所有循環配方都禁用：有成本、跨時段的生產循環合法；同一提交階段無法排序的讀寫循環須拆時段或拒絕。到期工作超出處理預算時停止於一致邊界並回報，不能跳過事件假裝完成等待。

## 中斷與離場

玩家請求等到目的地，不代表沿路戰爭、斷糧、死亡與期限可忽略。建議中斷分為必停（死亡、控制角色失能、必須選擇）與可依委任處理（改道、一般缺料）；通知偏好不改事件是否發生。

新事件落在原定大步長內，就在相應合法時點切段；已花時距不重置。步長決定操作節奏，產量依實際有效工時／資源積分或相應離散規則，不依「跑幾次回合」乘固定產量。

未載入地方的對外事件仍由權威排程發布；只有對外無先行影響的細節可按需補算。查詢依賴落後時先補齊，不回傳看似目前的過期庫存。

人物失能／死亡、工作完成／取消或供應失效時，所屬領域提交變化，沿直接依賴安排受影響工作重驗；不靠全世界 AI 每輪掃描找出。客觀上不可執行的步驟立即停止於合法邊界，未耗預約依工作規則處理。這是執行條件重驗，不是向遠方決策者免費送消息：其改案仍等實際通知、自身觀察或原定檢查點，並沿 [AI 等待流程](spec-ai.md) 接續。

## 存讀與重放邊界

建議只在完整提交點接受世界快照；使用者於執行途中要求保存時排到下一一致點，介面顯示尚未完成保存。可分段的長工作因此能中途存，未提交的半個領域交易不能存成成功。

保存時鐘、各游標／到期工作、交接、未完命令、亂數狀態或等價重建資訊、規則版本與歷史頭。載入不補跑已提交區間；重放包含被拒命令的未套用語意。崩潰恢復須驗證快照與歷史一致，損毀時明確拒絕或使用經驗證的恢復點，不默默吞尾筆。

## 驗收與待裁定

1. 邊界前工作已耗 3 份材料，邊界後取消：只釋放未耗份，存讀後仍是 3。
2. 同一有效工作時距拆成不同合法步長：資源帳完全一致；取整餘量延續，不每回合截斷丟失。
3. 遠方橋梁失守早於商隊到達：即使玩家在地城，商隊仍停／改道，不能穿橋後追補失守。
4. 旬界之前 Local 已交戰損：報表只收一次；打亂登記容器順序不改結果。
5. 注入同時點依賴環與重送結果：能辨識失敗，最後一致快照仍可載入。

待裁定：同時點領域優先表、必停清單、交易持久化格式與恢復策略。數值誤差界線沿用校準規則，未填前不宣稱測試已通過。
