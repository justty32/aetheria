# S11a：內容定義、追加與版本

← [本層入口](README.md)｜[注入裁定](../../wf/workflows/plan/runtime-injection-decisions.md)｜[擴展架構](../rules/rules-extensibility.md)

## 範圍與完成條件

草案。Done when：所有領域的新種類、實體與劇情可加入同一世界且有來源、版本、驗證及恢復；舊規則不被安裝目錄更新偷偷改掉。M10 全 def 追加與 M11 腳本／內容包追加分開，不用新規格縮小原承諾；不實作編輯器或遷移工具。

## 三層與共同語意

Region 接新文明／勢力／環境種類，Site 接聚落／工作／編制，Local 接人物／物品／能力／對話；三層引用同一世界規則集。內容協調器管定義批次與規則版本，各領域管實體創設及初始狀態，不能用包管理器直接改任意容器。

定義是種類、實例是本局對象、腳本是受限編排、素材是呈現資產。持久引用用命名空間字串 ID，runtime 下標只可追加；個別命名、材料、品質與研究所得配方實例不必每件都新增 def。

包宣告 id、版本、內容雜湊、依賴／衝突、機制相容需求、定義／腳本／文字／素材清單、來源與授權說明。版本號表達作者意圖，不代替內容 hash；同 id 同版本不同內容不可假裝等同。

## 驗證與提交

接收 → 正規化 → 驗 schema／容量 → 解依賴 → 影子 Ruleset → 領域預驗證 → 入日誌 → 回合尾一致提交 → 發布 revision。這是邏輯契約，沿用既有 journal-first 與 commit marker，不先指定新檔案格式。

- 檢查引用存在及型別、全域 ID 唯一、數值範圍／單位、能力來源、效果權限、生成前置、文字參數和消費端支援。
- 依賴包無環；生產配方可有跨時間有成本的循環，不能以拓樸排序一律禁掉。靜態檢查無法證明任意腳本無免費產物，還需領域驗證及行為測例。
- def 批次先於引用它的實體；一次文明組合包全過才生效，失敗不留半座城。錯誤列包、檔案、欄位、對象與原因，不只回失敗。
- 重送同請求同內容回原結果；同鍵異內容拒絕。預覽不是承諾資源，提交時仍驗領地、資產與版本。

## 創設不是偷偷回寫歷史

新勢力明示開拓、分裂、小部族成長等來源；首個 M10 來源仍是無主地開拓。已有佔領／所有權不得被一般開拓命令覆蓋。人物有出生／遷入／沙盒創設來源、位置與羣組扣量；物品有製作／轉移／創設來源。

沙盒明示創設可帶新人口／資源，但必須記外部注入量，不冒充既有城市自然生產。加入古文明設定不自動在已探索地面插入古城；若要補生成，作從加入時點生效的具名事件並驗衝突，不能偽造玩家過去走過的地形。

新 def 可存在但未有實例；驗收還要證明能被選取、生成、使用、AI 評估與存讀，不能只有載入成功。新增地形不重生成整個既有世界，新法術不自動教會所有法師。

## 規則保存與失敗恢復

基底 raws 建世界時複製且不改；追加 def 只由歷史日誌重建，不又寫回基底造成套用兩次。M11 建議世界保留實際腳本原文、內容雜湊、沙箱／語意版本，不能只存本機腳本路徑或不可攜 bytecode。

修改／刪除既有定義、包移除、歷史截斷皆不屬現行追加；若未來需要，另作世界分支／轉換契約。舊熱重載「同 ID 覆寫」只適用開發實驗，不能旁路改正式世界。

保存規則與世界狀態的同一提交頭；載入先驗基底、日誌與必要版本，再重建引用。未知玩法版本、缺腳本、hash 不符須停止，提供最後可驗一致點，不默默使用安裝目錄最新版。崩潰不等於遊戲內失敗退款。

## AI、內容作者與驗收

每個命令／效果原語都需權限、代價、目標、時間及拒絕語意，新增資料只能組合已有原語；新機制才需 C++。AI 候選生成須讀新定義，不能所有新兵種永遠不被招募。

- 全 def 類型各追加一筆，實際使用、保存、載入、重放一致；不是隻測文化／人物／物品。
- 一包合法兩筆、第三筆壞引用：全部零生效；重送修正須新請求鍵。
- 包創設 10 人，後續再從舊村移 3：新地 13、舊村少 3，注入來源只有 10。
- 全域 raws 更新後舊世界不變；篡改世界腳本拒絕而非自動修好。
- 正在看的 Site 收到追加：先提交再換快照；舊畫面指令重新驗證，不用新 def 錯解舊下標。

待裁定：包相容協定、沙盒創設可用權限、M11 原文保存佈局與補生成預算。版本數字由實際整合決定，本規格不預升存檔版本。
