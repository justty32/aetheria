# 規劃做到哪裡就好

← [本層入口](README.md)

## 使用者方向（2026-09-10）

「不要太過細節（太早訂死），不然會缺失靈活性」、「我們這只是遊戲，有些東西不要太認真，不然不好玩」。一般規劃取捨交由 agent 判斷，不把每個邊角問題都交回使用者裁定。

這是目前活世界草案的閱讀與續作準則。已有文件列出的細則是候選材料，不等於首版都要做；明確擱置的 mark／獨特物件與 root 成長仍擱置。尚未授權實作。

## 先定玩家會感受到的事

- 玩家能做什麼選擇，為什麼值得選，有什麼看得懂的後果。
- 三層地圖切換能接續同一件事；不能重複領人、物資或獎勵。
- 花掉的代價與重要後果要留下。具體怎麼記、算多細，可以調整。
- 同樣的輸入能重現同樣的結果，方便測試與解釋；這不要求模擬每個現實細節。

每個題目先用一個正常例子和一個明顯穿幫的反例檢查。只有發現會破壞主要玩法的問題，才繼續往下挖。

## 留到需要時再定

人口補帳算法、同刻事件細部順位、撤職交易責任、停火送達與賠償流程，都先留可替換方案。首個可玩版本只選一套簡單、能說明的處理，不要求先建出所有制度選項。

法律爭議可先用一個事件與簡單後果表達；遠方生活可按群組與摘要推進。若更細的模擬沒有增加有趣的選擇，就不增加它。允許規則化、戲劇化與合理近似，但不能把資料錯誤或重複結算說成遊戲性。

數值、公式、完整欄位、全部罕見例外不在本階段定死。試玩後覺得麻煩或不好玩，可以換算法、合併步驟、縮小模擬範圍；需要改掉既有明確裁定時，明列變更，不偷改。

## 什麼時候才問使用者

一般細節由 agent 選簡單的暫行方案並記理由。只有會改變遊戲核心體驗、推翻使用者明確取捨，或需要使用者自己的偏好／實際體驗時才集中詢問。不因多想到一個例外，就新增一個待使用者項。

**Done when：**一個玩法能說清楚「玩家做什麼、付出什麼、世界怎麼變」，且已知的主要漏洞有可行出口，就足以結束這一層規劃。是否好玩留給之後的可玩驗證，文件不能代替試玩。
