# 美術工作流（AI 生成）

> 使用者將以 **AI 生成為主**。這份講怎麼讓 700 張 AI 生成的素材**看起來像同一個人畫的**。
> 規格見 [art-specs.md](art-specs.md)。
> 通用原則見 [principles.md](principles.md)；用詞以 [glossary.md](glossary.md) 為準。

## 唯一的真問題：風格漂移

AI 能畫出很好看的單張素材。它做不到的是**七百張都一致**。

漂移的來源：模型的隨機性、prompt 的細微差異、不同批次、不同時間、
甚至同一組參數兩次生成的光源方向都可能不同。

**對策不是「要求 AI 更一致」，是「生成後用確定性的處理拉齊」。**
這與程式碼那邊的決定論是同一個哲學：不可控的部分收窄，可控的部分做死。

## 四道閘

```
1 錨定  → 2 生成 → 3 後處理（確定性）→ 4 驗收
                ↑                        │
                └────── 不過就退回 ──────┘
```

### 閘一：錨定

**先做一組「風格聖經」，之後所有生成都以它為參照。**

| 錨 | 內容 |
|---|---|
| **參考圖組** | 10～20 張人工挑選／修過的代表素材，涵蓋地形、建築、角色、物件 |
| **色盤** | [art-specs.md](art-specs.md) 的 48～64 色，做成一張色卡圖 |
| **prompt 模板** | 固定的前綴與後綴，只有中間的主體描述會變 |
| **反向 prompt** | 明確排除：寫實、灰褐濾鏡、多重光源、粗輪廓、3D 渲染感 |

prompt 模板的形狀：

```
<固定前綴：風格、視角、光源、色調>
<主體：這一張畫什麼>
<固定後綴：尺寸、去背、無文字>
```

**前後綴一個字都不准改**。要調整風格就改模板本身並**重生成整批**，
不要讓新舊模板的產物混在一起——那是漂移的頭號來源。

### 閘二：生成

- 用參考圖做 style reference／img2img，**不要純 txt2img**
- **記錄每張圖的生成參數**（模型、seed、prompt、參考圖）到一個 sidecar 檔。
  這讓「這張為什麼跟別人不像」可以被追查，也讓局部重生成可重現
- 一次生成一整類（所有地形一批、所有家具一批），**不要跨類混批**

### 閘三：後處理（這一道最關鍵）

**確定性的腳本，不是人工修圖。** 每張圖都跑同一條管線：

| 步驟 | 做什麼 | 解決什麼 |
|---|---|---|
| 1 裁切對齊 | 對齊到 64×64 格線，去背 | 尺寸與偏移不一致 |
| 2 **色盤量化** | 映射到專案色盤（有序抖動或最近色） | **色調漂移** |
| 3 **光源正規化** | 偵測主光方向，旋轉／重打陰影到左上 | **光源方向不一致** |
| 4 輪廓統一 | 統一輪廓線寬與色（地形無、物件有） | 線條粗細不一 |
| 5 邊界處理 | tile 的四邊做無縫檢查與修補 | 接縫可見 |
| 6 命名歸位 | 依 def id 映射到路徑（[art-specs.md](art-specs.md)） | 手動命名出錯 |

第 2、3 步是主力。**色盤量化幾乎能救回所有色調漂移**，
光源正規化能救回最刺眼的那類不一致。剩下的問題多半不明顯。

管線本身是一支 Python 工具（工具鏈語言不受限，
見 [cpp-conventions.md](cpp-conventions.md) 末段），放 `tools/art/`。

### 閘四：驗收

**人眼看單張沒用，要看陣列。** 三個檢查：

| 檢查 | 怎麼做 |
|---|---|
| **接觸表** | 把同類素材排成網格一起看。不一致的會立刻跳出來 |
| **實機拼貼** | 在 Godot 裡拼一張真實地圖看接縫與整體色調 |
| **自動檢查** | 腳本掃：尺寸、色盤外的顏色、alpha 邊緣、命名是否對得上 def |

自動檢查要能**擋下入庫**：色盤外的顏色 > 1% 就退回。

## 生成順序

**先地形，後其他。** 理由：地形鋪滿畫面，它決定整體色調；
建築與角色是疊在地形上的，必須配合地形而不是反過來。

```
1 色盤與參考圖組（人工，最花時間，但決定一切）
2 L1 地形三層（基底 → 起伏 → 地物）
3 邊：河／路／橋 autotile
4 L2 地面與建築
5 L3 地面、家具、物件
6 角色部件（紙娃娃）
7 UI、圖示、特效
```

**第 1 步不要急。** 它是七百張圖的地基，多花幾天在這裡，
後面省下的是整批重做。

## 程序化再壓一輪

有些東西**不必生成，用程式組**（`~/repo/game_dev/my_godot_assists/`）：

| 需求 | 作法 | 省下 |
|---|---|---|
| 同輪廓不同材質的建築 | `godot_material` 的材質疊加 shader | 數十張 |
| 地形變體（同種地形的 4 個變體） | noise 擾動 + 色相微調 | 上百張 |
| 角色換裝 | `godot_character` 紙娃娃 | 組合爆炸 |
| 圖示的邊框與底色 | 程式繪製 | 數十張 |

**先問「這能不能用程式組」，再決定要不要生成。**

## 版本與可重生成

- 生成參數的 sidecar 檔**進版控**，圖檔本身可以不進（依專案體積決定）
- 換模型或改模板時：**整批重生成**，不要局部修補
- 保留一份「已驗收」的基線，方便比對新批次有沒有漂移

## 待細化

- 自動檢查的門檻值
- 選用哪個生成模型與工具鏈
- 音效是否走類似的流程（見 [audio.md](audio.md)）
