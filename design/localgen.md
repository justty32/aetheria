# L3 生成：Local

> Site 的一格放大之後長什麼樣。64×64、一格約 2 m。
> **預算 < 10 毫秒**——串流中每幾個回合就要生一個，比 Site 更緊。
> 共通規矩見 [gen-pipeline.md](gen-pipeline.md)；玩法見 [lowmap.md](lowmap.md)。

## 輸入

| 輸入 | 來源 | 屬於 |
|---|---|---|
| 四條邊的 `BoundaryProfile` | [edge-consistency.md](edge-consistency.md)，**同一份實作**，`w` 換 64、seed 換 `site_seed` | 慢 |
| Site tile 的 `ground`／`overlay`／`edges`／`zoning`／`structure` | [sitegen-city.md](sitegen-city.md)、[sitegen-wild.md](sitegen-wild.md) | 慢 |
| `local_seed = splitmix64(site_seed ^ (y<<16\|x))` | — | 慢 |
| 佔用者、控制方、損毀狀態、季節、時辰 | Site 的快變數 | 快 |
| `LocalDigest` 的持久層 | [interface-lifecycle.md](interface-lifecycle.md) | — |

骨架只准讀慢變數，這條在 L3 一樣是鐵律（[principles.md](principles.md) 原則四）。

### ⚠ 慢輸入的載體缺一欄（M5.0 實測）

上表要求 B3 的散布密度依 Site 的 **feature** 決定，但 `SiteProceduralLayer` **不保存來源 feature**。

M5.0 的處置是由投影入口**顯式接收慢變數 `FeatureId`**，沒有去偷讀快變數——處置是對的。
但這件事本身值得記：**「慢／快變數分流」的抽象成立，缺的只是 L2→L3 的慢輸入載體少一欄。**

這個區別很重要：**不是抽象錯了，是 schema 沒補齊。** 前者要重新設計，後者加個欄位就好。
M5 作為「L1↔L2 的抽象是否通用」的回頭檢驗（見 [lowmap.md](lowmap.md) 末段），
到目前為止照出來的三件都屬於後者。

## 三條路線，由 Site tile 的 `zoning` 決定

Local 生成器不是一個大函式，而是**依上層的分區分派**到三條路線：

| Site tile 的分區 | 生成什麼 | 大致成本 |
|---|---|---|
| 建築類（住宅／商業／工坊／軍事） | **建築內外**：牆、房間、門、家具、居住者 | 最貴 |
| 開放類（農地／廣場／野外／道路） | 地表細節、植被、路面、零星物件 | 最便宜 |
| 特殊類（遺跡／礦坑／地城入口） | 地表 + **負 z 層**的地下結構 | 中等 |

**絕大多數 Local 走第二條**，而第二條幾乎不花時間。10 ms 的預算主要是留給第一條的。

## 路線 A：建築內外

Site 層的一個「建築」是**街廓**尺度（125～500 m），放大到 Local 是**一棟棟房子**。
這個對應關係最容易搞混，實作時要特別留意。

```
A1 地基     從 BoundaryProfile 內插地面，鋪街廓的地面材質
A2 排屋     沿臨街邊排出建築輪廓，背對背，中間留內院
A3 分間     每棟房子遞迴二分成房間（同 sitegen 的街廓演算法，尺度更小）
A4 開門窗   在牆（邊）上開門與窗；門的種類依 zoning 與 owner 的風格表
A5 家具     依房間類型（臥室／廚房／工坊／店面）從資料檔填物件
A6 居住者   依 Site 的人口密度放 NPC；絕大多數是 Ambient 級（見下節）
A7 垂直層   有地窖就在 z=−1 生一層；有樓層就在 z=+1
```

A3 直接複用 [sitegen-city.md](sitegen-city.md) 的遞迴二分——
**同一個演算法在兩個尺度上用兩次**：Site 層切街廓，Local 層切房間。
切點偏離正中的技巧也一樣，正中切會產生一模一樣的方格房間。

## 路線 B：開放地表

```
B1 地形     從 BoundaryProfile 內插高度，疊 local_seed 的細噪聲
B2 水與路   承接邊界的 Crossing，畫出河床／路面
B3 散布     植被、石塊、雜物用抖動網格（藍噪聲），密度依 Site 的 feature 與季節
B4 零星物件 採集點、路邊神龕、廢棄物
```

單趟、無迭代、微秒級。荒野 Local 幾乎是免費的。

## 路線 C：特殊

地表走路線 B，再加負 z 層的地下結構：

- **礦坑**：從入口沿礦脈方向掘進，分支遞減
- **地城**：房間 + 走廊（經典的 roguelike 生成，直接參考 ToME4 的 level generator）
- **遺跡**：路線 A 生成後拆掉 60～80%，複用 [sitegen-wild.md](sitegen-wild.md) 的廢墟作法

**深度由 Site 的 `structure` 與劇情決定**，不是每個入口都通往十層地城。

## 居住者：絕大多數不生成實體

一棟房子裡「住著一家人」，但**不必真的生出四個 entity**。

| 情況 | 怎麼做 |
|---|---|
| 玩家沒進屋 | 只有一筆「這裡住著 N 人」的統計，**零實體** |
| 玩家進屋 | 才依統計生出 `Ambient` 級的居住者，用標籤稱呼（見 [unique-objects.md](unique-objects.md)） |
| 具名 NPC | 從持久層還原到指定位置 |

這是 [significance.md](significance.md) 的實體 LOD 在生成階段的直接應用：
**生成器不生成不需要被看見的東西**。一個城鎮的 Local 可能只有幾十個實體，
而不是幾千個。

## 接邊：同一份實作，遞迴一級

[edge-consistency.md](edge-consistency.md) 的降維裁決鏈原封不動往下套：

```
canonical_edge_id / canonical_corner_id 的公式不變
只是 w = 64、region_seed → site_seed
```

所以 L2↔L3 的接邊測試也是**同一組測試換一組參數**。
若這裡需要新機制，表示 L1↔L2 的抽象抽錯了——目前推演下來不需要。

有一個細節值得點名：**牆可以壓在 zone 邊界上**。
一棟房子若橫跨兩個 Local，它的隔牆就落在共用邊上。
這沒有問題——牆是邊屬性，而邊由邊界剖面裁決，兩側必然一致。
`BoundaryProfile` 的 `edges` 欄位就是為此存在（L2 的城牆沿邊界走時同理）。

## 守住 10 毫秒

比 Site 更嚴，所以規矩也更嚴：

| 禁止 | 替代 |
|---|---|
| 全圖 A* | 走廊用直線 + 轉折，不用尋路 |
| 任何迭代／鬆弛／回溯 | 單趟遞迴切分 |
| 逐格的複雜判斷 | 查表 |
| 生成用不到的東西 | 見上節「居住者」 |

實測超標時的第一順位是**背景預生成**，第二順位才是簡化演算法。

## 持久層疊加

最後一步：把 `LocalDigest` 的持久層蓋上去——玩家挖通的牆、燒掉的房子、
開過的箱子旗標、具名 NPC 的位置。持久層永遠優先於底稿。

L3 的持久層是三層裡最小的（見 [lowmap.md](lowmap.md)），
所以這一步通常什麼都不用做。
