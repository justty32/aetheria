# 里程碑與判準

← [outline.md](outline.md)｜[INDEX](INDEX.md)

> 每個里程碑的完成判準。**M6 之前是「機制成不成立」，M7 之後是「玩起來對不對」**——
> 判準的形式因此不同，見下。

| 里程碑 | 完成判準 |
|---|---|
| **M0 骨架** | CMake 能編出 `.so`，Godot 能載入，headless 測試框架可跑 |
| **M1 大地圖可玩** | 生成一個 Region、單位可移動、旬回合可推進、存讀檔一致 |
| **M2 界面打通** | 任一 Region tile 可展開為 Site、可收回，來回三次狀態不漂移 |
| **M3 中層可玩** | 城區生成 + 城建循環；荒野生成 + 通過 |
| **M4 生命週期** | Site 卸載後推進 N 旬再載入，結果與不卸載一致（容許明確定義的誤差） |
| **M5 下層** | Local 串流與探索 |
| **M6 內容** | 戰鬥規則、勢力 AI、劇情 |
| **M7 規則展開** | 魔法／信仰／種族三條位階來源各自可玩；地城有機關與寶藏；獨特物件登記可用 |
| **M8 呈現** | 美術資源管線產出可用 tile 集；三層音景；主線 Lua 劇情可跑完一條 |
| **M9 可玩性** | 從新遊戲到通關一條完整路徑；平衡校準；存讀檔不漂移 |

M2 與 M4 是本專案真正的技術風險，其餘是工作量問題。

## M7 之後的判準怎麼定

⚠ **M6 之前的判準都是「機制成不成立」，M7 之後是「玩起來對不對」**——
後者沒有單一數字可斷言，所以判準要改成**可觀測的行為**，不是「做完了」。

| 里程碑 | 一句話判準 | 為什麼這樣定 |
|---|---|---|
| M7 | 三條位階來源**在同一場戰鬥裡可比**，且各自有不可替代的用法 | 若魔法只是「另一種傷害型別」，那它就不該是獨立系統 |
| M8 | 關掉 core 重開，畫面與音景**完全一致** | 呈現層不得持有玩法狀態（[tech-stack.md](tech-stack.md) 鐵律） |
| M9 | 同一存檔跑兩次通關，**世界雜湊在每個檢查點相同** | 決定論是可玩性的前提，不是附加價值 |

**待規劃清單**（見下節）就是 M7／M8 的工作項來源，不必另立。
