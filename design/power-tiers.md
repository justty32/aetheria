# 力量體系（簡單規劃）

> **⚠ 這是骨架，不是定案。** 目的只有一個：讓「一支軍隊」與「一個劍聖」
> 能放進同一條公式比較，好讓 [combat-formula.md](combat-formula.md) 有東西可算。
> 數值、技能、魔法、種族的細節全部待後續。
> 通用原則見 [principles.md](principles.md)；用詞以 [glossary.md](glossary.md) 為準。

## 核心問題

奇幻設定必須同時成立兩件互相拉扯的事：

1. **一個傳奇騎士能打散一群農民**——否則英雄沒有意義
2. **一個傳奇騎士打不過一支軍團**——否則國家與戰爭沒有意義

純數值（攻擊力 100 倍）做不到這件事：要嘛英雄被人海淹沒，要嘛英雄無敵。
需要的是**量與質分開**。

## 兩個維度

| 維度 | 是什麼 | 性質 |
|---|---|---|
| **量（Mass）** | 人數、裝備、補給、陣型 | 線性可加 |
| **質（Tier）** | 力量位階 | **非線性**，高階對低階有質的優勢 |

## 位階＝significance

**位階不另立一套等級，直接沿用 [significance.md](significance.md) 的五級。**
這不是偷懶——「他有多強」與「他值不值得被個別計算」本來就是同一件事。

| Tier | significance | 例子 | 權重 |
|---|---|---|---|
| 0 凡俗 | `Ambient` | 農夫、民兵、雜兵 | 1 |
| 1 精銳 | `Local` | 職業士兵、老練傭兵 | 4 |
| 2 名士 | `Site` | 騎士、法師、名匠 | 16 |
| 3 英傑 | `Region` | 名將、大魔導、聖騎士 | 64 |
| 4 傳奇 | `World` | 劍聖、古龍、神使 | 256 |

權重是**每階 ×4**（初值，待校準）。一個傳奇 ≈ 256 個民兵——
能打散一個連隊，打不過一支軍團。這正是我們要的兩件事同時成立。

## 等效戰力

```
S = Σ over units ( count × tier_weight[tier] × quality )
```

`quality` 是量的維度上的修正：裝備、訓練、補給、疲勞、種族特性。
初值域約 0.5～2.0，不跨階——**裝備再好也不會讓民兵變成騎士**。

這條讓一切可比：一支軍團有一個 `S`，一個劍聖也有一個 `S`，
[combat-formula.md](combat-formula.md) 只吃 `S`，不必知道裡面是什麼。

## 位階門檻：質的部分

只有權重折算的話，位階仍然只是「比較大的數字」——1000 個農民照樣淹死劍聖。
所以再加一條**非線性**規則：

> **階差 ≥ 3 時，低階方對高階**個體**的傷害趨近於零。**

一萬個農民也殺不死一條古龍。要跨過這道門檻，需要**破階手段**：

| 破階手段 | 例子 |
|---|---|
| 神器 / 附魔武器 | 屠龍之槍 |
| 大魔法 | 儀式魔法、法陣 |
| 地形與陷阱 | 誘入峽谷、坍塌、陷坑 |
| 攻城器械 | 對付巨獸的弩砲 |
| 另一個高階存在 | 以龍制龍 |

**這是刻意的玩法設計**：凡人對抗傳奇的方法不是堆人，是**想辦法**。
它讓「準備」比「兵力」更重要，也讓劇情有事可做。

門檻只作用在**個體**上。劍聖砍不完一支軍團，因為軍團的損傷走的是量的維度；
但軍團也殺不了劍聖，只能逼退他。

## 與 δ 的關係

[event-scaling.md](event-scaling.md) 定義了 δ：玩家在低層能偏離統計多少，
由 significance 決定。**位階就是 δ 的來源**——同一件事的兩種說法：

- 從模擬看：高位階實體能讓結果偏離統計期望值
- 從玩法看：英雄能扭轉戰局

所以不必為 δ 另外設計一張表，它就是 `tier`。

## 力量從哪裡來（先不細分）

位階是**結果**，不是職業。武技、魔法、信仰、血統、神器都能把人推上更高的位階：

| 來源 | 說明 |
|---|---|
| 武技 | 長年訓練與實戰 |
| 魔法 | 法術造詣。**魔法不是獨立系統，是位階的一種來源** |
| 信仰 | 神祇的眷顧；可被剝奪 |
| 血統 | 種族、龍裔、古老家系。**影響位階上限而非起點** |
| 神器 | 外加的位階，隨物品轉移 |

這樣分的好處：**現在不必設計魔法系統**，也能算戰鬥。
法師與戰士在公式裡都只是一個 `tier` + 一個 `quality`，
差別留到 `core/rules/` 落地時再展開。

## 位階會變動

- **升**：實戰、修行、獲得神器、劇情、繼承
- **降**：重傷、失去神器、被剝奪信仰、年老

**升階應該罕見且有敘事**。位階不是經驗條，是身分的改變——
一個角色一輩子升一兩階就很多了。這與
[significance.md](significance.md) 的升降級遲滯是同一條規則。

## 團體的位階

一群人聚起來的 Cohort 有自己的位階，但**不是成員位階的總和**：

```
cohort_tier ≈ 成員的最高位階（若該位階者能指揮）
cohort_S    = Σ 成員的等效戰力
```

十個騎士組成的隊伍，位階仍是 2，只是 `S` 比較大。
**位階不因人多而提升**——這是位階與量分開的必然推論，
也堵住了「堆人數升階」這條路。

例外是[significance.md](significance.md) 提過的「聚合提升重要性」：
那提升的是**被個別計算的資格**（一千個流民成為大地圖上的問題），不是戰鬥位階。
這兩件事共用等級表但不共用升級規則，**這是目前最容易混淆的一處**，實作時要分開。
