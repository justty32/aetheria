# L1 生成：地形與氣候

> 一個 Region（128×96，一格 8 km）的自然環境怎麼長出來。
> 共通規矩見 [gen-pipeline.md](gen-pipeline.md)；文明與道路見 [worldgen-civ.md](worldgen-civ.md)。
> 預算：整條管線 < 3 秒（一次性，可顯示進度條）。
> 通用原則見 [principles.md](principles.md)；用詞以 [glossary.md](glossary.md) 為準。

## 管線

```
1 板塊 → 2 高度場 → 3 侵蝕 → 4 氣候 → 5 河流 → 6 biome → 7 地物
```

每階段一個子種子、一個純函數、一張可 dump 的中間圖。

## 1. 板塊

把地圖切成 8～16 個板塊，每個帶一個運動向量。

- **切法**：撒 N 個 Voronoi 種子，逐格取最近種子。8 km 的格子搭 128×96，
  一個板塊約幾百格，尺度合理。
- **每板塊屬性**：`is_oceanic`（海洋地殼較低）、`drift`（二維整數向量）、`base_elevation`。
- **板塊邊界**：相鄰格屬於不同板塊時，比較兩者的 `drift`：

| 相對運動 | 地貌 | 高度效應 |
|---|---|---|
| 相向（收斂） | 造山帶 / 島弧 | 大幅抬升，沿邊界成脈 |
| 相離（張裂） | 裂谷 / 洋中脊 | 陸上下陷成谷，海中略升 |
| 錯動 | 斷層 | 高度不變，但地物層可放斷崖 |

板塊不是為了物理真實，是為了讓山脈**成脈而非成斑**。
純噪聲產生的山地是隨機散布的斑塊，玩家一眼就看得出不像真的世界。

## 2. 高度場

```
elevation = plate_base
          + boundary_effect(距最近板塊邊界的距離, 邊界類型)
          + fbm(x, y, octaves=6)
```

- `fbm` 用整數化的 value noise 或 simplex，**輸出立刻量化成整數公尺**
  （見 [gen-pipeline.md](gen-pipeline.md) 的平台一致性要求）。
- `boundary_effect` 隨距離指數衰減，讓山脈有山麓而不是垂直牆。
- **海平面**是一個常數，切分陸海。切完檢查陸地占比，
  若偏離目標（預設 30%±5%）就二分調整海平面重切——這比調噪聲參數穩定得多。

**連通性修補**：切完之後掃一次，把面積小於門檻的孤島與內陸湖泊清掉或保留（依設定），
並確保主大陸是單一連通塊。這一步是為了避免玩家開局在一座三格的島上。

## 3. 侵蝕（可選但強烈建議）

簡化的熱力侵蝕：迭代若干次，每次把高於鄰居超過閾值的部分削掉一些，堆到低處。

- 8～16 次迭代對 12288 格是毫秒級，成本可忽略。
- 效果是把噪聲產生的針狀尖峰磨成有山脊與山谷的地形，**河流階段會因此好走非常多**。
- 迭代必須用固定次數，不是「收斂為止」——收斂判定會引入不確定性。

## 4. 氣候

### 溫度

```
temperature = base_by_latitude(y) − elevation * lapse_rate
```

`base_by_latitude` 是一條查表曲線（赤道最熱、兩極最冷），不是線性。
`lapse_rate` 是高度遞減率。Region 在世界中的緯度位置由 Region 的設定給定，
所以同一個世界裡可以有熱帶大陸與極地大陸。

### 盛行風

依緯度帶查表，不做流體模擬：

| 緯度帶 | 風向 |
|---|---|
| 0°～30° | 信風，東風為主 |
| 30°～60° | 西風帶 |
| 60°～90° | 極地東風 |

### 降水與雨影

這是氣候階段的重點，也是讓地圖「說得通」的關鍵：

1. 每格初始水氣 = 海格為滿、陸格為 0
2. 沿盛行風方向掃過整張圖（一次線性掃描，不是迭代）
3. 每格：吸收上游帶來的水氣，依溫度決定飽和度
4. **遇到高度上升就強制降雨**（地形抬升降水），降完水氣大減
5. 水氣隨距離自然衰減

結果是山脈迎風面濕潤、背風面乾燥——**雨影**。
沙漠因此會出現在該出現的地方（大山背後、大陸內部），而不是隨機撒。

## 5. 河流

1. **計算流向**：每格指向最低的鄰居（四鄰接）。窪地先填平（priority-flood）。
2. **計算流量**：從高到低走一遍，每格把自己的降水加上所有上游流入的流量傳給下游。
   單趟拓撲排序，O(n)。
3. **判定河道**：流量超過門檻的格子構成河網。
4. **寫進 `edges`**：河流是**邊屬性**（見 [worldmap.md](worldmap.md)）。
   格 A 流向格 B，就在 A、B 之間那條邊寫上河類的 `EdgeId`；
   流量分級對應不同的 def（溪／河／大河）。
5. **入海**：河道走到海就結束；走到內陸窪地就形成湖泊。

**河流必須在 biome 之前算**，因為河谷會影響濕度，進而影響 biome。
算完之後把河道附近的 `moisture` 加成回寫。

## 6. biome 判定

查表：`(temperature, moisture, elevation)` → `(TerrainId, ReliefId)`。

- **表本身住在資料檔裡**（見 [definitions.md](definitions.md)），不是 C++ 的 if-else 樹。
  這樣加一種地形不必改程式。
- 表的形式是一組規則，每條給定三個維度的區間與輸出，**第一條命中者勝**，
  最後一條是無條件的 fallback。規則順序在資料檔裡是顯式的，可調可 diff。
- `ReliefId`（平原／丘陵／山地／高山）由 elevation 與**局部起伏度**
  （周圍 3×3 的高度極差）共同決定——高原是「高但平」，這兩者要分開表達。

## 7. 地物

| 地物 | 放置規則 |
|---|---|
| 森林（疏林／密林／雨林） | 密度 = f(temperature, moisture)，用藍噪聲散布避免整片糊成一塊 |
| 礦脈 | 偏好板塊邊界與山地；種類依 `FeatureDef` 的資料檔設定 |
| 綠洲 | 沙漠中有地下水的格（低窪 + 周圍有山） |
| 廢墟 | 隨機，但偏好「曾經適合居住」的地方（用 [worldgen-civ.md](worldgen-civ.md) 的選址評分反查） |
| 特殊地標 | 由劇情資料指定，或從高分候選中抽 |

廢墟那條特別值得做：把「這裡曾經有文明」寫進地形，玩家探索時會自己腦補歷史。
成本只是多跑一次已經有的評分函數。

## Region 之間的一致性

**不要求**。相鄰的兩個 Region 在空間上不接壤（它們之間隔著 WorldGraph 的海路或山口），
所以各自獨立生成即可。這與 Site 之間的嚴格接邊要求不同，
理由見 [edge-consistency.md](edge-consistency.md)。

但**要求風格一致**：同一個世界的所有 Region 共用海平面、緯度曲線、
biome 判定表與同一組 def，只有 `region_seed` 與緯度位置不同。
