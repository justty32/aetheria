# 重要性機制（Significance）與實體 LOD

> 決定「哪些**實體**值得被個別計算」。姊妹機制是 [observer.md](observer.md)（決定哪些**地方**值得高解析度）。
> 命運判定的演算法在 [significance-fate.md](significance-fate.md)。
> 通用原則見 [principles.md](principles.md)；用詞以 [glossary.md](glossary.md) 為準。

## 一句話

> **實體的重要性決定它在哪一層的 tick 裡被個別計算；重要性不足的實體，
> 其計算被合併進所屬團體，由團體代表它承受結果。**

這一條同時解掉四個問題：模擬成本、命名、玩家的情感投入、統計與個體的一致性。

## 等級

| 等級 | 例子 | 在哪一層被個別計算 |
|---|---|---|
| `World` 世界級 | 神祇、傳奇人物、跨大陸勢力的領袖、聖遺物 | 世界圖 + 所有下層 |
| `Region` 大洲級 | 王國君主、名將、大城、傳說武器 | Region 的旬回合起 |
| `Site` 地方級 | 城主、商會會長、地標建築、名匠作品 | Site 的小時回合起 |
| `Local` 本地級 | 有名字的市民、店主、一般魔法物品 | 只在 Local 的分回合 |
| `Ambient` 環境級 | 無名群眾、雜物、量產裝備 | **從不個別計算**，只存在於團體統計中 |

規則：**實體只在「重要性所及的層級以下」被個別 tick。**
一個 `Site` 級的城主，在 Region 的旬回合裡不會被單獨算——他被算在他所屬的「該城統治階層」團體裡。

## 團體（Cohort）

重要性不足的實體不是消失，而是**被代表**。

- **Cohort 本身是一個實體**，有自己的重要性（通常高於其成員），有數量、有平均屬性、有分布。
- 例子：某城的平民人口、流民團、山賊團、商隊、獸群、某軍團的士兵。
- **聚合提升重要性**：一千個個別流民什麼都不是；聚成一個「流民團」Cohort，
  重要性升到 `Region` 級，就會出現在大地圖上、被旬回合個別計算、成為玩家要處理的問題。
- **反向合併**：重要性不足的個體，其命運由 Cohort 的統計代算——
  「該區域饑荒造成人口損失 12%」是對 Cohort 算的一筆數字，不是對三千個人各擲一次骰。

Cohort 是這套機制的計算單位。一座十萬人的城市在 Region 回合裡是**幾個 Cohort**，
而不是十萬個實體。

### Cohort 的形成與解散

| 事件 | 效果 |
|---|---|
| 大量同類低重要性實體聚集 | 形成 Cohort，重要性 = f(數量, 成員平均重要性) |
| Cohort 數量降到門檻以下 | 解散，成員回到個別狀態或併入鄰近 Cohort |
| Cohort 分裂（軍隊分兵） | 產生兩個 Cohort，各自重新評估重要性 |
| 具名個體加入 | 個體**不**被吸收；它同時是 Cohort 成員與獨立實體（見下節） |

**具名成員的雙重身分**是關鍵：被 mark 的角色既屬於某 Cohort（承受統計結果），
又是獨立實體（有自己的判定）。這正是使用者要的「命運仍屬團體，但會被特別計算下場」。

## 命名：延遲且吝嗇

- 重要性低於 `Local` 門檻的角色**不生成具體名字**，只有**角色標籤**：
  「雜貨店老闆娘」「守門的老兵」「碼頭的搬運工」。
- 標籤由職業 + 場所 + 少量特徵組成，是**投影出來的**（見 [interface-world-mid.md](interface-world-mid.md) 的程序層），不進存檔。
- 名字是**延遲生成**的：需要時才用 `hash(site_seed, entity_slot)` 生成，
  **一旦生成就進持久層**——否則玩家記住的名字會在重載後變掉。

這條規則的效果是：世界裡有幾十萬個「人」，但只有幾百個有名字，
而那幾百個恰好是玩家在乎的那些。

## Mark：significance 與 observer 的共同入口

> **⚠ 本節刻意不定死（使用者裁定 2026-08-15）。**
> mark 是建立在縮放機制之上的——它同時要抬高 significance、產生 observer、
> 影響事件的主場層。那三套機制（[observer.md](observer.md)、[events.md](events.md)、
> [event-scaling.md](event-scaling.md)）先穩定下來，再回頭把 mark 的細節定案。
> 以下是方向性的草案，不是結論。

`mark` 是把某個對象標記為「玩家在乎」。它同時做兩件事：

1. **提升 significance** → 該實體開始被個別計算
2. **產生一個 observer** → 該實體周圍與上下層獲得較高 LOD

所以 mark 過的人事時地物，即使玩家不在場，它周圍的世界也會被模擬，它的命運也會被單獨擲判。

### 誰來 mark

| 方式 | 說明 |
|---|---|
| **玩家手動** | 在 UI 上標記某個角色、地點、物品、勢力 |
| **自動：深厚關係** | 與玩家的互動累積超過門檻 → 自動 mark，並同時生成名字 |
| **自動：劇情** | 劇情腳本提名的對象 |
| **自動：持有** | 玩家持有的物品、擁有的城市、麾下的部隊 |

「與玩家有了深厚關係就自動 mark」是這套設計最有價值的一條：
玩家不必手動管理清單，系統從行為推斷在乎什麼。那個他反覆光顧的雜貨店老闆娘，
會在某一刻悄悄獲得名字，並從此有了自己的命運線。

### mark 的上限

mark 過的對象全部要被個別計算，所以**必須有預算**。
超過上限時，最舊且互動最少的 mark 會**降級**（不是移除）：
保留名字與持久層，但降回統計計算。玩家再次接觸時自動恢復。

## 升降級與遲滯

significance 會變動：

- **升**：mark、形成／加入 Cohort、獲得地位、持有重要物品、劇情提名、重大事蹟
- **降**：失去地位、Cohort 解散、長期無互動（**被 mark 的不因無互動而降**）

**必須有遲滯（hysteresis）**：升級門檻高於降級門檻。
否則實體會在門檻附近反覆抖動，每次抖動都伴隨「進出團體」的重算，既浪費又會產生詭異的敘事。

## 事件也有重要性

**事件與實體共用同一套等級。** 這條讓 L2 → L1 的影響有了乾淨的機制：

> Site 內發生的事件，若其重要性 ≥ `Region` 級，就**升級成 Region 事件**，
> 立即影響 Region 狀態，不必等每旬的數值歸約。

| Site 事件 | 重要性 | 後果 |
|---|---|---|
| 某工坊完工 | `Site` | 併入每旬歸約的數值裡 |
| 糧倉焚毀 | `Site`～`Region` | 依規模決定是否升級 |
| 城破、領主被殺 | `Region` | **立即**改變 Region 的 owner、觸發外交連鎖 |
| 神器出土 | `World` | 立即進世界圖，所有勢力都收到消息 |

這是 [interface-world-mid.md](interface-world-mid.md) 的**第二條通道**：
第一條是每旬的數值歸約（連續量），第二條是事件升級（離散事件）。
兩條合起來才是完整的 L2 → L1 界面。

## 與 observer 的分工

| | 決定什麼 | 軸 |
|---|---|---|
| **Observer** | 哪些 **zone** 要載入、用什麼解析度模擬 | 空間 |
| **Significance** | 哪些 **實體** 要個別計算、要不要有名字 | 實體 |

實際計算量 = 兩者的乘積。一個 `L_COARSE` 的 Site 裡，
只有 `Region` 級以上的實體會被個別算，其餘全部走 Cohort 統計。
