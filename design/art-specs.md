# 美術規格

> tile 尺寸、圖集、命名規約、素材量。**先定規格再生成**——
> 規格錯了，AI 生成得越多錯得越多。
> 工作流見 [art-pipeline.md](art-pipeline.md)。
> 通用原則見 [principles.md](principles.md)；用詞以 [glossary.md](glossary.md) 為準。

## 核心策略：靠組合，不靠窮舉

素材量的天敵是**組合爆炸**。三個機制把它壓下去：

| 機制 | 效果 |
|---|---|
| **三層 TileMapLayer 疊加**（[worldmap.md](worldmap.md)） | 沙漠丘陵有森林 = 三張小圖疊，不是一張專屬圖 |
| **邊屬性用 autotile** | 河流／道路／牆是邊，用連接規則組出來，不是每種走向一張 |
| **紙娃娃分件** | 角色 = 部件組合，不是每套裝備一張立繪 |

沒有這三條，中世紀奇幻的素材量會直接失控。有了它們，**總量壓在幾百張**。

## tile 尺寸：三層統一 64×64 px

| 層 | 一格代表 | 像素 |
|---|---|---|
| L1 Region | 8 km | 64×64 |
| L2 Site | 125 m | 64×64 |
| L3 Local | 約 2 m | 64×64 |

三層用同一個尺寸，換來的是**同一套工具鏈、同一個圖集規格、同一組後處理**。
不同尺寸帶來的唯一好處是省記憶體，而我們不缺那點記憶體。

`64 = 2^6`，與 [outline.md](outline.md) 的 64 倍放大同源，縮圖與 mipmap 都乾淨。

**角色可以跨格**：L3 的人物用 64×96（佔一格寬、高出半格），
這是 JRPG 的標準做法，讓角色不被地面壓扁。

## 素材量估算

| 類別 | 種類數 | 變體 | 小計 |
|---|---|---|---|
| L1 基底地形 | ~12 | ×4 | 48 |
| L1 起伏（半透明疊加） | 4 | ×2 | 8 |
| L1 地物 | ~20 | ×2 | 40 |
| 邊：河／路／橋（autotile） | ~8 種 × 16 連接 | — | 128 |
| L2 地面／覆蓋 | ~20 | ×3 | 60 |
| L2 建築（街廓尺度） | ~40 | ×2 | 80 |
| L3 地面／室內 | ~20 | ×3 | 60 |
| L3 家具與物件 | ~60 | — | 60 |
| 角色部件（紙娃娃） | ~80 | — | 80 |
| UI、圖示、特效 | ~150 | — | 150 |
| **合計** | | | **約 700** |

700 張對 AI 生成完全可行。**但前提是規格先定死**——
中途改尺寸或色盤就要全部重來。

## 圖集與命名：def id 直接映射路徑

**命名規約是規格裡最重要的一條**，因為它是資料與素材的接縫。

```
def id                    →  素材路徑
"terrain.grassland"       →  art/tiles/terrain/grassland_{00..03}.png
"edge.road_stone"         →  art/tiles/edge/road_stone_{atlas}.png
"building.smithy"         →  art/tiles/building/smithy_{00,01}.png
"item.sword_iron"         →  art/icons/item/sword_iron.png
```

規則：**def id 的點換成斜線，就是路徑**。

好處：加一種地形 = 加一筆 def + 放一張圖，**不必維護任何索引表**。
`VisualRef`（[definitions.md](definitions.md) 的 `TerrainDef` 欄位）
存的是相對路徑或圖集座標，core 完全不解讀它——core 只搬運，Godot 才認得。

### 缺圖的處理

**缺圖不得靜默。** 載入時掃一遍所有 def 的 `VisualRef`：

- 開發模式：缺圖 → 用醒目的洋紅棋盤格佔位 + 在 console 列出清單
- 正式版：缺圖 → 拒絕啟動

靜默的缺圖會變成「這格為什麼是空的」的除錯地獄。

## 色盤

**先定一組專案色盤，所有素材量化到它。**

這是風格一致的最強手段，也是 [art-pipeline.md](art-pipeline.md)
後處理的基礎。理由與程式碼的決定論同源：
與其要求每次生成都一致，不如**生成後用確定性的處理拉齊**。

建議規模：48～64 色，分成幾組：

| 組 | 用途 |
|---|---|
| 地形基色 | 綠／黃／褐／灰／白／藍，各 4～6 階明度 |
| 材質 | 木、石、金屬、布 |
| 強調 | 魔法、火、聖光、暗影 |
| UI | 中性灰階 + 一組品牌色 |

## 分層與繪製順序

Godot 端的 TileMapLayer 堆疊（[tech-stack.md](tech-stack.md)）：

```
L1: [地物] [起伏，半透明] [基底]
L2: [物件] [建築] [覆蓋] [地面]
L3: [特效] [角色] [家具] [覆蓋] [地面]
```

**邊（河／路／牆）畫在哪**：它們跨在格與格之間，
用一個獨立的 layer 以半格偏移繪製，或用 autotile 的角落規則畫進地面層。
兩種都可行，實作時擇一並寫進 `art-pipeline.md`——
**不要兩種混用**，那會讓接縫對不齊。

## 日式表現的具體約定

[outline.md](outline.md) 的風格鐵律「規則西式、表現日式」落到素材上：

| 面向 | 約定 |
|---|---|
| 色調 | 明亮、飽和度中高。**避免歐美奇幻常見的灰褐濾鏡** |
| 輪廓 | 有輪廓線但不重；地形無輪廓、物件與角色有 |
| 光源 | **統一從左上打光**，陰影往右下。這條必須全素材一致 |
| 角色 | 頭身比 6～7（不 Q 版、不寫實），臉部特徵清晰 |
| 建築 | 中世紀歐洲骨架 + 日式插畫的線條與配色 |

「光源方向統一」是最容易被 AI 生成破壞、又最容易被眼睛察覺的一條，
所以它進後處理的檢查清單（[art-pipeline.md](art-pipeline.md)）。

## 可複用的現成元件

`~/repo/game_dev/my_godot_assists/` 已有（[tech-stack.md](tech-stack.md)）：

| 需求 | 元件 |
|---|---|
| 多 TileMapLayer 世界地圖 | `godot_world_map/` |
| 紙娃娃換裝 + 動畫 | `godot_character/` |
| 2D 材質疊加 shader | `godot_material/` |
| 程序生成圖像（SDF／Bézier／noise） | `godot_procgen_art/` |

`godot_material` 的「基底 texture × 材質疊加層」可以再壓一輪素材量：
同一個建築輪廓換材質層就變成石造／木造。
