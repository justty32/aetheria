# 事件縮放：升格、降格與期望值一致

> 一個事件如何在三層之間移動主場，以及**為什麼玩家親自去打，結果不會比較划算**。
> 模型見 [events.md](events.md)；交戰的具體例子見 [combat-scaling.md](combat-scaling.md)。
> 通用原則見 [principles.md](principles.md)；用詞以 [glossary.md](glossary.md) 為準。

## 誰觸發縮放

只有一個東西：**observer**。

```
home = min( significance 所要求的最低層 , observer 允許的最高解析度層 )
```

玩家騎馬趕到戰場 → 產生 observer → Site／Local 的 LOD 升級 → 事件跟著升格。
玩家離開 → observer 消失 → 事件降格回統計。

縮放**不是**由事件自己決定的，也不是由玩法邏輯散落各處地決定的。
單一入口讓它可測、可預測、可在回合結算的固定時點批次執行。

## 降格（demote）

高解析度 → 低解析度。把具體壓成統計，形狀與 `SiteDigest` 一模一樣：

| 保留 | 丟棄 |
|---|---|
| 聚合統計：人數、平均士氣、陣型完整度、補給、傷亡累計 | 每個無名單位的座標、當前 HP、朝向 |
| **具名／被 mark 的參與者**（持久層）：身分、傷勢、相對位置 | 無名單位的一切個體狀態 |
| 事件的 `props` 與時序 | 動畫與演出狀態 |

降格必須是**有損但守恆**的：丟掉的是分布的細節，保留的是分布的總量與矩。
降格後 Region／Site 面孔繼續推進時，用的就是這些統計量。

## 升格（promote）

低解析度 → 高解析度。把統計展開成具體，形狀與 `project()` 一模一樣：

1. **取當前統計狀態**（權威）——不是事件開始時的狀態。
   打了三個回合已經死了 400 人，升格後戰場上就該只剩下該剩的人。
2. **確定性展開**：`seed = hash(event_id, target_zone_id, promote_tick)`。
   單位擺位、陣型、地形佔位全部由此決定。
3. **邊界條件由上層給定**：Site 層說部隊 B 在東側，
   那 Local 層的敵方單位就從**東邊緣**進來。這與
   [edge-consistency.md](edge-consistency.md) 的 `BoundaryProfile` 是同一件事——
   **上層永遠負責給下層邊界條件**。
4. **具名參與者按持久層還原**，其餘由程序層生成（不存檔，見 [events.md](events.md)）。

### 反覆升降格

玩家打十分鐘就走、走了又回來——具體佈局會不會每次都不一樣？

**會，而且沒關係。** 具體佈局是程序層（不存、可重算）；
統計狀態是權威（存）；具名參與者的位置是持久層（存）。
三層資料的分工與 [interface-world-mid.md](interface-world-mid.md) 完全一致，
不必為事件另發明一套規則。

## 期望值一致（expectation parity）

**這是整套縮放機制唯一真正困難的地方。**

同一場戰鬥有三種算法：Region 的一條公式、Site 的部隊模擬、Local 的逐單位廝殺。
若三者的期望結果不同，玩家立刻會學會用最划算的那一層去打——
不管是「親自去打比較賺」還是「掛機讓系統算比較賺」，都是設計失敗。

### 要求

```
E[結果 | Region 公式] ≈ E[結果 | Site 模擬] ≈ E[結果 | Local 模擬]
```

**期望值必須對齊，方差不必。** 低層的方差本來就該更大——
那正是玩家親自出手的意義：不是提高期望，是換取影響結果的機會。

### 怎麼保證

不能靠祈禱，要靠校準與 CI：

1. **Region 公式是校準基準**（它最簡單、最穩定、跑得最多）
2. **Site 模擬校準到 Region**：對隨機取樣的戰鬥情境跑蒙地卡羅，
   調整 Site 層參數使期望值對齊
3. **Local 模擬校準到 Site**：同理
4. **自動化回歸測試**：隨機 1000 組情境，三層各跑 N 次，
   兩兩比對期望值，相對誤差 < 5%

這與 [interface-world-mid.md](interface-world-mid.md) 的
「`reduce(project(s))` 要約等於 Region 近似公式」是同一條測試的推廣。

## 玩家能偏離統計多少

Local 層玩家的個人發揮**可以**改變結果，但必須有界——
否則一個人可以打贏一支軍隊。

```
最終結果 = 統計期望值 + clamp( 個人貢獻 , −δ , +δ )
```

而 `δ` 由誰決定？**significance。**

| 參與者等級 | δ（能扭轉多少） |
|---|---|
| `Ambient` | 0——無名小卒改變不了戰局 |
| `Local` | 很小 |
| `Site` | 可以決定一場遭遇戰 |
| `Region` | 可以決定一場會戰（名將） |
| `World` | 可以獨自扭轉戰役（傳奇英雄、神祇） |

這給了「英雄」一個**機制上的定義**，而不只是數值更高：
**significance 決定你被允許偏離統計多少**。
一個 `World` 級的劍聖真的可以隻身破陣，因為機制允許他偏離；
而同樣數值的無名士兵不行。

這同時是 [significance-fate.md](significance-fate.md) 的「配額守恆」在戰鬥上的推廣——
個體的例外必須從統計的配額中扣抵，總量守恆。

## 無偏性測試

比期望值一致更嚴格的一條：**縮放的時機不應影響結果分布**。

| 測試 | 內容 | 判準 |
|---|---|---|
| **期望值一致** | 同一情境三層各跑 1000 次 | 兩兩期望值相對誤差 < 5% |
| **縮放無偏** | A：全程 Region 算完；B：中途升格到 Local 再降回 | 結果分布無顯著差異 |
| **反覆縮放** | 升降格 10 次 vs 不縮放 | 統計狀態守恆，具名參與者狀態相同 |
| **展開決定論** | 同一事件升格 100 次 | 單位擺位逐位元相同 |
| **不算兩次** | 主場在 Site 時，Region 是否重複結算 | Region 面孔的損傷寫入次數 = 0 |

**「縮放無偏」是防刷測試**：若玩家能靠「在關鍵回合趕到現場、其餘時間掛機」
系統性地獲得更好的結果，那就是漏洞。這與
[interface-lifecycle.md](interface-lifecycle.md) 的「常進城的玩家，
他認識的人比較容易活」是同一類問題。

## 執行時點

縮放只在**回合結算的尾端**發生，與 LOD 的升降級、zone 的逐出同一批次執行。
理由與 medps 的 `zone-addressing-lifecycle-design.md` §3.11 相同：
在模擬途中改變 zone 或事件的結構，會造成迭代器失效與懸置引用。

順序固定為：`場強重算 → LOD 升降 → 事件升降格 → zone 逐出`。
事件縮放排在 LOD 之後，因為它依賴 LOD 的結果。

## 待細化

- Region 戰鬥公式的實際形式（校準基準，要先定）
- 蒙地卡羅校準的自動化流程（是否進 CI，跑多久）
- 各 significance 等級的 `δ` 實際數值
- 中途升格時，已進行的回合數如何影響展開（戰場上的屍體、已破的城牆）
- 多個事件在同一 zone 同時升格時的預算分配
