# 個體規則：屬性、檢定、傷害

> DnD-like 的個體層規則。往上要接得住 [power-tiers.md](power-tiers.md) 的位階，
> 往下要能在 L3 逐單位算。
> 通用原則見 [principles.md](principles.md)；用詞以 [glossary.md](glossary.md) 為準。

## 位階與屬性的關係（先解這題）

[power-tiers.md](power-tiers.md) 的待細化問過：位階是屬性的摘要，還是獨立欄位？

> **獨立欄位。屬性是位階的細部展開，不是位階的來源。**

理由是資料可用性：**位階必須在 Region 層就能用**（等效戰力要算），
而那時個體屬性根本沒載入。Region 層只看得到一個 `tier` 和一個 `count`。

但兩者必須**校準**，否則會出現「屬性頂尖卻是低階」的荒謬：

```
suggest_tier(attributes) → 建議位階
```

- 實際 `tier` 預設等於建議值
- **可被覆寫**（劇情人物、神器持有者、被詛咒者）
- 測試：隨機 1000 組屬性，`|實際 tier − suggest_tier| ≤ 1`，
  超過的必須在資料裡有明確的覆寫理由

## 四屬性

不用 DnD 的六屬性。四個就夠，而且**每個對應一種力量來源**：

| 屬性 | 涵蓋 | 主要力量來源 |
|---|---|---|
| **體** Body | 力量、耐力、生命上限、負重 | 近戰武技 |
| **技** Skill | 靈巧、命中、迴避、潛行、手藝 | 遠程與技巧武技 |
| **心** Mind | 智力、學識、魔力上限、施法 | 魔法 |
| **魂** Spirit | 意志、感知、信仰、魅力 | 信仰、統御 |

四屬性比六屬性好平衡（組合空間小得多），也讓「純戰士／純法師／聖職／盜賊」
四個原型天然浮現，不必額外設計職業系統。

**衍生值**（全部由屬性 + 裝備 + 位階算出，不獨立存）：
生命、魔力、命中、迴避、防禦、抗性、移動、負重、視野。

## 檢定：d100

```
成功 ⟺ roll(rng, 0..99) < 屬性值 + 修正 − 難度
```

用 d100 而不是 d20，兩個理由：

1. **對玩家直覺**——「七成機會」比「DC 14」好懂，符合日式表現的取向
2. **與上層公式同語言**——[combat-formula.md](combat-formula.md) 的損失率是百分比，
   個體判定也是百分比，兩層校準時不必換算

`rng` 是注入的確定性 RNG（[principles.md](principles.md) 原則八）。
**沒有暴擊骰另外擲**——用同一次擲骰的餘量表達：
超出門檻越多，效果越好（分段查表）。少擲一次骰 = 少一個決定論破口。

## 傷害與抗性

**傷害型別是 `DamageTypeDef`，不是 enum**（[definitions.md](definitions.md)）。
初始清單只是資料檔的第一版：

| 物理 | 元素 | 超自然 |
|---|---|---|
| 斬、刺、鈍 | 火、冰、雷 | 毒、暗、聖 |

抗性是**每型別一個百分比修正**，掛在實體的稀疏屬性袋上：

```
實際傷害 = 基礎傷害 × (100 − 抗性) / 100
```

- 抗性可為負（弱點）
- 抗性上限（初值 90%）——**不允許完全免疫**，除非位階門檻生效
- 完全免疫走的是 [power-tiers.md](power-tiers.md) 的階差門檻，不是抗性。
  兩條路徑分開，是為了讓「這打不動」有兩種可解釋的原因：
  抗性高（換一種傷害型別）或階差太大（需要破階手段）

## 裝備

- 裝備是實體，帶 `ItemDef`
- 提供屬性修正、傷害型別、抗性
- **裝備不跨階**：好裝備能讓你在同階內變強，不能把你推上高一階
  （[power-tiers.md](power-tiers.md) 的 `quality` 值域 0.5～2.0，不跨階）
- **例外是神器**：神器直接附帶位階加成，且隨物品轉移。
  這也是為什麼神器該是獨特物件（[unique-objects.md](unique-objects.md)）

## 兵種相剋只在 Site 層

[combat-formula.md](combat-formula.md) 的待細化問過：兵種相剋要不要進 Region 層？

> **不要。只在 Site 層有意義。**

Region 的一回合是**一旬**，涵蓋整場戰役——行軍、紮營、數次接戰、補給。
在那個尺度上，兵種配置的優劣已經被平均掉了，等效戰力足以代表。

Site 層才有陣型、朝向、地形站位，相剋才有東西可以咬合：

| 剋制關係 | 條件 |
|---|---|
| 長槍 → 騎兵 | 正面接敵且陣型完整 |
| 騎兵 → 弓手 | 側背接敵 |
| 弓手 → 長槍 | 保持距離 |
| 攻城器械 → 城牆 | 靜止且有掩護 |

**條件是重點**。無條件的石頭剪刀布會讓戰術退化成查表；
帶條件的相剋逼玩家去創造那個條件，那才是戰術。

## 狀態效果

`StatusDef`（資料檔）：中毒、流血、恐懼、加速、護盾……

- 有持續時間（以 `Tick` 計，**不以回合計**——stride 可變）
- 有疊加規則（可疊／取最大／互斥）
- **降格時大部分丟棄**：狀態效果屬易失層
  （[principles.md](principles.md) 原則三），玩家離開 Local 就沒了。
  真正要跨層存活的（重傷、詛咒、瘟疫）必須明確標為持久層

這條分界要在資料檔裡逐條標明，不能靠慣例——
「我的buff怎麼不見了」與「這個詛咒怎麼還在」都是設計要主動回答的。

## 與三層的接軌

| 層 | 個體規則怎麼參與 |
|---|---|
| L1 Region | **完全不參與**。只有 `tier` 進等效戰力 |
| L2 Site | 方陣的平均屬性影響修正項；具名指揮官的屬性進 `command` |
| L3 Local | 完整參與，逐次檢定 |

**這是實體 LOD 的直接落地**：屬性只在被個別計算的層才展開，
其餘層用摘要（[significance.md](significance.md)）。
