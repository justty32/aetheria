# 執行期注入：存檔進行中加入新內容

> [本層入口](README.md)｜**使用者的原始需求，2026-08-25 才被正確寫下來。**
> 要的是：**在一個進行中的存檔裡，隨時加入任意文明、勢力、角色、城鎮、兵種、劇情。**
> 不是熱重載（[rules-extensibility.md](rules-extensibility.md)）——那保證「不動世界狀態」，
> 而這裡要的正是動世界狀態。
> 通用原則見 [principles.md](../principles.md)；用詞以 [glossary.md](../glossary.md) 為準。

## ⚠ 這份文件為什麼晚了九個里程碑

需求從一開始就存在，但被翻譯成了 `rules-extensibility.md` 的「熱重載」，
而那份文件把它定位成「**開發期**價值極高……**正式版可關閉**」。
「開發時改數值不用重開」與「玩家在一局中加入新文明」是兩件事，前者是工具便利，後者是玩法能力。

而且 **M0～M9 沒有任何一個里程碑的判準涉及它**，所以沒有任何一輪的驗收會碰到它。
有設計、沒里程碑的文件，等於沒有。

⚠ **這條的教訓比這條本身重要**：需求被寫進文件不代表它會被做。
**沒有里程碑判準掛著的能力，十輪之後也不會存在。**

## ✅ 使用者裁定（2026-08-26）：這是一個**可編輯的沙盒**，不是可重放的模擬

原本的隱含前提是「世界 = `f(seed, 玩家行動)`」，決定論是地基。
使用者裁定：**要的是可編輯的沙盒**，參照點是**矮人要塞**。
**存檔分成兩塊：世界與角色。**

### 決定論不必放棄，只要重新定義

| | 舊 | 新 |
|---|---|---|
| 世界 | `f(seed)` | **`f(seed, 世界的歷史日誌)`** |
| 確定性的意思 | 世界只由 seed 決定 | **重放一致**：重放同一份日誌得到同一個世界 |

**原則八「確定性不可妥協」一個字都不用改**——改的是確定性**指什麼**。
注入被記進日誌、可重放、可雜湊，這是 event sourcing 的老路，不是新發明。

⚠ 但驗收判準要跟著改寫：M9 的「同存檔跑兩次通關，每個檢查點雜湊相同」
要變成「**同存檔 + 同注入序列**跑兩次相同」。

### 兩塊存檔的分工（矮人要塞模型）

矮人要塞有一條特別關鍵的做法：**每個存檔自帶它的 raws**——
改了全域定義檔，舊存檔照樣能開，因為它裡面有自己那份。對應過來：

| 存檔 | 內容 | 為什麼 |
|---|---|---|
| **世界** | zone 樹、勢力、歷史日誌、**它自己的 def 表** | 注入新文明 = 往 def 表加型別 + 往世界狀態加勢力 + 記進日誌 |
| **角色** | 觀察點、駐留層、進度、主線狀態 | 型別一律用 **def id** 引用世界那邊，自己不存型別 |

一次解掉三件事：**舊存檔相容**（各自帶表）、**任意添加**（表可以長）、
**同一個世界可以有多個角色檔**。

✅ **現成的便宜**：存檔本來就是**目錄**不是單一 blob
（[zone-save.md](../architecture/zone-save.md)：路徑由 key 推導、有 manifest）。
「分成兩塊」是多一個根，**不是重構存檔格式**。

### 已量到的代價

依賴世界雜湊的測試 **12 個檔**、寫死的雜湊常數 **11 個**。
⚠ **2026-08-27 重量：21 個檔、14 個寫死的 64-bit 常數**（其中有 FNV offset basis 之類
非基準值，要逐條分辨）——以
[investigation/runtime-injection-status.md](../../wf/workflows/investigation/runtime-injection-status.md) 為準。
⚠ 而 [KNOWN-TRAPS](../../wf/KNOWN-TRAPS.md) 早就記著「那些寫死的 hash 是 golden snapshot、
不是領域不變量，**該改成關係斷言**」——**這批本來就在待修清單上**，
不是這個裁定額外製造的成本。

## 樞紐問題：注入必須是歷史，不是旁路

本專案的核心保證是**同 seed + 同歷史 → 同世界雜湊**
（[tech-stack.md](../architecture/tech-stack.md)、[principles.md](../principles.md) 原則八），
大量回歸測試建在上面。

若能在存檔進行中任意注入，世界就不再是 `f(seed, 玩家行動)`，
而是 `f(seed, 玩家行動, 注入)`。

> **所以注入必須被記進存檔、可重放、可雜湊——成為世界歷史的一部分。**
> 一旦它是旁路修改，存讀檔就會分岔，決定論的整套回歸測試全面失效。

這條決定了實作形狀：注入是**一種被記錄的世界事件**，不是一個 setter。

## 既有原則對它是友善的

| 原則 | 為什麼有利 |
|---|---|
| 原則二 權威在高層，低層是展開 | 加一個文明只需在 World／Region 層加，下層自己長出來，不必逐格寫入 |
| 原則七 結構性變更只在回合尾端 | 現成的合法插入點；注入排進命令緩衝，回合尾端結算 |
| 原則五 種類是資料，不是 enum | 只要種類真的是資料，「任意兵種／建築」就是加 TOML |
| 三層資料（程序／持久／易失） | 注入寫進**持久層**，程序層照常由 seed + 高層狀態重算 |

⚠ 但**原則五目前只做對一半**——見下。

## 已經擋在路上的三件事

| # | 阻礙 | 位置 | 性質 |
|---|---|---|---|
| 1 | **勢力數量建構時定死**，沒有 `add_faction` | `WorldDiplomacyState(faction_count, ...)` | L-Core |
| 2 | **兵種完全寫死**，連 `units.toml` 都沒有 | `enum class CohortRole { Spear, Cavalry, Archer, Siege }` | 違反原則五 |
| 3 | **AI 目標與動作寫死**，且四個動作是空實作 | `FactionGoal`／`FactionActionKind`；`Develop`／`Prepare`／`Expand`／`StatisticalProgress` 都是 `break;` | 違反原則五 + 功能缺口 |

第 3 條的功能缺口要單獨講：**AI 目前不會在地圖上派兵，也不會建新城**。
`Expand` 只讓抽象國力數字變大。所以就算能注入新文明，它也不會在地圖上做任何事。

## 待裁定（裁定沙盒之後仍未定的）

- 注入的**粒度**：一次注入一個完整文明（含起始領土、外交關係、AI 狀態），
  還是可以只注入一個角色／一座城？
- 注入的**來源**：玩家在遊戲內操作？外部檔案？兩者都要？
- 新勢力的**起始領土**從哪來：割既有勢力的地？只在無主地生成？
- **世界日誌要不要能被編輯／截斷**（矮人要塞不能，但沙盒也許該能）。
  若能，「重放一致」的判準要再想一次。
- root 的成長軸（[zone-model.md](../architecture/zone-model.md)）原本被裁定擱置，
  注入會讓 root 級結構持續變大——**這條因此可能變成真問題**
