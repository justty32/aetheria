# 交戰的三層表現

> 事件縮放最重要的具體案例。同一場戰鬥，在三層各有一個面孔。
> 機制見 [events.md](events.md) 與 [event-scaling.md](event-scaling.md)。
> 通用原則見 [principles.md](principles.md)；用詞以 [glossary.md](glossary.md) 為準。

## 交戰狀態（Engagement）

部隊 A 攻擊部隊 B → 雙方進入**交戰狀態**。這是一個 `Event`，
參與者是兩支部隊，主場層由 observer 決定。

交戰狀態的特徵：**它會持續多個回合**，不是一次性結算。
每回合雙方計算損傷、士氣變化、陣型變化，直到一方潰散、撤退或被殲滅。

## L1 Region：一個圖標，一條公式

| | |
|---|---|
| 回合 | 1 旬 |
| 看到什麼 | 兩個部隊圖標鎖定在同一格上，帶一個交戰標記 |
| 算什麼 | 一條公式：`戰力比 × 地形修正 × 補給 × 士氣 → 損傷率、潰散機率` |
| 成本 | 幾十次浮點運算 |

這是**校準基準**。Site 與 Local 層的模擬都必須校準到它的期望值
（見 [event-scaling.md](event-scaling.md)）。

一旬 = 10 天，所以 Region 層的一個回合可能涵蓋整場戰役，
公式必須把「戰役」而不是「會戰」算進去：補給消耗、疾病、逃兵。

## L2 Site：Total War，但是回合制

| | |
|---|---|
| 回合 | **15 分鐘**（交戰狀態下的縮短 stride，見下節） |
| 戰場 | 該 Site 的 64×64，一格 125 m |
| 單位 | 部隊拆成若干個**方陣**（Cohort），每個方陣約佔 1～2 格 |
| 算什麼 | 機動、陣型、地形、側背、士氣、遠程與衝鋒 |

這一層最像 Total War：你看到的是一個個方陣在戰場上機動，
而不是個別士兵。差別只在它是回合制的。

- **方陣就是 Cohort**（見 [significance.md](significance.md)）：
  有人數、平均素質、士氣、陣型完整度，沒有個別士兵。
- **地形直接沿用 Site 的地圖**：丘陵加射程、林地加迴避、河流阻隔、
  **城牆是城建蓋出來的那些牆**——這是兩套玩法真正咬合的地方。
- **側背與包抄**有意義，因為方陣有朝向、戰場有 8 km 見方的迂迴空間。
- 一場會戰約 4～8 小時 = **16～32 個戰鬥回合**，對回合制戰棋是合理長度。

## L3 Local：你舉起劍

| | |
|---|---|
| 回合 | **6 秒**（戰鬥 stride） |
| 戰場 | 該 Local 的 64×64，一格約 2 m |
| 單位 | 個別士兵、玩家角色 |
| 算什麼 | 逐單位攻防、技能、位置、視線 |

**敵人從地圖邊緣進來**——而從哪個邊緣進來，由 Site 層決定：
Site 說部隊 B 在戰場東側，Local 的邊界條件就是「敵方單位從東邊緣進入」。

> **上層永遠負責給下層邊界條件。** 空間上這叫 `BoundaryProfile`
> （[edge-consistency.md](edge-consistency.md)），因果上就是事件投放點。同一條原則。

玩家在這一層能做的事，受 `δ` 上界約束——見
[event-scaling.md](event-scaling.md) 的「玩家能偏離統計多少」。
一個 `World` 級的劍聖可以隻身破陣，無名士兵不行。這是機制，不只是數值。

## 時間粒度的修正

**我在推演移動速度時發現原本的時間表有問題，這裡修掉。**

原本定 Site 回合 = 1 小時、Local 回合 = 1 分鐘。但：

| 層 | 原回合 | 一回合能走多遠 | 問題 |
|---|---|---|---|
| Site | 60 分 | 保持陣型 1.5 km/h × 1h = 1.5 km = **12 格** | 一兩回合就穿過整個戰場，沒有機動可言 |
| Local | 60 秒 | 步行 5 km/h × 1min ≈ 83 m = **40 格** | 一回合橫穿整張圖 |

**解法：回合長度是可變的 stride，不是固定常數。**
統一時鐘沒有被破壞——它仍然只有一條，只是各層在不同狀態下用不同的步長：

| 層 | 狀態 | 一回合 | 一回合的移動 |
|---|---|---|---|
| L1 Region | 恆定 | 10 天 | 依 MP |
| L2 Site | 平時（經營） | 1 小時 | — |
| L2 Site | **交戰** | **15 分鐘** | 約 3 格（375 m） |
| L3 Local | 平時（探索） | 1 分鐘 | 約 40 格，但探索不需要精細 |
| L3 Local | **戰鬥** | **6 秒** | 約 5 格（10 m） |

6 秒是 DnD 的 round，這不是巧合——它是「一個人做一個動作」的自然尺度。

### 連帶：時鐘單位改成秒

6 秒無法用分鐘表達，所以**全局時鐘的基本單位從分鐘改成秒**：

```cpp
using Tick = std::chrono::duration<int64_t, std::ratio<1>>;   // 秒
```

| 週期 | 秒 |
|---|---|
| 1 年（360 天） | 31,104,000 |
| 1 旬（10 天） | 864,000 |
| Site 平時回合 | 3,600 |
| Site 交戰回合 | 900 |
| Local 平時回合 | 60 |
| Local 戰鬥回合 | 6 |

`int64_t` 秒可表示約 2.9×10¹¹ 年，綽綽有餘。
全部都是整數且互為整除，換算不會有餘數。

## 部隊、補給與士氣

- **部隊是 Region 層的實體**，significance 至少 `Region` 級——
  所以它在大地圖上就會被個別計算，不會被併進 Cohort。
- **部隊的組成**是一組 Cohort（方陣）+ 若干具名成員（將領、英雄）。
  具名成員走 [significance-fate.md](significance-fate.md) 的「統計優先、具名例外」：
  部隊被殲滅時，將領有機率突圍。
- **補給**由 Region 層算（補給線是否被切斷、糧草存量），
  結果作為 Site 與 Local 層的修正輸入。補給斷絕會直接壓低士氣上限。
- **士氣**是三層共用的量：Local 的個體事件（指揮官陣亡、旗幟被奪）
  向上聚合成 Site 的方陣士氣，再聚合成 Region 的部隊士氣。

## 撤退、追擊與潰散

這三件事必須在三層都表達得出來，否則會出現「在下層逃掉了，上層卻顯示被殲滅」：

| 事件 | Local | Site | Region |
|---|---|---|---|
| 撤退 | 玩家往地圖邊緣跑 | 方陣脫離接觸，向後方移動 | 部隊移動到鄰格，交戰事件結束 |
| 追擊 | 敵單位緊咬不放 | 勝方方陣追擊，撤退方持續掉人 | 撤退時額外損傷，速度差決定損失 |
| 潰散 | 周圍友軍四散奔逃 | 方陣解體，士氣歸零 | 部隊從地圖上消失，殘兵併入最近友軍 |

**潰散的殘兵是一個 Cohort**，可能變成流民團或盜匪——
這正好接上 [significance.md](significance.md) 的「聚合提升重要性」：
一支潰散的軍隊會變成大地圖上的一個新問題。

## 攻城

交戰的特例，也是城建與戰爭真正咬合的地方：

- **防禦工事是玩家蓋的**：城牆、塔樓、閘門、護城河直接成為 Site 層的戰場地形。
- **圍城是持續事件**：主場層通常在 Region（一圍幾個月），
  每旬結算補給消耗與守軍士氣；玩家趕到才升格。
- **破城是一個 `Region` 級事件**（見 [significance.md](significance.md) 的事件升級），
  立即改變 `tile.owner`，不等每旬歸約。
- 破城後的損毀寫進 Region 的 `damage`，重載該 Site 時由
  [sitegen-city.md](sitegen-city.md) 的 F5 步驟把瓦礫畫在城牆缺口附近。
