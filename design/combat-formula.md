# Region 戰鬥公式（簡單規劃）

> **三層縮放的校準基準。** Site 與 Local 的模擬都必須對齊它的期望值
> （見 [event-scaling.md](event-scaling.md)），所以它比完整的戰鬥規則更該先定。
> 力量的來源見 [power-tiers.md](power-tiers.md)；三層表現見 [combat-scaling.md](combat-scaling.md)。
>
> **⚠ 形式已定，數值全部待校準。**
> 通用原則見 [principles.md](principles.md)；用詞以 [glossary.md](glossary.md) 為準。

## 它要滿足什麼

| 要求 | 理由 |
|---|---|
| **簡單** | 它是基準，會被跑幾百萬次（校準、AI 推演、離線補算） |
| **穩定** | 輸入微小變化不該造成結果劇變，否則校準無從談起 |
| **整數化** | 跨平台一致（見 [gen-pipeline.md](gen-pipeline.md)），用定點而非浮點 |
| **可解釋** | 每一項都要能寫進玩家看得懂的戰報 |
| **涵蓋一旬** | Region 一回合是 10 天，算的是**戰役**不是會戰 |

## 主公式

輸入是雙方的等效戰力 `S`（[power-tiers.md](power-tiers.md)）與一組修正：

```
S'ᴀ = Sᴀ × terrain × supply × morale × command
S'ʙ = Sʙ × ...

R = S'ᴀ / S'ʙ                       // 戰力比

lossʙ = base × R^p × duration
lossᴀ = base / R^p × duration
```

`p` 是**優勢指數**，初值 **1.3**：

| p | 意義 |
|---|---|
| 1.0 | 線性——兵力兩倍，殺傷兩倍 |
| 2.0 | Lanchester 平方律——兵力兩倍，殺傷四倍 |
| **1.3** | 折衷。集中兵力有實質回報，但不到「碾壓」的程度 |

用 `R^p` 而不是寫死平方律，是為了讓它成為**一個可調參數**——
校準時要動的就是這一個數字。

## 修正項

全部是乘法，全部來自資料檔（[definitions.md](definitions.md)），一項都不寫死：

| 修正 | 範圍 | 說明 |
|---|---|---|
| `terrain` | 0.6～1.5 | 地形。防守方在丘陵、渡口、城牆後有加成 |
| `supply` | 0.3～1.1 | 補給。斷糧是戰役級戰鬥最強的變數 |
| `morale` | 0.5～1.3 | 士氣。也決定潰散閾值 |
| `command` | 0.8～1.5 | 指揮官的位階與特質 |
| `posture` | 0.7～1.3 | 姿態：強攻／固守／襲擾／撤退 |

**補給的權重刻意給得最重**：一旬涵蓋十天，這個尺度上斷糧比戰技重要得多。
這讓大地圖的補給線成為真正的戰略要素，而不是裝飾。

## 不打到最後一人

純損耗公式會產生殲滅戰，那不符合真實也不好玩。所以：

```
若 累計損失率 > 崩潰閾值(morale) → 潰散
```

潰散的後果見 [combat-scaling.md](combat-scaling.md) 的撤退／追擊／潰散表。
崩潰閾值初值約 30%——**大多數戰役結束於一方崩潰，而非全滅**。

追擊階段的損失往往大於交戰本身，這也要進公式（`pursuit_loss`），
它讓「保持完整撤退」成為一種能力，而不是理所當然。

## 位階門檻

[power-tiers.md](power-tiers.md) 的階差規則要進公式，否則等效戰力只是個大數字：

> 對於**個體**參與者，若敵方最高位階與其階差 ≥ 3，
> 該個體受到的損傷趨近 0，除非敵方持有破階手段。

實務上：先用主公式算出雙方的總損失，再把損失**分配**給參與者時，
高位階個體按門檻豁免，豁免掉的部分由低位階者吸收——
這正是 [significance-fate.md](significance-fate.md) 的**配額守恆**，同一套機制。

所以劍聖不會被人海殺死，但他所在的部隊會被打垮。他只能全身而退，救不了軍隊。

## 一旬涵蓋的其他損耗

Region 回合是十天，除了交戰還有：

| 項目 | 說明 |
|---|---|
| 補給消耗 | 依人數與地形；圍城方消耗更大 |
| 疾病 | 密集駐紮 + 衛生條件；長期圍城的主要殺手 |
| 逃兵 | 士氣低、補給差、遠離家鄉時上升 |
| 季節 | 冬季行軍與駐紮的額外損耗 |

這幾項讓「久攻不下」自己就會付出代價，不需要額外的計時器設計。

## 輸出

```cpp
struct CombatResult {
    int32_t loss_a, loss_b;        // 等效戰力損失
    Outcome outcome;               // 續戰 / A潰散 / B潰散 / 雙方脫離
    int32_t morale_delta_a, _b;
    std::vector<ParticipantFate> named;   // 具名參與者的個別下場
};
```

`named` 走 [significance-fate.md](significance-fate.md) 的「統計優先、具名例外」：
先算總損失，再對具名參與者逐一擲判，結果從配額中扣抵。

## 校準

這條公式是**基準**，另外兩層要對齊它：

```
E[結果 | Region 公式] ≈ E[結果 | Site 模擬] ≈ E[結果 | Local 模擬]
```

作法與判準（隨機 1000 組情境、相對誤差 < 5%）見
[event-scaling.md](event-scaling.md) 的「期望值一致」。

**校準的順序是固定的**：先把 Region 公式的參數調到「打起來像那麼回事」，
再讓 Site 與 Local 去追它。反過來做會失控——低層的自由度太高，
拿它當基準等於沒有基準。

## 這條公式也給 AI 用

勢力 AI 要判斷「這仗打不打得贏」，用的就是同一條公式。

好處是 **AI 與玩家看到同一個世界**：AI 不會有隱藏的勝率表，
玩家能學會的推算，AI 也只用那一套。這對策略遊戲的公平感很重要。

## 待細化

- 所有數值：`base`、`p`、各修正的實際曲線、崩潰閾值、追擊係數
- 兵種相剋（騎兵／長槍／弓）要不要進 Region 層，還是只在 Site 層有意義
- 多方混戰（三支以上部隊）的推廣形式
- 攻城的專門修正（城牆等級、器械、圍城時長）
- 海戰
- 與 DnD-like 個體規則（屬性、檢定、傷害型別）的接軌點
