# L1 ↔ L2 界面：投影與歸約

> **本專案技術風險最高的一份文件。** 兩層地圖各有一套狀態，一旦兩邊都能自由演化，
> 就會出現兩個互相矛盾的真相。這份文件的全部目的，就是讓那件事不可能發生。
> 生命週期與補算見 [interface-lifecycle.md](interface-lifecycle.md)。
> 通用原則見 [principles.md](principles.md)；用詞以 [glossary.md](glossary.md) 為準。

## 問題

Region 的一格 = 一個 Site。兩邊都描述「同一塊土地」，
但空間解析度差 64 倍、時間粒度差 240 倍（交戰時 960 倍——stride 可變，見 [glossary.md](glossary.md)）。

- 玩家在 Site 裡蓋了 10 棟工坊 → Region 該不該知道？
- Region 模擬讓這座城的人口漲了三成 → Site 裡該多出什麼？
- Site 卸載 20 旬後重載 → 它該長什麼樣？
- 兩邊都在算生產 → 是不是算了兩次？

## 唯一原則

> **Region 是權威（source of truth），Site 是它的一次高解析度展開。**

Region 層的低解析度模擬**永遠在跑**，不管 Site 有沒有被載入。
Site 從來不「獨立演化」，它只是把 Region 已經決定的事**攤開來給你看與給你操作**。

推論：**世界上沒有任何一個量是「只存在於 Site」而會影響大局的。**
Site 裡發生的事若要影響大局，必須先歸約成 Region 層的量。

## 三層資料

Site 的每一格、每一個物件，都恰好屬於以下三層之一：

| 層 | 內容 | 存檔 | 重載時 |
|---|---|---|---|
| **Procedural 程序層** | 地形骨架、街道走向、樹木、裝飾、無名 NPC | **不存** | 用 `site_seed` + Region 慢變數重算 |
| **Persistent 持久層** | 玩家／勢力做過的不可再生決定：蓋了哪棟建築在哪一格、挖通了哪條路、哪個具名 NPC 死了、哪個寶箱開過了 | **必存** | 原樣還原，再依 Region 現況調變狀態 |
| **Volatile 易失層** | 單位當下位置、當前 HP、臨時 buff、本回合行動點 | **不存** | 由持久層 + 規則重建 |

程序層與易失層佔了資料量的 99%，卻一位元都不必存。
存檔裡的 Site 只剩下持久層——通常是幾十個物件，不是 4096 格。

這套三分法直接對應 ToME4 的 zone 持久化模型（`~/repo/moddings/tome4`），
差別是我們把「程序層可重算」這件事變成鐵律而非慣例。

## 方向 A：投影（Region → Site）

```
project(region_tile_state, site_seed, tick) -> SiteDraft
```

- **確定性**：`site_seed = splitmix64(world_seed ^ region_id ^ (y << 16 | x))`。
  同樣的輸入永遠產生同樣的 Site，跑一百次都一樣。
- 輸入的 Region tile 狀態被切成兩類，這個切分是整套機制的地基：

| | 慢變數（slow） | 快變數（fast） |
|---|---|---|
| 例子 | `base`、`relief`、`feature`、`elevation`、`edges`（河／路／牆）、`site_seed` | `人口`、`建設等級`、`資源存量`、`owner`、`駐軍`、`忠誠度`、`損毀度` |
| 變動頻率 | 幾乎不變（地形改造是罕見的大事件） | 每旬都在變 |
| 決定什麼 | **地形骨架**：地面、水系、主幹道、海岸線、可建地範圍 | **填充與狀態**：蓋滿幾成、建築是繁榮還是荒廢、有幾隊守軍 |

### 骨架穩定性鐵律

> **投影出的地形骨架只准依賴慢變數。快變數一律不得參與骨架生成。**

這條鐵律換來一個極重要的保證：**持久層物件的座標永遠有效**。
你在 (17, 32) 蓋的工坊，不會因為城市人口暴跌就發現那格變成了河。

實務上：`build_skeleton(slow_vars, site_seed)` 與 `populate(skeleton, fast_vars)` 是兩個函式，
前者的簽章裡拿不到快變數——用型別擋死，不靠自律。

## 方向 B：歸約（Site → Region）

```
reduce(site_state) -> RegionTileDelta
```

Site 不能任意寫 Region。它**只能**透過一張固定的歸約量表影響 Region：

| 歸約量 | Site 側怎麼算 | Region 側是什麼 |
|---|---|---|
| 人口 | 各住宅建築的居住人數總和 | `city.population` |
| 建設等級 | 各分區建築的加權分數 | `city.dev_level` |
| 糧食產出 | 農地格數 × 地力 × 季節 | `city.food_yield` |
| 工業產出 | 工坊產出總和（含相鄰加成） | `city.production` |
| **治安** | 駐軍／巡邏覆蓋 − 盜匪與流民壓力 | `city.order` |

> **治安是 M6.6 逼出來的第五列**（2026-08-22 裁定）。湧現任務「清剿盜匪」要能
> **真的提高治安**，而不是只發一則訊息；沒有正式歸約列的話，實作者只能在任務模組裡
> 另建一份世界真相——那會直接違反本檔。M6.6 的實作者拒絕那樣做並要求先裁定，判斷正確。
>
> ⚠ 另外三個觀測值**不走歸約，走持久層旗標**，不要誤加進本表：
> 具名 NPC 的 `missing`（[significance.md](significance.md) 的持久層）、
> 地城的 `cleared` 與 `depth`（[dungeon.md](dungeon.md) 已定義 `cleared` 防刷）。
> **歸約表只收「Site 側算得出數值、Region 側有對應數字」的量**，旗標不是量。
| 駐軍戰力 | 場上我方部隊的戰力和 | `tile.garrison` |
| 防禦值 | 城牆完整度 × 塔數 | `city.defense` |
| 忠誠度 | 滿意度加權平均 | `city.loyalty` |
| 控制勢力 | 場上控制點的歸屬 | `tile.owner` |
| 資源存量 | 倉庫內容 | `city.stock[*]` |
| 損毀度 | 傾頹／焚毀建築占比 | `city.damage` |

**這張表就是界面本身。** 表上沒有的東西，Site 裡怎麼變都影響不到世界。
要新增一種「Site 裡能影響大局」的玩法，就必須先在這張表上加一行——
這是刻意設下的摩擦，防止界面被悄悄擴散。

### 歸約時機

- **每旬一次**（Site 只要不是 `L_ABSENT`），與 Region 回合結算對齊
- **卸載時**必定執行一次
- 不逐小時歸約：Region 層根本沒有小時粒度，逐小時歸約只是徒增噪音

### ⚠ 歸約是「部分觀測」，不是「完整快照」（M5.15 裁定）

L1↔L2 的歸約原本假設**每一列都必有值**——Site 永遠有人口、永遠有建設等級。
L2↔L3 打破了這個假設：**一片純荒野的 Local 根本沒有建築**，
所以「建築完整度」這一列它**沒有觀測**，而不是「觀測到 0」。

沿用原形狀只能把空層量成 0，**那會清掉父層既有的值**。

> **裁定：歸約的每一列是 `optional`。present 才絕對覆寫，absent 不寫。**
> **「沒有觀測」與「觀測到零」是兩件事，資料上必須分得開。**

⚠ 這與 [verification-detection-power.md](verification-detection-power.md) 的
「空的層必然通過」是同一族：**0 和「不存在」長得一樣，意思卻相反。**
那份講的是它讓測試失去偵測力，這裡講的是它讓機制算錯帳。

L1↔L2 的 reducer 仍固定填滿每一列，行為未變——**它只是這個更一般形狀的特例。**

## 衝突解析：Region 說縮水，持久層還記著建築

投影出的底稿說這座城現在只養得起 3 棟工坊，但持久層記著玩家蓋過 10 棟。怎麼辦？

**建築不消失，狀態被調變。** 每個持久層物件帶一個由快變數決定的狀態：

```
運作中 (active) → 閒置 (idle) → 荒廢 (derelict) → 傾頹 (ruined)
```

Region 的人口與資源只夠支撐 3 棟，其餘 7 棟就顯示為閒置或荒廢；
日後人口回升，它們自動恢復運作。只有明確的「摧毀」事件才會把物件從持久層刪掉。

一句話總結整份文件：

> **數值歸 Region，佈局歸持久層，狀態由 Region 調變佈局。**
