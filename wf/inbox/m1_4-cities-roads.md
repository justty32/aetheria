## M1.3：通過，而且證明方式我沒話說

81/81 我自己跑的。兩條證明特別到位：

**正規化雜湊**——你用**相反順序**建立兩批單位，讓 EnTT entity 配對不同，
於是 PortableBinary bytes **不同**、正規化雜湊**相同**。
這一次證了兩件事：雜湊真的忽略 entity id，而且**底層 bytes 確實有差**——
所以「雜湊相同」不是因為兩邊根本一樣。多數人只會做前半。

**A\* 對 Dijkstra**——`dijkstra=12 / admissible=12 / 故意加權=16`。
你把啟發倍率放大到 100 破壞 admissibility，測試確實抓到次佳解。
不 admissible 的症狀是**安靜地給出次佳解**，肉眼永遠看不出來，
所以這條負向控制是必要的，不是加分。

「持續命令該進存檔」你的理由也對：它決定未來各旬的權威狀態轉移，遺失就會分歧。

### 一個我補進設計的東西

你建的是 **per-zone** 雜湊。M4 要的是**世界級**的——「卸載後推進 N 旬再載入」
牽涉多個 zone，其中有些還在磁碟上。

但世界級雜湊要列舉 zone，而成長軸不變量禁止 manifest 存 zone 清單。
裁定：**世界級雜湊是驗證工具，不是執行期狀態**，它直接走訪存檔目錄列舉。
測試工具走訪檔案系統不違反不變式（不常駐、不進存檔、不影響玩法路徑）。
已寫進 [`design/zone-save-format.md`](../../design/zone-save-format.md)。**M1.4 不用做**，記著就好。

## 這份任務的核心風險：**順序相依**

前面每一個生成階段都是順序無關的。**這一個不是。**

設計原話（`worldgen-civ.md` 第 9 階段）：

> **道路傾向重用既有道路**：已鋪路的邊成本大減，讓路網自然收束成幹道 + 支線
> （這一條讓生成順序有影響，所以城市對必須按**固定順序**處理——依 canonical id 排序）

這是整條生成管線第一個「演算法本身順序相依」的地方。它是**刻意的**——
路網收束成幹道正是我們要的效果。代價是決定論不再自動成立，必須靠**顯式的正規順序**維持。

**所以本任務最重要的驗收是：把輸入的城市清單打亂，輸出必須完全相同。**

## 範圍

### 1. 城市選址（階段 8）

評分函數的**各項權重全部住在資料檔裡**。因子照設計那張表。

「**交通瓶頸**」那條特別重要——`worldgen-civ.md` 說「兵家必爭之地應該是地形算出來的，
不是手工擺的」。簡化做法是「移除此格後周圍連通性下降多少」。
**注意成本**：12288 格各跑一次局部連通性測試，量一下實際耗時。

選址是**貪婪 + 最小間距**：全圖算分排序 → 取最高分 → 抹除半徑 R 內候選 → 重複。
最小間距是必要的，否則城市全擠在同一條大河沿岸。

規模分三級（大城／城鎮／村莊）。**要塞不走選址**，走第 9 步之後的隘口補點。

### 2. 道路（階段 9）

- 城市為節點建完全圖，邊權 = **實際地形移動成本（用 A\* 算，不是直線距離）**。
  你 M1.3 的 A\* 可以直接複用。
- Kruskal 求 MST → **補 10～20% 環路**（挑 `樹上距離 / 直接距離` 比值最大者）。
  純 MST 是樹狀路網，斷一條就切斷半個大陸，看起來假玩起來也差。
- 落到格子上用 A\*，但**成本函數與部隊移動不同**：坡度加重、沿河谷、繞開沼澤、
  **重用既有道路成本大減**。
- 路徑寫進 `edges`，等級依被多少路線重用而定。**一律走 `set_edge`。**

### 3. 渡河與橋：複合 def

一條邊只能存一個 `EdgeId`，但道路跨河時該邊**同時是河也是路**。
解法是資料檔裡的**複合 def**（`edge.bridge_stone_over_river`、`edge.ford`），
由「河的等級 × 路的等級」查表決定。

**查表本身也要在資料檔裡**，不要寫成 C++ 的 if-else。

## 回信給我

1. **打亂順序那條測試，負向控制抓到了嗎？** 如果跳過正規排序輸出**沒變**，
   那代表重用折扣沒生效——那比順序相依本身更嚴重，直說。
2. **交通瓶頸的連通性測試花了多少時間？** 12288 格各跑一次，我擔心這是第一個真的吃掉預算的東西。
3. **複合 def 的查表維度夠不夠？** 設計寫「河的等級 × 路的等級 × 該處的技術水準」，
   但技術水準這輪還不存在。你用兩維夠嗎，還是發現需要別的？
