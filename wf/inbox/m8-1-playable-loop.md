## 為什麼這輪最重要

`bridge/` 目前**只對外開了四個方法**：
`generate_region`、`get_core_version`、`poll_events`、`tick_to_date`。
`godot/` 只有一個 debug renderer、main、事件面板。

> **M6／M7 做的戰鬥、勢力 AI、外交、地城、湧現任務，從遊戲裡一個都碰不到。**

core 很厚，但它不是一個能玩的東西——**而且每多做一輪 core，這個缺口就更大**。

## M8 的判準（跟前面所有輪都不同）

> **不看程式碼、不跑測試，只用滑鼠鍵盤，能打完一場仗並看到世界因此改變。**

⚠ **這是唯一無法靠測試自證的判準。** 所以這輪的回報**必須附操作腳本**：
一步一步寫出「按什麼、看到什麼」，讓使用者能照著走一遍。
沒有那份腳本就是沒做完。

## 這輪的範圍：一條最小但完整的迴圈

**不要做全部的 UI。** 只做一條能走完的路：

```
1. 開新遊戲 → 看到 Region 地圖（已有 debug renderer，沿用）
2. 選一支部隊 → 下移動命令 → 看到它移動
3. 推進一旬 → 看到 AI 勢力也動了、事件面板有東西
4. 遭遇敵軍 → 選擇「親自打」或「讓系統算」
5. 打完 → 看到戰報（傷亡、誰潰散、具名者下場）
6. 世界真的變了（該格 owner／人口／治安）
```

⚠ 第 4 步的兩條路徑**必須都通**——那是 [`player-residence.md`](../../design/player-residence.md)
的核心，也是 M6.7／M7.2 校準的意義所在（兩條路一樣划算）。

## 跨語言邊界的三條規則，一條都不准破

1. **命令是意圖，不是結果。** GDScript 送「這個單位要移動到 (x,y)」，
   **不送**「把座標設成 (x,y)」。合法性由 core 判。
2. **事件是已成事實。** core 吐出的事件都已經改過狀態，GDScript 只負責演出。
3. **地圖資料批次拉。** ⚠ **絕不逐格 `get_tile(x, y)` 跨邊界**——
   12288 格 × 每格一次呼叫是效能災難。一次拉一整層 `PackedByteArray`。

⚠ **第 4 條（bridge 必須驗證所有跨界輸入）是硬性的**：
GDScript 傳進來的值是**外部輸入**，不是內部不變式。
core 的 `AETH_CHECK` 會 `abort`——實測從 GDScript 傳一個域外 tick 進去，
**整個 Godot 進程以 134 結束，沒有例外、沒有錯誤攔截**。
所以「非法值到不了 core」是 **bridge 的責任**。

**負向控制**：從 GDScript 送一個域外座標與一個域外 tick，
確認 **bridge 擋下來回錯誤／空值，Godot 沒有掛**。附兩個實測。

## ⚠ Godot 端不准持有玩法狀態

自我檢查法：**把場景整個 free 掉再從 core 重建，畫面必須完全一致。**
M6.6 已經對事件面板做過（`NARRATIVE_REBUILD_MATCH=1`），**這輪對整個迴圈再做一次**。

## 驗收

| 判準 | 怎麼量 |
|---|---|
| **操作腳本** | 一步一步的「按什麼、看到什麼」，使用者可照走 |
| 六步迴圈都通 | 每步附 headless dump 或截圖 |
| 兩條戰鬥路徑 | 親自打／系統算**都要通**，附兩份戰報 |
| 命令是意圖 | 送一個**非法**移動命令，core 拒絕且世界沒變 |
| 批次拉圖 | 附一次拉整層的位元組數與耗時，**不是逐格** |
| bridge 擋外部輸入 | 域外座標與域外 tick 各一，Godot 不掛 |
| 場景重建一致 | free 後重建，畫面逐字相同 |
| 效能 | 一旬推進的牆鐘時間，**暖機後 N≥5 取最小** |

### ⚠ 假通過

1. **「能跑」不等於「能玩」。** 若某一步只有 headless dump 而畫面上看不到，
   那步就是沒做完——如實回報。
2. **戰報若是假資料驅動**，那證明不了迴圈接通。附「戰報數字來自真實 `CombatResult`」的證據。
3. **場景重建一致若只比一個欄位**，不算。比整段可見文字。
