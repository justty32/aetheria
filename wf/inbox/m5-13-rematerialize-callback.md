## 你自己在 M5.12 標出來的缺口

> `ZoneManager::load` 不等於 Local rematerialize：codec 刻意不存程序 tiles，
> manager 也**沒有「載入失敗後呼叫 Local 生成／重展開」的 callback**。

所以 `migrate_entity` 目前只能搬進**已經備妥的完整 zone**。

⚠ **你當時沒有用 `materialize()` 假造空地形來讓路徑看起來能走——那個判斷是對的。**
設計文件早就記了這個陷阱：

> **`load` 不是 `rematerialize`。** 存檔的 `load` 只解碼持久層，程序層本來就不在裡面。
> 危險不在於它會壞，而在於**它不會壞得很明顯**：
> 拿 `load` 當重新展開去做往返測試，**兩次的程序層都是空的，測試照樣通過**。

## 要做的

把重新展開接到 `ZoneManager` 的**單一入口**，讓「取得一個可用的 zone」有明確語意：

| 情境 | 行為 |
|---|---|
| 存檔裡有 | `load` 解碼持久層，**然後**走完整的重新展開把程序層長回來 |
| 存檔裡沒有 | 直接生成（骨架 → 填充 → 疊持久層） |
| 生成／載入都失敗 | 回失敗，**不是回一個空殼** |

⚠ **`rematerialize` 與 `load` 必須維持兩個不同的入口**，不要為了方便合併成一個。
設計文件明寫這一條。這輪要加的是**協調者**，不是把兩者混成一個。

重新展開照三步走（[`interface-lifecycle.md`](../../design/interface-lifecycle.md)）：
① 重建骨架（只讀慢變數）② 用**當下**的快變數重新填充 ③ 疊回持久層並補算。

## 驗收

| 判準 | 怎麼量 |
|---|---|
| **程序層真的回來了** | 冷載入後 tile 數 = 4096，**不是 0** |
| 持久層沒被蓋掉 | 存檔裡的持久物件在重新展開後仍在原座標 |
| 兩個入口還在 | `load` 單獨呼叫仍然只解持久層（程序層 0）——**這是特性不是 bug** |
| `migrate_entity` 解鎖 | 搬進一個**只存在於磁碟**的 zone 會成功，而不是回 `false` |
| 失敗不給空殼 | 生成與載入都失敗時回失敗，**不能回一個 tile 數 0 的 zone** |
| 決定性 | 同一串操作 → 同一個正規化雜湊 |

### ⚠ 負向控制：這一輪特別容易假通過

> **拿 `load` 當重新展開，往返測試會照樣通過，因為兩次的程序層都是空的。**

所以要有一條測試**專門抓這個**：把協調者暫時改成「只 `load` 不重新展開」，
**測試必須紅，而且要紅在「tile 數是 0」而不是別的原因**。
⚠ 要真的紅，並把數字寫進回報。

另外：**空的層必然通過**。做往返測試前先確認持久層**真的有東西**，
不要用一個空 digest 去證明「不漂移」。
