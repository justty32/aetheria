## 這一輪要達到的一句話

**七百張素材還不存在，但「拉齊它們」的那條確定性管線先做好，而且是位元可重現的。**

`art-pipeline.md` 的賭注：不可控的部分（AI 生成）收窄，可控的部分（後處理）做死。
這一輪只做**可控的那一半**——不需要任何真素材，用合成輸入就能全部驗證。

## ⚠ 與其他輪完全檔案互斥（這是它能並行的前提）

只准動 `tools/art/`。**不准碰** `core/`、`bridge/`、`godot/`、`cmake/`、
`kSaveFormatVersion`、任何 C++ 檔。測試用 `pytest` 自帶，**不要掛進 cmake 的 ctest**
（`cmake/targets_tests.cmake` 是這個 repo 最會壞的檔，這輪一個字都不要碰）。

工具鏈語言不受限，見 [cpp-conventions.md](../../design/cpp-conventions.md) 末段。

## 要做的：閘三的六步 + 閘四的自動檢查

| 步 | 做什麼 | 我的裁定 |
|---|---|---|
| 1 裁切對齊 | 對齊 64×64 格線、去背 | — |
| 2 **色盤量化** | 映射到專案色盤 | **有序抖動（ordered dither），不要誤差擴散**——後者對鄰格順序敏感，會讓 tile 接縫不可重現 |
| 3 **光源正規化** | 主光方向偵測 → 旋轉／重打陰影到左上 | **用梯度分析，不要法線估計**。前者夠用且完全確定；法線估計的迭代解會引入浮點路徑依賴 |
| 4 輪廓統一 | 統一線寬與色（地形無、物件有） | — |
| 5 邊界處理 | tile 四邊無縫檢查與修補 | — |
| 6 命名歸位 | 依 def id 映射路徑 | **def id 的點換斜線就是路徑**（art-specs） |

閘四的自動檢查要能**擋下入庫**：尺寸不符、色盤外顏色 > 1%、alpha 邊緣不乾淨、
命名對不上 def → 非 0 退出碼並印出是哪一張、哪一項。

## ⚠ 色盤的實際色值是「待使用者」，不是這輪的阻塞

`art-pipeline.md` 的「閘一第一件事」還沒做。所以：
**色盤是管線的輸入檔，不是寫死的常數。** 這輪附一份**確定性生成的佔位色盤**
（給測試用，檔名要看得出是佔位），真色盤等使用者定。
⚠ 不要自己挑 48～64 個顏色然後當成專案色盤——那會被後面整批重生成推翻。

## 驗收（每一條都要在回報裡附數字）

| 項目 | 標準 |
|---|---|
| **位元可重現** | 同輸入 + 同色盤跑兩次，輸出 **SHA-256 完全相同**，附雜湊 |
| **跨行程可重現** | 兩次在**不同行程**跑（不是同一行程內迴圈），雜湊仍相同 |
| 色盤量化 | 輸出的顏色**全部**在色盤內，附「色盤外像素 = 0」 |
| 光源正規化 | 合成一組主光在四個方向的輸入，附正規化後四張的雜湊**相同** |
| 無縫 | 合成一張刻意有接縫的 tile，修補前後各附一次接縫度量 |
| 入庫閘會擋 | 四種違規各餵一張，附各自的非 0 退出碼與訊息 |
| `pytest` | 全綠，附測試數 |
| 文件 | `find . -name '*.md' -size +8k` 為空 |

### 負向控制（一次只改一條，取得紅燈後還原）

| # | 注入 | 必須紅 |
|---|---|---|
| 1 | 量化改成誤差擴散、或某處改用 `set` 迭代 | 位元可重現的雜湊比對 |
| 2 | 把色盤外門檻從 1% 放寬到 100% | 入庫閘的擋下測試 |
| 3 | 光源正規化跳過旋轉 | 四方向雜湊相同那條 |

⚠ **無效注入不算通過**：若某條注入下來全綠，**如實寫進回報說這條測不到**，
不要換一個更容易紅的注入充數。

⚠ **「同一行程內跑兩次」不算跨行程可重現**——那和 M2.3 踩過的「沒冷載入」是同一個坑。
