## 結論與校準順序

實際順序是 **Region（只量、不改）→ Site 對 Region → Local 對 Site**。沒有改
`resolve_region_combat`、`data/combat.toml` 或 `p=1.3`，也沒有動存檔版本（仍為 v18）。
本輪只採一組下層參數：Region／Site／Local 零均值抽樣幅度分別為 **2%／6%／12%**；
沒有試第二組數值，也沒有反覆調到好看。Site 與 Local 方差刻意遞增，沒有壓平玩法。

現有 main 尚無 Site 方陣／Local 逐單位戰鬥迴圈，已依即時協議寫 `m6-7.ask` 並採假設繼續：
本輪落地的是 **Region 權威配額 + 下層高方差展開 + 有界個人偏離**。它提供未來真戰鬥器的
校準契約與 CI，不冒充尚未存在的戰技模擬。

## `p` 偵測力

原測試已有 `fixed_ratio_power` 倍率檢查；本輪先補正式損失的集中兵力邊際回報。
固定 `R=1.2` 時，`p=1.0／1.3／2.0` 的 B 方損失依序為
**16660／17470／19540**，斷言嚴格遞增。原倍率 ×10^6 亦為
**2000000／2462294／4000000**；三者兩兩不等，所以把 p 改線性會紅。

## 1000 樣本期望一致

取 500 個情境，每個用相鄰的 antithetic seed `2k/2k+1` 各跑一次；三層各 **1000** 次，
seed 為 **0..999，全不相同**，event id 隨情境變。成對 seed 共用幅度但符號相反，避免有限
樣本的偶然同向偏差，並非重跑同一場。

`R` 以中性修正後 A/B 戰力比取樣：最小／中位／最大為

**300／402／298** 筆，涵蓋勢均力敵區間，不是完勝假案例。

## 五級 δ 與配額守恆

固定敵軍戰力 100000、統計損失 12000、個人請求偏離 +1000000。δ 以敵方初始戰力比例
`0%／1%／5%／20%／100%` 設定，只採此一組：

| significance | δ 上限 | 實際偏離 | 最終損失 | 具名／無名配額 |
|---|---:|---:|---:|---:|
| Ambient | 0 | **0** | 12000 | 0／12000 |
| Local | 1000 | **1000** | 13000 | 1000／12000 |
| Site | 5000 | **5000** | 17000 | 5000／12000 |
| Region | 20000 | **20000** | 32000 | 20000／12000 |
| World | 100000 | **88000**（被敵軍總量封頂） | 100000 | 88000／12000 |

每列皆斷言 `具名 + 無名 == 最終總量`；具名例外從最終配額扣抵，沒有加算第二次。
Ambient 真為 0，四個非零等級都真的偏離；World 可獨自補足剩餘 88000 並扭轉戰役。

## 負向控制（真的紅）

直接執行故障 binary 為 **0/2 通過、exit 1**：

- 拿掉 δ clamp 與軍力上限：全 Region 損失 **14260**，升 Local 後單一 Ambient 個體使損失
  變成 **1014260**，敵軍只有 **100000**；`縮放無偏` equality 明確失敗。
- Site 主場後故意再跑 Region：`site_runs=1`、`region_face_damage_writes=1`；「必須 =0」
  明確失敗。

CTest wrapper 只有在兩段輸出與數字都出現且內層非零時才綠。

## 效能、驗證與 CI 判斷

完整校準一輪 = 1000 樣本 × 3 層。暖機 1 次後固定量 5 次取最小值，實測
**1.824 ms**（Debug，共用機器），預算 500 ms；測試本身含暖機與五次量測約 11 ms。
**適合進 CI**：時間相對全套測試可忽略，且能守住防刷、p、δ、主場唯一性與決定論。

- `cmake --build build --parallel 2`：通過，未超過 2 路。
- `ctest --test-dir build --output-on-failure`：**359/359** 通過，82.79 秒。
- `aetheria_sim --tick 62208000`：exit 0；Godot editor 首掃走既有重跑路徑後 exit 0，主場景 exit 0。
- `git diff --check`：通過；未動 `design/`、指定禁區、v18 或 push。

## 現有測試證不了的事

- Site 方陣與 Local 個體戰鬥器尚不存在；目前能證明校準轉接、守恆與防刷契約，不能證明
  未來陣型、地形、技能、AI 操作接入後仍無偏。接入時必須用同一組 N=1000 回歸重測。
- Welch 檢定刻意只檢驗平均位置；設計允許三層方差不同，因此不以 KS 檢定強迫整個分布同形。
- 跨平台逐位元決定論只在本機 ABI 實跑；placement 型別已限制為兩個 `uint64_t` 並
  `static_assert(has_unique_object_representations)`，但尚未在第二平台執行。
