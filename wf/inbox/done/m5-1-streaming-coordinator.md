## 這輪的核心：時鐘只有一份

你在批次入口加的「拒絕旬內小時不同步」是對的**過渡**行為，但那條檢查真正在說的是
「這 N 份時鐘拷貝必須彼此同意」——而它們之所以可能不同意，**只因為時鐘被拷貝了 N 份**。

> **裁定：旬內小時由全局時鐘導出，不存在 Site 上。**
> 拿掉 `CityEconomy::hours_into_xun`，串流中途載入的 Site **讀**時鐘，不自帶一份。

⚠ **這改位元流，要升版到 v14**，版本沿革表照舊由你維護。

⚠ **不要擴大解釋。** 我掃過全庫，帶時間語意的持久欄位分三類，只有一類是缺陷：

| 類別 | 例子 | |
|---|---|---|
| 時距 | `remaining_hours`、`aging_seconds`、`elapsed_seconds` | ✅ 各物件自己的量，留著 |
| 時戳 | `unload_tick`、`last_saved_tick` | ✅ 是紀錄不是時鐘，留著 |
| **時鐘讀數** | `hours_into_xun` | ❌ **只有這一個要拿掉** |

分界是「**這個值會隨時間自己前進嗎**」。會的才是拷貝。

## 串流協調器

照 [`lowmap-streaming.md`](../../design/lowmap-streaming.md)，**不引入任何新機制**，
就是 [`observer.md`](../../design/observer.md) 的場強換一組參數：

| 參數 | 值 |
|---|---|
| `L_FULL` 半徑 | 1 格（3×3 = 9 個 zone） |
| `L_COARSE` 半徑 | 2 格（5×5 外圈） |
| 場強重算 | **每次玩家跨格** |
| `N`（落到 `L_ABSENT`） | 1 旬 |

要做的：

1. **場強重算 + 升降級**，接到既有 LOD 狀態機，不要另立一套詞彙。
2. **接上 M5-pre 的批次入口**——3×3 全載表示同時有多個 `L_FULL`，
   協調器必須把它們**一次交給批次**，不准逐一呼叫單 Site 入口。
3. **卸載延遲緩衝圈**：離開的 zone 不立刻卸載。
   ⚠ **玩家在邊界來回踱步不得反覆觸發載入／卸載**——這要有測試。
4. **降級與逐出只在回合結算尾端執行**（[`principles.md`](../../design/principles.md) 原則七）。

## 驗收

| 判準 | 怎麼量 |
|---|---|
| 時鐘唯一 | `hours_into_xun` 不再存在於任何持久結構；批次的同步檢查**因而可以拿掉** |
| 存檔升 v14 | 舊檔大聲拒讀，不是靜默讀壞 |
| 3×3／5×5 | 玩家所在為中心，實測各級 zone 數 = 9 / 16（外圈） |
| **踱步不抖動** | 玩家在邊界來回 N 次，載入／卸載次數必須**有界**，不隨 N 線性成長 |
| 批次真的走批次 | 一旬內 Region 結算次數 == 1，即使有 9 個 `L_FULL` |
| 回合尾端 | 模擬途中不得發生降級／逐出 |

### ⚠ 負向控制（每條都要有，沒有偵測力的通過不算通過）

- **踱步**：先量「沒有緩衝圈」的版本會抖動幾次，再證明有緩衝圈後有界。
  兩個數字都要寫進回報。
- **批次**：讓協調器退化成逐一呼叫，Region 結算次數必須被測出來 > 1。
- ⚠ **你上一輪自己踩到的**：注入了但兩邊都沒紅 = **那次注入沒有偵測力，不算通過**。
  這輪每個負向控制都要確認它**真的紅了**，紅的是哪一個測試、數字從多少變多少。

### 量測規約

效能斷言一律**暖機後取 N≥5 次最小值**，**禁止重試到過為止**。
每個量測附「路徑真的跑過」的計數；**計數為 0 的量測不算通過**。
