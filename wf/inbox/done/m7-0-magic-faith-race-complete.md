## 結果

已完成三條位階來源的共同接點：`PowerSourceDef/State` 統一提供 tier 加成、能力、四屬性
修正與剝奪條件，且只由 `resolve_power_profile()` 彙整。魔法、信仰、血統的三個接線測試
均走此函式，最後統一套用種族上限。Ruleset 加入 `SchoolDef`、`TenetDef`、`DeityDef`、
`RaceDef` 與 typed id；資料骨架只有指定六學派，神祇、教義、種族保持空白，未代替使用者
創作內容。

魔法涵蓋 Region 儀式、Site 方陣、Local 個體三層；Local 直接使用 M6.1
`evaluate_check()` 的單骰 d100。信仰有教義衝突、立即剝奪與 root World 神祇殞落事件；
種族提供屬性、位階上限與壽命，loader 明確拒絕血統提高起點。未做職業、經驗等級、
Vancian 法術或科技對立軸，未改 `design/`，未 push。

## 三者不可互相取代

同一場戰鬥的三名個體可比較：魔法 `S=1600`、信仰 `S=1600`、血統 `S=400`，合計
`S=3600`。在共同 S 接點之外，各自仍有別條來源沒有的操作：

1. **魔法**：多旬儀式完成後寫入 Region 天氣／戰鬥姿態；信仰與血統 API 都不能供應此
   Region 戰役修正。
2. **信仰**：神祇殞落的單一 World 事件可同時剝奪所有信徒兩階；魔法與血統沒有這種
   可撤銷、跨信徒的來源生命週期。
3. **血統**：位階上限在所有加成彙整後仍硬性截斷；魔法與信仰只能提供加成，不能繞過
   Local cap。

目前三個情境確實不可互換，未發現需回報的可替代設計。

## 版本與現有測試證不了的事

本輪新增的是規則 def 與測試用執行期狀態，沒有加入 zone／registry 持久欄位，因此存檔仍為
**v18**，沒有占用指定的 v19。現有測試不能證明這些執行期魔法／信仰狀態的存讀、冷載入或
正規化 hash；若後續將它們納入權威世界狀態，才需以 v19 payload 補齊往返與舊版拒讀。

神祇殞落已證明個體 tier 與計算出的等效戰力同步改變，但本輪沒有 Region 配額統計的寫入
入口；因此不能證明 M6.4 的 Region aggregate 會和大量信徒掉階同交易重算。直接接入現行
世界前仍可能形成統計層／個體層兩個真相，需後續由權威配額歸約處理。另未證明跨 zone
信徒 fan-out、真實內容生成、AI 決策或 UI 表現。
