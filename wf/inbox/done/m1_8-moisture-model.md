## 我算過了：這個模型**不可能**讓平地不是沙漠

`core/worldgen/stage_climate.cpp:63-68`：

```cpp
const auto rain = std::min<std::uint32_t>(air, 900U + rise * config.uplift_rain);
output.moisture[index] = static_cast<std::uint16_t>(rain);   // ← 這裡
const auto spent = std::min<std::uint32_t>(air, rain + config.air_decay);
air -= spent;
```

### 錯誤一：`moisture = rain`（本步降下的雨），不是空氣的含水量

平地 `rise = 0` → `rain = 900 + 0 = 900`（**固定值**）。沙漠門檻是 **12500**。

> **900 < 12500 恆成立。平地在算術上不可能不是沙漠。**

唯一的例外是單格爬升超過 **483 公尺**（`rise × 24 > 11600`）——也就是**只有陡峭的迎風面**
能越過門檻。這正是你量到的：94～99% 沙漠，而 28k～37k 的濕尾全在山的迎風面。

**概念上的錯誤**：一塊濕潤的平原之所以濕潤，是因為**流過它的空氣是濕的**，
不是因為那一步剛好下了雨。`moisture = rain` 等於宣告「這一步沒下雨的地方就是沙漠」。

### 錯誤二：`air` 是等量遞減，不是比例衰減

平地每格扣 `rain + air_decay` = `900 + 1800` = **2700**。起始 `air` 是 30000～50000。

> **約 11～18 格之後 `air` 歸零。地圖寬 128 格。**

之後 `rain = min(0, …) = 0`，moisture 直接 0——這就是你量到的 **p25 全為 0、中位數 0** 的來源。

減法衰減還有第二個毛病：它讓模型跟**地圖寬度綁死**。地圖變寬，絕對乾燥帶就跟著變大。
比例衰減（每格保留固定百分比）才會產生**跨整片大陸的平滑梯度**，而且與地圖尺寸無關。

這跟 M1.7 是同一類問題：**模型的形狀錯了，不是數字錯了。**
（也印證了我很久以前記在 SESSION-LOG 的那條：「雨影探針 leeward moisture 剛好 0，
合成探針裡合理，但真實地圖若出現連綿不斷的絕對乾燥帶，代表水氣模型太激進。」
現在確認了，而且比「太激進」更根本。）

## 範圍

### 1. `moisture` 由空氣含水量導出

地表濕度要是**流過該格的空氣含水量**的函數，地形抬升造成的額外降雨是**加成**，不是全部。
形狀我裁定成這樣，實際換算你決定並說明：

```
moisture[tile] = f(air) + 地形抬升加成
```

`f` 要讓「濕空氣經過的平地」拿到高濕度，「乾空氣經過的平地」拿到低濕度。

### 2. `air` 改成比例衰減

每格保留一個固定**比例**，不要等量扣除。空氣會漸近趨零而不是在第 15 格硬著地。
降雨仍然要從 `air` 扣掉（守恆），但**基礎衰減**改成比例。

參數怎麼表達你決定——**但只准新增一個參數**，並在 `civilization.toml`／climate config
裡有明確名字與註解。不要一口氣加三個旋鈕。

### 3. 一次只動一個變因（跟 M1.7 一樣）

- **不要動 `data/biomes.toml` 的任何門檻**（12500 / 52000 / 20 / 4500 一律不動）
- **不要動 relief 那三個數值**
- 只改水氣模型的**形狀**，加上必要的那一個參數

我要看的是「光把水氣模型的形狀改對，畫面變多少」。門檻校準是**下一輪**的事。
