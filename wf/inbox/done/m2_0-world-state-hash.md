## 為什麼第一輪做量測工具，而不是先做展開

M1 給了一個很貴的教訓：**十二階段的雜湊全綠、114 個測試全過，世界卻是單色的**——
因為當時沒有任何工具能「看見」結果。Region 檢視器一上線就抓到 97% 是沙漠，
而那個缺陷已經悄悄躺了好幾個里程碑。

M2 的「不漂移」有同樣的問題：**沒有漂移偵測器，「不漂移」就是不可驗證的。**
而且 `zone-save-format.md` 早就警告過：

> **不要拿 byte 相等去驗跨歷史的等價**，那會在 M4 給出假失敗，或更糟——
> 為了讓 bytes 相等而去強行同步兩條路徑的建構順序，**那是把測試需求洩漏進玩法邏輯**。

所以先把儀器做出來。

## 範圍

### 1. `world_state_hash(save_dir)`

設計已經裁定了做法，照做：

> 直接走訪存檔目錄（`saves/<slot>/**/*.bin`）列舉，載入後逐一算 per-zone 雜湊，
> 再**依 key 排序**合併。

- 複用 M1.3 已有的 `normalized_state_hash(zone, ...)`，不要另寫一份
- 合併順序**必須依 `ZoneKey` 排序**，不能依目錄走訪順序（那是檔案系統決定的，不決定論）
- 要能處理**磁碟上的 zone**（M4 的情境是「有些 zone 還在磁碟上」）

### 2. 它必須在結構上看得出是「驗證工具」而非執行期狀態

`zone-model.md` 的成長軸不變量禁止 manifest 存 zone 清單；世界級雜湊之所以能列舉，
**正是因為它不常駐、不進存檔、不影響玩法路徑**。這個性質要**在結構上守住**，不是靠註解：

**裁定**：把它做成 `aetheria_sim` 的子命令（例如 `aetheria_sim verify world-hash <save_dir>`），
不要放進任何會被 tick／populate／load 路徑呼叫到的地方。
加一條測試斷言**玩法路徑不會呼叫它**（怎麼斷言由你決定，能擋住就好）。

### 3. 三條證明（這是本輪的核心產出）

**(a) 跨建構歷史等價**：用**兩種不同的建構順序**造出同一個世界狀態
（例如反序建立單位、或先建 A 再建 B vs 先建 B 再建 A），兩者的世界級雜湊**必須相同**。

**(b) 同時證明 bytes 真的不同**：貼出兩邊存檔的 byte 長度或 byte 雜湊，**證明它們確實有差**。
⚠ 這條不能省——你 M1.3 做過一次一模一樣的事而我當時特別點名過：
**「雜湊相同」如果不搭配「bytes 確實不同」，可能只是因為兩邊根本一樣，等於沒證。**

**(c) 負向控制**：只改**一個** component 的**一個**值，世界級雜湊**必須改變**。
再加一條：只改**執行期 LOD／cache／pinned** 這類不進存檔的東西，雜湊**必須不變**。

### 4. 健壯性

存檔目錄不存在／空目錄／檔案損毀／版本不符 → **fail-fast 且錯誤訊息指出是哪個檔**。
不要安靜跳過壞檔（那會讓雜湊「看起來對」）。

## Done when

- [ ] `world_state_hash` 可用，合併依 `ZoneKey` 排序（不依目錄走訪順序）
- [ ] 做成 `aetheria_sim` 子命令；有測試擋住玩法路徑呼叫它
- [ ] **證明 (a)**：兩種建構順序 → 世界級雜湊相同（貼雜湊）
- [ ] **證明 (b)**：同一組存檔的 **byte 層確實不同**（貼 byte 雜湊或長度）
- [ ] **證明 (c)**：改一個 component 值 → 雜湊改變；只改執行期狀態 → 雜湊不變（各貼雜湊）
- [ ] 空目錄／缺目錄／壞檔／版本不符各自 fail-fast，錯誤訊息含檔名（負向測試）
- [ ] **多 zone**：至少 3 個 zone 的存檔，其中包含尚未載入的（證明它真的走訪磁碟）
- [ ] 四 target 零警告、CTest 全綠、`aetheria_core` 仍零 godot-cpp
- [ ] commit 到 `main`（**不 push**）

## 回信給我

寫成 `wf/inbox/m2-0-world-state-hash-complete.md`。三個問題：

1. **證明 (b) 的 bytes 真的不同嗎？** 如果兩邊 bytes 恰好相同，那證明 (a) 就沒有意義——
   要換一種更激烈的建構順序差異再試。**直說，不要讓它看起來過關。**
2. **合併函式你用了什麼？** 依 key 排序之後怎麼合併（XOR？逐一餵進同一條 FNV？）——
   XOR 對「兩個 zone 交換內容」是盲的，如果你用 XOR 請說明為什麼不會出問題。
3. **走訪磁碟的成本？** 幾個 zone、多少毫秒。這是驗證工具不在玩法路徑上，
   但 M4 會反覆呼叫它，太慢會變成測試的瓶頸。
