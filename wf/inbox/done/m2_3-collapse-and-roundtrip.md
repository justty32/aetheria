## 這輪的核心風險：往返測試很容易「假通過」

我要先講三個會讓這條驗收變成空證的陷阱，你要主動避開：

### 陷阱一：狀態沒有真的離開記憶體

如果收回之後 Procedural 層還留在快取裡，再展開時就不是「重算」而是「沿用」——
**重算路徑的 bug 會被完全掩蓋**。

要求：**每次重新展開都必須從磁碟冷載入**。照你 M2.0 那招——
斷言該 zone 在展開前確實**未載入**，不要只信 API 名字。

### 陷阱二：持久層停在預設值

如果那棟建築整場都是 `Active`（預設值），那麼「重載後回到 `Active`」
既可能是正確還原，**也可能是被重設成預設值**——兩者無法區分。

要求：**往返前先把建築改成非預設狀態**（`Idle` 或 `Derelict`），
再開始三次往返。這樣「重設成預設」的 bug 才會現形。

### 陷阱三：只比最後一次

三次往返只比第一次與最後一次，中間的漂移可能互相抵消。

要求：**每一次收回後、每一次展開後都取一次世界級雜湊**，貼出完整序列。
我要看的是整條序列而不是頭尾。

## 範圍

1. **收回**：`L_COARSE → L_ABSENT`，寫盤。照 `interface-lifecycle.md` 的狀態機，
   不要另立一套詞彙。
2. **三次往返**：展開 → 收回 → 展開 → 收回 → 展開 → 收回，全程冷載入。
3. **Procedural 確實是重算而非讀盤**：加一條證明（例如斷言存檔裡沒有程序層資料，
   或刻意破壞快取後結果不變）。
