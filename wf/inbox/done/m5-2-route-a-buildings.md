## 這輪是純工作量，但有兩個容易搞混的地方

M5.0 把路線 B（開放地表）做完了。這輪做**路線 A：建築內外**，
`localgen.md` 說 10 ms 預算主要就是留給它的。

### ⚠ 尺度對應（設計文件點名「實作時最容易搞混」）

> Site 層的一個「建築」是 **125～500 m = 街廓**尺度；
> 放大到 Local 才是**一棟棟房子**。

M5.0 的 adapter 目前遇到 structure 就拒絕（那是對的，路線 B 不該處理）。
這輪要接手：一個帶 structure 的 Site tile → 一整片街廓的房子。

### ⚠ 同一個演算法用兩次

A3 分間**直接複用 [`sitegen-city.md`](../../../design/sitegen-city.md) 的遞迴二分**，
不要另寫一份。Site 層切街廓、Local 層切房間，**同一份實作、兩個尺度**。

**驗收方式照 M5.0 那條**：把共用的切分實作改壞，
**Site 側與 Local 側的測試必須同時變紅**。只紅一邊就是複製。
⚠ 而且要確認注入**真的紅了**——你上一輪的 corner salt 注入兩邊都沒紅，
那次沒有偵測力。**沒紅的注入不算通過**，要換一個能觀察到差異的注入點。

## A1～A7

```
A1 地基     從 BoundaryProfile 內插，鋪街廓地面材質
A2 排屋     沿臨街邊排輪廓，背對背，中間留內院
A3 分間     遞迴二分（複用 sitegen-city，切點偏離正中）
A4 開門窗   在牆（邊）上開門與窗
A5 家具     依房間類型從資料檔填
A6 居住者   見下節
A7 垂直層   有地窖生 z=−1，有樓層生 z=+1
```

**牆與門是邊屬性**，沿用既有 `EdgeDef`。不要發明「牆佔一格」。

### A6：絕大多數不生成實體

[`localgen.md`](../../../design/localgen.md) 寫死了：

| 情況 | 怎麼做 |
|---|---|
| 玩家沒進屋 | **只有一筆「這裡住著 N 人」的統計，零實體** |
| 玩家進屋 | 才生出 `Ambient` 級居住者 |
| 具名 NPC | 從持久層還原 |

⚠ **不要為了「看起來完整」就把整城的居住者都生出來**。
一個城鎮的 Local 應該只有幾十個實體，不是幾千個。
回報要寫**實際生成的實體數**。

## 驗收

| 判準 | 怎麼量 |
|---|---|
| 尺度對應 | 一個街廓切出幾棟房、每棟幾個房間，數字要合理（房間 ≥ 5×5 格 = 10 m 見方） |
| **切分複用** | 改壞共用實作 → 兩層同時紅（含「注入真的紅了」的確認） |
| **有門就有牆、有牆的房間必有門** | 不得產生進不去的房間。這是**結果的不變式**，不限定實作 |
| 10 ms 預算 | 暖機後 N≥5 次最小值。**這是最貴的路線，真正的考驗在這** |
| 實體數 | 城鎮 Local 的實體數量級要是**幾十**，不是幾千 |
| 決定性 | 同輸入同輸出，正規化雜湊；**不要用 byte 相等** |
| 骨架只讀慢變數 | 用簽章擋，不靠自律 |

### ⚠ 每個量測都要附「路徑真的跑過」的證據

生成了幾棟房、幾個房間、開了幾扇門、擺了幾件家具、生了幾個實體。
**計數為 0 的量測不算通過**——沒跑過的路徑耗時 0 ms、誤差 0，兩個數字都很漂亮。

### 負向控制

- 「有牆的房間必有門」要有一個**故意封死**的反例，證明測試抓得到
- 10 ms 若超標，先報數字，**不要為了達標偷偷簡化到不生成東西**
