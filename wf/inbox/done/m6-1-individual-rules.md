## 四屬性：不是六屬性

| 屬性 | 涵蓋 | 主要力量來源 |
|---|---|---|
| **體** Body | 力量、耐力、生命上限、負重 | 近戰武技 |
| **技** Skill | 靈巧、命中、迴避、潛行、手藝 | 遠程與技巧武技 |
| **心** Mind | 智力、學識、魔力上限、施法 | 魔法 |
| **魂** Spirit | 意志、感知、信仰、魅力 | 信仰、統御 |

**衍生值全部算出來，不獨立存**：生命、魔力、命中、迴避、防禦、抗性、移動、負重、視野。
公式從資料檔讀。

## d100 檢定

```
成功 ⟺ roll(rng, 0..99) < 屬性值 + 修正 − 難度
```

⚠ **沒有暴擊骰另外擲。** 用同一次擲骰的**餘量**表達：超出門檻越多效果越好，分段查表。
設計文件寫得很明白：**少擲一次骰 = 少一個決定論破口**。

- `rng` 是**注入的** `std::mt19937_64`，不准內建、不准讀時鐘
- 分段表從資料檔讀

**負向控制**：把「餘量分段」換成另擲一顆暴擊骰 →
擲骰次數改變，同 seed 的結果序列必須整條變掉，決定性測試要紅。
把紅的是哪個測試、差異長什麼樣寫出來。

## 傷害與抗性

```
實際傷害 = 基礎傷害 × (100 − 抗性) / 100
```

- **傷害型別是 `DamageTypeDef`，不是 enum**。初版資料檔：斬、刺、鈍｜火、冰、雷｜毒、暗、聖
- 抗性**可為負**（弱點）
- 抗性上限 90%（初值，資料檔）——**不允許完全免疫**
- ⚠ **完全免疫走的是階差門檻，不是抗性。兩條路徑必須分開。**
  這樣「這打不動」才有兩種可解釋的原因：抗性高（換傷害型別）或階差太大（需要破階手段）。
  階差門檻本身是 M6.0 在做，**你這輪不要實作它**，只要確保你的抗性路徑
  結構上不可能產生 100% 減傷（負向控制：把上限拿掉 → 測試要紅）。

## `suggest_tier`：位階與屬性的校準

設計已裁定：**位階是獨立欄位，屬性是它的細部展開，不是它的來源。**
理由是資料可用性——Region 層算等效戰力時，個體屬性根本沒載入。

但兩者必須校準，否則會出現「屬性頂尖卻是低階」的荒謬：

```
suggest_tier(attributes) → 建議位階
```

- 實際 tier 預設等於建議值，**可被覆寫**（劇情人物、神器持有者、被詛咒者）
- **測試（設計文件指定的）**：隨機 1000 組屬性，`|實際 tier − suggest_tier| ≤ 1`

⚠ `suggest_tier` 回傳 `world::Significance`（既有型別），**不要另立 enum**。
它與 M6.0 的權重表是同一套等級，但**兩路並行**——
你只 include `core/world/significance.h`，不要碰 M6.0 的檔案。

## 驗收

| 判準 | 怎麼量 |
|---|---|
| 一次擲骰 | 同 seed 跑 N 次檢定，`rng` 的呼叫次數 == 檢定次數 |
| 分段有效 | 餘量最大與最小的結果**必須不同**，附兩個數字 |
| 抗性可負 | 負抗性放大傷害，附前後數字 |
| 不可完全免疫 | 抗性設到極大，減傷仍 < 100%，附實際百分比 |
| `suggest_tier` 校準 | 隨機 1000 組，超差的組數與最大差 |
| 決定性 | 同 seed 同結果；整數運算，**不准 `double`／`std::pow`** |
| 型別是 def 不是 enum | 加一種傷害型別只改資料檔就生效，**實測加一種**並附證據 |

### ⚠ 三個一定要避開的假通過

1. **每個傷害型別、每個餘量分段都要在參考案例裡真的被打到。**
   M5.4 踩過兩次「門檻落在分布之外」——規則寫了但一次都沒命中，測試照樣全綠。
   **回報要附每個型別、每個分段的命中計數**，任何一格是 0 就是有問題。
2. **`suggest_tier` 別讓分布塌掉。** 若 1000 組隨機屬性有 900 組落在同一階，
   那個測試等於沒測。**回報要附五階各自的組數。**
3. **「同 seed 同結果」對一個什麼都沒擲的實作也成立。** 先確認擲骰真的發生了，附次數。
