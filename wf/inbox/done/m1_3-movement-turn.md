## 這份任務要證明什麼

M1 的完成判準是「生成一個 Region、單位可移動、旬回合可推進、**存讀檔一致**」。
前兩項是工作量，**第四項是真正的技術內容**——而且它會逼出一個 M2／M4 都需要的東西。

## ⚠ 「存讀檔一致」不能用 byte 比較

你在 M1.0 指出過：EnTT snapshot 只對**同一段建構歷史**決定性，不會 canonicalize。

「存檔 → 讀回 → 再推 N 旬」與「不存檔 → 直接推 N 旬」是**兩段不同的建構歷史**
（讀檔那條走過 snapshot loader，entity id 的配發順序不同）。
拿 byte 相等去驗它，會得到**假失敗**。

所以 M1.3 要建立**正規化狀態雜湊**：

- 與 `entt::entity` 的具體數值**無關**——依穩定 key（座標、`StableId`、def id）排序後再雜湊。
- 涵蓋所有**權威狀態**：tile 欄位、單位位置與 MP、時鐘、命令佇列。
- **不涵蓋執行期衍生量**（LOD、快取、`pinned`）。

M2／M4 都要用它（M4 是「Site 卸載後推進 N 旬再載入，結果與不卸載一致」——
同樣是跨歷史比較）。**現在建立它，是 M1.3 最有價值的產出。**

判準用哪個工具，照這張表：

| 比什麼 | 用什麼 |
|---|---|
| 同一串命令跑兩次 | byte 相等（同歷史，可用） |
| 存讀檔前後、卸載重載前後 | **正規化狀態雜湊** |

## 範圍

### 1. 移動

照 [`worldmap.md`](../../../design/worldmap.md)：

- **MP 是整數**（避免浮點漂移）。進入一格的成本由各 def 的 `move_cost` 相加，
  再乘季節修正——**成本全部來自資料檔，不寫死**。
- **邊上的東西優先**：移動所經的邊若有 `EdgeDef`（道路、棧道、橋），成本改用該 def 的跨越成本。
  小數用「MP 以 2 為單位」的整數表示法迴避。
- **河流阻擋**：跨越河類 `EdgeDef` 需額外成本，除非該邊另有橋類 def。
- **命令是持續的**：下一次移動命令後，單位每旬自動推進，中途遇敵或遇事件才中斷。
  **這是文明系列的節奏，不是每旬手動點一步。**

海格／港口這輪**先跳過**（還沒有船的 def）。

### 2. 尋路

Region 內 A*，四鄰接，啟發函數 = 曼哈頓距離 × 最小格成本（**admissible**）。
跨 Region 與路徑快取這輪不做。

### 3. 旬回合流水線

七個階段的**順序骨架**要對，但這輪只有 1、2、7 有實質內容：

| 階段 | M1.3 |
|---|---|
| 1 玩家指令 | ✅ 收集命令（時鐘不動） |
| 2 命令執行 | ✅ 移動 |
| 3 遭遇判定 | ⬜ stub |
| 4 勢力 AI | ⬜ stub |
| 5 世界模擬 | ⬜ stub |
| 6 事件階段 | ⬜ stub |
| 7 回合末 | ✅ 自動存檔、時鐘 += `kXun` |

**stub 也要在流水線裡佔位**，順序固定。之後補內容時不會有人把順序放錯。

**任何非確定性都不允許進入這條流水線。**

## Done when

- [ ] **正規化狀態雜湊**：與 entity id 無關，說明你怎麼證明這一點
- [ ] **存讀檔一致**：存檔 → 讀回 → 推 N 旬，與不存檔直接推 N 旬，
      **正規化雜湊相同**（N ≥ 10）。**貼兩組雜湊**
- [ ] **同一串命令跑兩次 byte 相等**（這條仍用 byte，因為同歷史）
- [ ] **A* 的解與 Dijkstra 相同**：隨機地圖上跑 ≥100 組起訖點，兩者的**路徑成本必須相等**。
      這條會否證「啟發函數是不是真的 admissible」——不 admissible 就會給出次佳解
- [ ] **道路真的更便宜**：同一條路徑，邊上鋪道路前後的總成本下降（貼數字）
- [ ] **河流真的擋人**：跨河成本高於不跨河；同一條邊放橋之後成本下降
- [ ] **持續命令**：下一次命令後推 5 旬，單位每旬自動前進，不需要重複下令
- [ ] **MP 與所有移動計算零浮點**（型別上擋住）
- [ ] 七階段流水線順序固定，stub 階段有佔位且被呼叫
- [ ] 四個 target 零警告、CTest 全綠、`aetheria_core` 仍零 godot-cpp
- [ ] commit 到 `main`（不 push）
