## 這輪補的是 M6.6 自己指出的缺口

M6.6 的回報寫著：

> 現有持久世界模型沒有「治安」「具名 NPC missing」「地城 cleared/depth」欄位。
> 因此這四種目前驗證的是「給定世界觀測快照後只依真門檻生成」，
> **尚不能證明完整遊戲循環已供應這些觀測**。
> **不能為補證據而在 Godot 或任務模組另建第二份世界真相。**

⚠ **它拒絕造第二份真相並回頭要裁定，這個判斷是對的。** 現在裁定下來了。

## 裁定：一個走歸約，三個走持久層旗標

| 觀測值 | 歸屬 | 為什麼 |
|---|---|---|
| **治安** | ✅ **歸約量表新增第五列** `city.order` | Site 側算得出數值、Region 側有對應數字 |
| 具名 NPC `missing` | 持久層旗標 | 旗標不是量 |
| 地城 `cleared` | 持久層旗標（`dungeon.md` 已定義，防刷用） | 同上 |
| 地城 `depth` | 生成期的靜態屬性 | 它不變，不需要歸約 |

⚠ **歸約表只收「Site 側算得出數值、Region 側有對應數字」的量。**
不要順手把三個旗標也塞進歸約表——那會讓歸約的語意糊掉。

### 治安的歸約側算法

```
治安 = 駐軍／巡邏覆蓋 − 盜匪與流民壓力
```

數值全部從資料檔來，一個都不准寫死。

⚠ **歸約新增一列會踩到 M5 已經踩過的坑**：
`interface-world-mid.md` 記著「L1↔L2 的歸約原本假設**每一列都必有值**」，
M5.15 為此把每列改成 `std::optional<Value>`。
**新列要照那個既有機制走**，不要另發明「缺值時用 0」——
⚠ **`0` 與「缺席」看起來一樣但意義相反**：
治安 0（無政府）與治安未知（Site 沒載入）是完全不同的兩件事，
**存檔與歸約都必須分得出來**。負向控制：讓缺席退化成 0 → 測試要紅。

## 接線目標

M6.6 的五種湧現任務目前吃的是「觀測快照」。這輪讓其中四種吃**真實世界狀態**：

| 任務 | 要能從真實世界讀到 |
|---|---|
| 清剿盜匪 | 某格治安低 |
| 尋人 | 某具名 NPC `missing == true` |
| 探索 | 地城 `cleared == false` 且 `depth` 夠深 |
| 戰前情報 | 積怨高且國力接近（**外交真值是別路的禁區**——這輪只留介面，不要接） |

**運糧那條 M6.6 已經真的接上了**（石橋鎮 40→100、`reduction_writes=1`），照那個模式做。

## ⚠ 清剿要能真的提高治安

這是新增治安列的**全部理由**。所以驗收是：

> 完成一個清剿任務後，該格的治安數字**真的變好**，
> 且變化是**經由歸約通道**發生的（附歸約寫入計數）。

附前後兩個數字。⚠ 若它沒有真的改變世界，這一列就白加了。

## 驗收

| 判準 | 怎麼量 |
|---|---|
| 治安歸約列可用 | Site 側算得出、Region 側收得到，附前後數字 |
| 清剿真的提高治安 | 附前後數字 + 歸約寫入計數 |
| 缺席 ≠ 0 | 未載入的 Site 其治安是「缺席」不是 0，附兩者的區別證據 |
| 三個旗標接上 | `missing`／`cleared`／`depth` 從真實世界讀得到 |
| 沒有第二份真相 | 任務模組沒有自己的世界狀態，附證據 |
| 四種任務吃真值 | 附各自的生成計數（**任何一種是 0 就是有問題**） |
| 存檔往返 | 治安與三個旗標跨存檔存活 |
| 決定性 | 同輸入同結果 |

**負向控制**：讓「缺席」退化成 `0` → 區分測試必須紅，附紅的數字。

## 不要做的事

| 不要 | 理由 |
|---|---|
| 把三個旗標塞進歸約表 | 旗標不是量，會糊掉歸約語意 |
| 接外交真值 | M6.2b 在並行，戰前情報這輪只留介面 |
| 缺值時用 0 當預設 | `0` 與缺席意義相反 |
| 動戰鬥公式 | M6.3 並行中 |
| 改 `design/` | 有設計異議寫進回報，我裁定 |
