## 這輪要成立的是兩件互相拉扯的事

設計文件把它寫成整個力量體系存在的理由：

1. **一個傳奇騎士能打散一群農民** —— 否則英雄沒有意義
2. **一個傳奇騎士打不過一支軍團** —— 否則國家與戰爭沒有意義

⚠ **驗收判準不是「公式寫對了」，是這兩件事實際成立。**
你要量出**具體的 N 與 M**：一個 tier 4 打得過 N 個 tier 0，打不過 M 個。
兩個數字都寫進回報。若 N 與 M 之間沒有明顯區間（例如 N=250、M=260），
那表示權重表選錯了——**如實回報，不要調參數把它藏起來**。

## 位階直接用既有的 `world::Significance`

`core/world/significance.h` 已經有五級。**不准另立一套 tier enum。**
設計文件明說「他有多強」與「他值不值得被個別計算」是同一件事。

| Tier | Significance | 權重（初值，從資料檔讀） |
|---|---|---|
| 0 凡俗 | `Ambient` | 1 |
| 1 精銳 | `Local` | 4 |
| 2 名士 | `Site` | 16 |

## ⚠ 最容易混淆的一處：兩種「升級」不共用規則

`power-tiers.md` 末段點名了這件事，**實作時要分開**：

| | 戰鬥位階 | 聚合提升重要性 |
|---|---|---|
| 升級條件 | 實戰、修行、神器、劇情、繼承 | 人數／影響聚合到一定量 |
| 提升的是 | 打得贏誰 | 有沒有資格被個別計算 |

**負向控制**：把 1000 個 tier 0 湊成一個 cohort，
`cohort_tier` 必須**仍然是 0**（`cohort_S` 才變大）。
若你的實作讓它升階了，就是把兩條規則混在一起了。

## 等效戰力

```
S = Σ over units ( count × tier_weight[tier] × quality )
```

- **全整數**。`quality` 用百分比整數表達（0.5～2.0 → 50～200），不要浮點。
- `S` 用 `int64_t`。溢位要有 `AETH_CHECK` 或飽和，寫清楚選了哪個。
- `tier_weight`、`quality` 的值域**全部從資料檔讀**（新增 `data/power.toml`），
  一個數字都不准寫死在 `.cpp` 裡。

### ⚠ 一個我要你去量的邊界

設計說「裝備不跨階：裝備再好也不會讓民兵變成騎士」。
但權重每階 ×4、`quality` 值域 0.5～2.0，於是：

```
頂裝的 tier N   = 200% × w      = 2w
劣裝的 tier N+1 =  50% × 4w     = 2w
```

**恰好相等，一點餘裕都沒有。** 去實測確認是不是這樣，
然後回報**你認為這是可接受的貼齊、還是值域該收窄**。
⚠ **不要自己改值域**——這是設計裁定，我來裁。你只負責量出來並給判斷。

## 位階門檻：質的部分

> **階差 ≥ 3 時，低階方對高階個體的傷害趨近於零。**

- 門檻**只作用在個體**，不作用在量的維度（軍團照樣被打垮）
- 破階手段（神器／大魔法／地形陷阱／攻城器械／另一個高階存在）解除門檻
- 破階手段走 `definitions.md` 的 def，**不是 enum**，放進 `data/power.toml`

**負向控制**：拿掉門檻 → 「一萬個農民殺不死古龍」的測試必須紅，
並寫出紅的時候古龍掉了多少血。

## 驗收

| 判準 | 怎麼量 |
|---|---|
| 兩件事同時成立 | 量出 N 與 M，兩者之間要有明顯區間 |
| 堆人數不升階 | 1000 × tier0 的 `cohort_tier` 仍是 0 |
| 階差門檻 | tier4 面對 tier0／tier1 傷害趨近 0；面對 tier2 不趨近 0 |
| 破階手段有效 | 同一組輸入，帶破階手段時傷害恢復 |
| 決定性 | 同輸入同結果；全整數，**不准出現 `std::pow`／`double`** |
| 數值全在資料檔 | `grep` 不到寫死的權重數字 |

### ⚠ 兩個一定要避開的假通過

1. **每個 tier 都必須在測試裡真的被打到**。M5.4 踩過兩次「門檻落在分布之外」——
   規則寫了但參考案例一次都沒命中，測試照樣全綠。
   **回報要附每個 tier 的命中計數**，任何一階是 0 就是有問題。
2. **不要挑一個「改了等於沒改」的量做負向控制**。
   拿掉門檻後傷害必須有可見的數值差，把前後兩個數字都寫出來。
