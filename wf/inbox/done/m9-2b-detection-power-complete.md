## 驗收腳本的可重現性故障控制

`verify_acceptance.py` 改用與 pytest 相同原理的平手色盤
`#000000/#020000/#000200/#000002` 與 `(1,0,0)` 合成輸入。腳本會複製工具到暫存目錄，
把色盤載入注入為 `set(values)`；原始檔從未被改動，注入後再用原始工具重跑，等同自動還原。

| 階段 | `PYTHONHASHSEED=11` | `PYTHONHASHSEED=97` | 結果 |
|---|---|---|---|
| 健康版 | `1a61e9bff0ee36d738122230907a3a848b71ff97433abe22dc4bc14de2f7f039` | 同左 | 相同 |
| 注入無序色盤 | `acb5be8326a37ed5953e51e0abed2e56bc698129f415bc023bcdb65c4f32d8de` | `54053f55f80e4b94c2571dc389066f756d30924d82815ac357e908d0b1f31efa` | **分歧** |
| 還原後 | `1a61e9bff0ee36d738122230907a3a848b71ff97433abe22dc4bc14de2f7f039` | 同左 | 相同 |

注入沒有造成分歧、或還原後沒有回到完全相同，腳本都會退出 1。

## 光源行為

terrain 四方向的偵測順序為 `top-left / bottom-left / bottom-right / top-right`，旋轉角為
`0 / 270 / 180 / 90`；四張輸出 SHA-256 都是：

```text
da058940e825324215d4f7a26f39cb188c2db2c1b54c5bff7cd68d76c434997a
```

腳本內建「跳過 terrain 旋轉」故障控制後，四張分別變成：

```text
da058940e825324215d4f7a26f39cb188c2db2c1b54c5bff7cd68d76c434997a
b1fc116f1e0a91aad47c2c3d172f2f86770319d187de58596167ba7de4703ad2
f3b1d196b84c8665896a7676d04552f8a9da5568debb2d26dbf7a108b4ec066e
832a3aa47e66eecf337e3cc791a6679830abd71e7f9d36d494709b3900f6c70f
```

object 同一組四方向輸入的偵測方向相同，但旋轉角全部為 0；光源步驟前後逐位元比對全部
`true`，證明原朝向保留。四張輸出各不相同：

```text
top-left     90233b2c7bb39f88b176b33f831f2e5aa89862bbdc62c90a88bd76931c3df59d
bottom-left  02d9f0421548b0f57a3df572d521adccd4869fde1ff8b41866529a8f89ed3fec
bottom-right 1f406081cb0cb7777d514318ffbc526b74735aa974b451d15675ed24a508820f
top-right    c153969a326303c63777143477299284c4bfbdb6f49281d09897b510595c0528
```

64×96 object 合成圖偵測為 `top-right`，旋轉角 0，尺寸 **64×96 → 64×96**，像素前後
完全相同。process 與入庫閘預設對非左上 object 印警告但退出 0；
`--object-light-policy ignore` 可關閉警告，沒有 `fail` 模式，也沒有訂入庫門檻。

## 數字逐項偵測力自查

| 輸出 | 壞掉時會不會變 | 內建證據／如實定位 |
|---|---|---|
| 跨行程是否相同 | 會 | `set(values)` 後兩 seed 分歧 |
| terrain 四向是否相同 | 會 | 跳過旋轉後 1 種雜湊變 4 種 |
| object 朝向保留 | 會 | 四張都做光源步驟前後逐位元比對 |
| 光源方向／角度 | 會，但不能單看 | 方向必須涵蓋四象限；terrain 角度固定，object 全 0，另以像素／雜湊佐證 |
| 色盤外像素 | 會 | 注入 1 個外色像素，**0 → 1** |
| 可見像素 4096 | 會，但只是分母 | 注入透明像素變 **4095**；不是獨立成果門檻 |
| 接縫修補後度量 | 會 | 正常 **0.0**；跳過修補 **95.625** |
| 修補前度量 95.625 | 會，但只是 fixture 前置 | 現在要求必須 > 0，不把它當管線成果 |
| 四種入庫退出碼 | 會 | 正常各為 2；逐一停用對應規則後各為 0；乾淨控制為 0 |
| 入庫訊息全文 | 不足以證明規則正確 | 只把必要片段納入驗收，全文保留作診斷 |
| 每個單一 SHA-256 值 | 不一定 | 是觀察資料；真正判準是同一／分歧關係，不再把單一值當偵測力 |

所以 `verify_acceptance.py` 原本確實有好看但不保證會動的數字：**單一 SHA 值、可見像素數、
修補前接縫值、完整錯誤文案**。這輪沒有假裝它們都是成果斷言，而是把前三者分別定位為
觀察資料、分母、fixture 前置，文案則定位為診斷；會影響通過與否的關係式都有故障控制。
