## 交付內容

全部工具、測試、佔位資料與操作文件都在 `tools/art/`。沒有真素材，也沒有定案專案色盤；
`placeholder_palette.json` 明確標示僅供測試，由每個 RGB 色頻依序取 0、85、170、255 的
笛卡兒積公式確定性生成，共 64 色。

六步實作如下：

1. **裁切對齊**：既有 alpha 或指定背景色去背，alpha 硬化為 0/255，裁可見 bbox；地形填滿
   目標格線，物件等比例縮小置中。合成輸入由 20×10 對齊為 64×64，可見 bbox =
   `(27, 29, 37, 35)`。
2. **色盤量化**：固定 4×4 Bayer 矩陣的 ordered dither，加整數偏移後依色盤原始順序選最近
   色；沒有誤差擴散。色偏合成圖改變 4096/4096 像素。
3. **光源正規化**：以整數亮度的水平／垂直梯度總和判斷四象限，旋轉至左上；無有效梯度
   不旋轉。非正方形圖旋轉後等比例縮回原畫布，維持 64×96 等指定尺寸。
4. **輪廓統一**：物件 alpha 內緣依固定線寬改為色盤第一色；地形邊緣以最近內部色移除
   輪廓色。16×16 物件合成案例改變 32 像素。
5. **邊界處理**：地形相對邊成對取平均再選色盤最近色，兩邊寫入同值；接縫度量是相對四邊
   RGBA 平均絕對差。
6. **命名歸位**：驗證 def id 後以點換斜線並加 `.png`；`terrain.grassland` 對應
   `terrain/grassland.png`（位於呼叫端給定的 asset root 下）。

入庫閘讀取 def manifest，逐張檢查相對路徑、尺寸、可見像素的色盤外比例，以及半透明 alpha
與透明 RGB 污染；任一違規即退出 2。

## 效果判定與限制（如實回報）

合成測試支持第 2、3 步是主力：色偏圖量化改變全數像素，方向光旋轉改變 75% 像素，且四向
確實拉成相同位元輸出。**效果最不明顯的是第 4 步**：刻意畫粗輪廓時能機械化改掉 32 個邊緣
像素，但正常全滿地形或原本已一致的物件幾乎沒有可見差異；第 6 步本來就只有組織效果。

另有兩個不能用合成驗收掩蓋的限制：目前沒有真素材，故不能宣稱人眼風格已一致；而第 3 步
旋轉的是整個主體，不只光影，對有朝向語意的角色／建築可能是過強處理，64×96 在 90° 旋轉
時還會縮小後置中。工具保持確定且尺寸正確，但這些圖仍必須經接觸表與人工檢視，不能只靠
本輪綠燈入庫。
