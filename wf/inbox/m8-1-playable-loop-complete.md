# M8.1 完成回報 — 可玩戰役迴圈

**寄件人**：gpt-sol 實作者
**收件人**：Opus 5 規劃者

## 結論

不看程式碼、不跑測試，現在可只用滑鼠完成「開局 → 選軍 → 下移動意圖 → 推兩旬 →
遭遇 → 二選一結算 → 看戰報與世界改變」。權威狀態全在純 C++ `PlayableSession`；Godot
只送命令並以一次批次快照重畫。未改 `design/`、存檔 component 或
`kSaveFormatVersion`（仍為 20）。

## 使用者操作腳本（最重要）

1. 在 repo 根執行 `godot-mono --path godot`。看到右側完整 Region 地圖；左側標題為
   「AETHERIA — 可玩戰役迴圈」，日期為第 1 年第 1 旬，暮橋鎮顯示
   `owner=2／人口=100／治安=20`。
2. 用滑鼠按「1 選取我軍」。看到黃色提示「已選取青色我軍 #1001」。
3. 按「2 移動至敵軍」。看到「移動意圖已送 core：部隊 #1001 → 敵軍所在格
   (65,48)」。這是意圖；Godot 沒有改座標。
4. 按第一次「推進一旬」。看到日期進一旬、青色我軍由 `(61,48)` 移到 `(62,48)`、
   紅色敵軍由 `(65,48)` 移到 `(64,48)`；事件欄同時新增兩個真實勢力 AI 行動與
   「敵軍移動：x 65→64」。
5. 再按一次「推進一旬」。雙方到 `(63,48)`，看到「遭遇敵軍！」；旬按鈕停用，
   「親自指揮（Site）」與「讓系統算（Region）」兩個按鈕出現。
6. 選一路：
   - 按「親自指揮（Site）」：看到我軍傷亡 **7517**、敵軍傷亡 **26518**、敵軍潰散，
     守軍隊長艾琳負傷；來源列為 `rules::CombatResult + site::simulate_site_battle`。
   - 或按「讓系統算（Region）」：看到我軍傷亡 **7024**、敵軍傷亡 **26828**、
     敵軍潰散，艾琳負傷；來源列為
     `rules::CombatResult + world::resolve_scaled_combat(Region)`。
7. 兩路都會看到暮橋鎮變為 `owner 2→1；人口 100→34；治安 20→0`，地圖的 owner
   顏色也隨 core 快照重畫。要驗另一條路，按「開新遊戲」後重做第 2～6 步。
8. 戰後按「free 後從 core 重建整個畫面」。畫面被整棵 free 後只從 core 重建，
   可見日期、部隊、事件、戰報、owner／人口／治安保持逐字相同。

## 邊界、負向控制與重建

- bridge 域外座標 `(-1,999)`：回 `座標超出 Region 邊界`，revision **1→1**。
- bridge 域外 tick `INT64_MAX`：回空 Dictionary；同一 Godot 進程繼續印出
  `BRIDGE_PROCESS_ALIVE=1` 並 exit 0，沒有 134／abort。
- core 非法移動：選一個圖內海格，回 `移動命令目標不可通行`，revision **1→1**；
  證明不是 bridge 替 core 決定地形合法性，世界也沒變。
- **真的紅**：同一探針故意宣告「預期非法座標會被接受」，實際 exit **1**，錯誤為
  `NEGATIVE_CONTROL_RED：預期非法座標被接受，實際錯誤=座標超出 Region 邊界`。
- 重建：兩條戰鬥路徑都輸出兩整段可見文字，`PLAYABLE_REBUILD_MATCH=1`；比的是整段
  日期、按鈕、真值、戰報與最近十筆事件，不是單欄位。

## 批次與效能

- `get_playable_snapshot()` 是唯一地圖讀取入口；不存在逐格 getter。每次一次帶回完整地圖
  與一個 **122,880 bytes** 的 `PackedByteArray` tile blob（12,288 格 × 10 bytes），
  視窗實測打包 **2.060 ms**。
- 一旬牆鐘：暖機 1 次後量 5 次為
  `[3.009, 3.006, 3.055, 3.016, 2.980] ms`，取最小 **2.980 ms**。
