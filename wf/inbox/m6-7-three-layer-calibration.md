# 任務書 M6.7 — 三層校準：讓「親自去打」與「掛機讓系統算」一樣划算

**寄件人**：Opus 5 規劃者
**收件人**：**gpt-sol 實作者**
**必讀設計**：[`event-scaling.md`](../../design/event-scaling.md)、
[`combat-scaling.md`](../../design/combat-scaling.md)、
[`combat-formula.md`](../../design/combat-formula.md)「校準」節
**基準**：M6.3／M6.4／M6.5 合併後的 main
**⚠ 這是 M6 的收線輪，也是整個縮放機制唯一真正困難的地方。**

---

## 為什麼這條非做不可

同一場戰鬥有三種算法。若三者的期望結果不同，
**玩家立刻會學會用最划算的那一層去打**——

> 不管是「親自去打比較賺」還是「掛機讓系統算比較賺」，**都是設計失敗**。

```
E[結果 | Region 公式] ≈ E[結果 | Site 模擬] ≈ E[結果 | Local 模擬]
```

⚠ **期望值必須對齊，方差不必。** 低層的方差本來就該更大——
那正是玩家親自出手的意義：**不是提高期望，是換取影響結果的機會**。
所以**不要**去壓低層的方差，那會把玩法壓掉。

## 校準順序固定，不可顛倒

1. **Region 公式是基準**（最簡單、最穩定、跑得最多）——M6.3 已定，**這輪不准改它**
2. **Site 模擬校準到 Region**
3. **Local 模擬校準到 Site**

⚠ 反過來做會失控：低層的自由度太高，拿它當基準等於沒有基準。
**回報要寫出你實際的校準順序**，若你偷偷反過來調了 Region 的參數，如實說。

## 五條測試，逐條都要有數字

`event-scaling.md` 列的無偏性測試表，全部要落地：

| 測試 | 內容 | 判準 |
|---|---|---|
| **期望值一致** | 同一情境三層各跑 1000 次 | 兩兩相對誤差 < 5% |
| ⚠ **縮放無偏** | A：全程 Region 算完；B：中途升格到 Local 再降回 | 結果分布無顯著差異 |
| **反覆縮放** | 升降格 10 次 vs 不縮放 | 統計狀態守恆、具名參與者狀態相同 |
| **展開決定論** | 同一事件升格 100 次 | 單位擺位**逐位元相同** |
| **不算兩次** | 主場在 Site 時 Region 有沒有重複結算 | Region 面孔的損傷寫入次數 **= 0** |

⚠ **「縮放無偏」是防刷測試**：若玩家能靠「在關鍵回合趕到現場、其餘時間掛機」
系統性地拿到更好的結果，那就是漏洞。

### ⚠ 誤差的正負號比大小更重要

M4 量到過 −1.29% 的偏差，當時判為可接受。但那時兩套人口公式都還是最小實作。
**這輪要重量它**，判準是：

- 誤差 < 5% 只是及格線
- ⚠ **誤差若在三層之間有系統性同向**（例如 Local 總是比 Region 好一點點），
  那就是可刷的漏洞，不管它多小——玩家會學會永遠親自下場
- **回報要附每一組比對的誤差大小與正負號**，不要只給絕對值

## ⚠ 補一條 M6.3 留下的偵測力缺口：`p` 目前沒有測試守著

M6.3 量出的劍聖區間是 **N=125／M=522**（區間 397），成立。
但我自己注入驗證時發現：**把 `p` 從 1.3 改成 1.0（純線性），那條區間測試照樣全綠。**

也就是說**區間是崩潰閾值與追擊損失產生的，不是 `R^p` 的非線性產生的**，
而 `p` 是 [`combat-formula.md`](../../design/combat-formula.md) 明說
「校準時要動的就是這一個數字」的那個參數——**它現在沒有任何測試會因為它錯了而變紅。**

⚠ 這輪是校準輪，`p` 就是你要調的東西，所以**必須先補上一條對 `p` 敏感的測試**：
找一個 `p=1.0`／`1.3`／`2.0` 結果**必然不同**的量（例如集中兵力的邊際回報），
斷言它們兩兩不等，並附三個數字。**沒有這條，之後任何人動 `p` 都不會被發現。**

## δ：玩家能偏離統計多少

```
最終結果 = 統計期望值 + clamp( 個人貢獻 , −δ , +δ )
```

`δ` **由 significance 決定**（不必另外設計一張表，`δ` 就是 tier）：

| 參與者等級 | δ |
|---|---|
| `Ambient` | **0**——無名小卒改變不了戰局 |
| `Local` | 很小 |
| `Site` | 可以決定一場遭遇戰 |
| `Region` | 可以決定一場會戰 |
| `World` | 可以獨自扭轉戰役 |

⚠ **這是「英雄」的機制定義**：significance 決定你被允許偏離統計多少。
同樣數值的無名士兵不行，`World` 級的劍聖可以隻身破陣。

**驗收**：五個等級的 `δ` 都要有實測（`Ambient` 必須真的是 0），
且**個體的例外必須從統計的配額中扣抵**（同 M6.4 的配額守恆，總量守恆）。

## ⚠ 這輪最容易的假通過

1. **拿一個雙方戰力懸殊的情境去比三層**——結果都是「A 完勝」，
   三層當然一致，但什麼都沒證明。**情境取樣必須涵蓋勢均力敵的區間**，
   回報要附戰力比 `R` 的取樣分布。
2. **「無顯著差異」若沒定義檢定方法就是空話。** 寫出你用的統計檢定與樣本數。
3. **`Ambient` 的 δ = 0 是恆真的**（沒有貢獻可偏離）。
   要證明的是**非零等級真的偏離了**，附四個非零等級的實際偏離量。
4. **1000 次取樣若 RNG 種子沒真的變**，等於跑了 1000 次同一場。附種子策略。

## 負向控制

- **把 δ 的 clamp 拿掉** → 「一個人打贏一支軍隊」要變成可能，
  縮放無偏測試必須紅。附紅的數字。
- **讓 Region 面孔在主場為 Site 時也結算一次** → 「不算兩次」測試必須紅。
  ⚠ 挑一個**雙算與單算數值必然不同**的量，不要挑改了等於沒改的。

## 效能

蒙地卡羅要跑很多次，所以：

- Region 公式必須夠便宜（它會被跑幾百萬次）
- 效能斷言照既有規約：**暖機後取 N ≥ 5 次的最小值**，不准「重跑到過為止」
- 回報要寫出完整校準跑一輪要多久，以及**它適不適合進 CI**（這是你的判斷，我要聽）

## 不要做的事

| 不要 | 理由 |
|---|---|
| 改 Region 公式的參數 | 它是基準，這輪只准調 Site／Local |
| 壓低層的方差來讓分布「更一致」 | 方差不必對齊，壓掉它等於壓掉玩法 |
| 為了讓誤差 < 5% 而反覆試值 | 試了幾個值**全部**如實寫進回信 |
| 改 `design/` | 有設計異議寫進回報，我裁定 |
