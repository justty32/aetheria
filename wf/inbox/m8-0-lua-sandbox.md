## 這輪是 M8 主線劇情的前置

`narrative.md` 說主線走 L-Script 層。但 `core/script/` **還不存在**，
所以主線現在無處可寫。這輪把它建起來。

**選型已定：Lua 5.4 + sol2**（vcpkg 現成、header-only；使用者熟悉 ToME4 的 Lua 生態）。
⚠ **不要重新評估選型**，直接做。

## ⚠ 六條決定論鐵律：這輪的全部重點

core 的決定論保證**必須延伸到腳本**，否則整套回歸測試失效。
六條每一條都要有**獨立的測試**，而且每一條都要有**負向控制**：

| # | 鐵律 | 負向控制長什麼樣 |
|---|---|---|
| 1 | 沙箱 `_ENV` 裡**沒有** `os.time`／`os.clock`／`os.date`／`io`／`math.random`／`math.randomseed`／`collectgarbage` | 把其中一個放回去 → 沙箱測試要紅 |
| 2 | **只用注入的 RNG**：`ctx.rng:int(a,b)`，背後是 core 的 `mt19937_64` | 讓腳本拿得到別的亂數源 → 要紅 |
| 3 | **table 迭代順序**：提供 `ordered_pairs`（依 key 排序），lint 禁止在影響狀態的路徑用 `pairs` | 把 `ordered_pairs` 換成 `pairs` → 決定性測試要紅 |
| 4 | **腳本不持有跨回合狀態**；⚠ **存檔不序列化 Lua state** | 讓腳本存住跨回合變數 → 要紅 |
| 5 | **執行點固定**：只在回合流水線的固定階段被呼叫，沒有 coroutine 跨回合、沒有非同步 | 加一個非同步掛勾 → 要紅 |
| 6 | **錯誤不吞**：腳本拋錯要**中止該次結算並回報**，不能靜靜跳過 | 改成靜默跳過 → 要紅 |

⚠ **第 4 條同時解決存檔相容性與決定論兩個問題**——別為了方便而序列化 Lua state。
⚠ **第 6 條最容易被「順手」寫錯**：靜默失敗會讓兩次執行結果不同，
而且它**不會有任何測試變紅**，除非你專門為它寫一個。

## `ctx` 是受限視圖，不是裸指標

> 腳本拿不到 `RegionTiles` 的裸指標，也不能直接改 `owner`——
> 只能呼叫 `ctx:set_owner(...)`，由 C++ 端驗證合法性並記錄成事件。

⚠ **用型別擋，不要用約定擋。** M6.2 的 `FactionView` 已經示範過：
給那個 target 只帶特定 include path，讓「直接讀真值」在編譯期就不存在。
**照那個做**，並用 `tests/compile_fail/` 證明繞不過去。

⚠ compile_fail 測試有個假通過：**它可能因為打錯路徑而「編不過」**。
所以要同時證明**把隔離解除後它編得過**（M6.2 我驗過這條，照做）。

## 掛勾點（先做這幾個就好）

```
事件：  condition(ctx) -> bool          effect(ctx) -> void
劇情：  on_trigger(ctx)
勝敗：  check(ctx) -> Outcome
```

其餘（技能、建築、AI、生成後修飾）**這輪不做**，留介面位置即可。
理由：先證明沙箱與決定論是對的，再擴掛勾點。

## 效能：腳本只跑在低頻路徑

高頻路徑（尋路、地形生成、逐格模擬、全圖 stencil）**一律留在 C++**。

⚠ **驗收要有一條防線**：量出每回合的腳本呼叫次數，
若某個掛勾被呼叫上萬次，**那是設計錯了**，如實回報。
效能斷言照既有規約：**暖機後 N ≥ 5 取最小值**。

## 熱重載

- 重載 `scripts/` 後**重建 Lua state，但不動世界狀態**
- 重載後跑一次驗證：現存物件的 id 是否仍在新表中；**缺 id 就報錯並拒絕重載**
- ⚠ **拒絕重載**不是「載入一半」。附一個「缺 id 時世界狀態完全沒被動過」的證據

## 驗收

| 判準 | 怎麼量 |
|---|---|
| 六條鐵律 | 六條各一個測試 + **六次獨立負向控制**，各附紅的訊息 |
| 沙箱真的空 | 列出 `_ENV` 的完整 key 清單，附出來 |
| `ctx` 型別隔離 | compile_fail 編不過**且**解除隔離後編得過 |
| 決定性 | 同 seed 同腳本跑兩次，世界雜湊相同 |
| 存檔不含 Lua state | 存檔位元流裡 `grep` 不到腳本狀態，附證據 |
| 熱重載 | 缺 id 時拒絕且世界狀態未變 |
| 呼叫次數 | 每回合各掛勾的實際呼叫次數 |
| 效能 | N≥5 取最小 |

⚠ **「六條都過」若只用一個測試涵蓋，不算。** 六條各自失效時要各自有東西變紅——
這與 M6.6c 逐欄位注入是同一個要求（漏掉一條，整組一起改照樣會變）。

## 版本號歸屬

⚠ **這輪不准動 `kSaveFormatVersion`。** 鐵律第 4 條就是「存檔不序列化 Lua state」，
所以正確的實作**不需要**動版本號。若你發現非動不可，那多半表示第 4 條被違反了——
寫 `.codex-inbox/m8-0.ask` 說明，採用「不動版本號」的假設繼續做完。
