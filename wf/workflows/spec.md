# spec — 把方向寫成可檢驗的規則

← [工作流派發](../WORKFLOWS.md)

使用者要求規劃規格、比較規則或展開 roadmap 時使用。產物是設計方案，不是實作任務書，也不授權改程式。

## 流程與完成條件

1. 讀對應 roadmap、調查基線與既有設計；不把參考作品當成本案裁定。
2. 寫明 Done when、範圍與不包含事項；區分既定約束、草案規則、待裁定選項。
3. 依子題寫入 `design/` 單檔；列資料語意、唯一寫入者、時間、操作、中斷、AI、保存與驗收。遵守每檔 8 KB，不先定未必需要的 API。
4. 用具體正反情境推演；衝突指回原文，不暗改舊裁定。數值可參數化，但條件和失敗出口不能省略。
5. 維護設計入口／索引與原 roadmap 的下一層連結；核對大小、連結與差異。未完成項記進度，只有真正需使用者處理的阻塞才記待使用者。
6. 使用者裁定後才能標為定案；另獲實作指示才進 plan／任務書。文件完整不等於執行驗證通過。

## 目前規格

- [三層活世界 spec](../../design/spec/README.md)：S0–S11 全批功能規格草案、整合推演、待裁定與驗證矩陣；不是實作完成。
