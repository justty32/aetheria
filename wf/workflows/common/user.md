# user — 使用者偏好與確認邊界

← [common/README](README.md)

agent 不用重猜的事。always-on 鐵律在 [AGENTS.md](../../../AGENTS.md)，這裡是**這位使用者**的偏好——改了改這裡，不改鐵律。

**何時用**：使用者說了偏好、講定了確認邊界（哪些事可以直接做、哪些一定先問）、或講定分支慣例／時區／語言時，記到這裡。
**何時不用**：一次性的小事不必記（例如「這次先不要跑測試」）——那是當下的指示，不是長期偏好；長期知識歸屬層的原則見 [STRUCTURE](../../STRUCTURE.md)。

## Done when

對應的那一列已更新（或新開一列），沒有留下與新偏好矛盾的舊值。

| 項目 | 設定 |
|------|------|
| 語言 | 回覆與文件一律繁體中文；程式碼註解英文 |
| 分支慣例 | 直接 commit `main`；並行派工用 `git worktree` 分支，併回 main 由波管家做 |
| 直接做、不用問 | 改 `wf/` 與 `design/` 文件、加測試、跑唯讀指令與 ctest、寫任務書草稿、歸檔已辦信件 |
| 一定先問 | push、刪檔、改存檔版本號政策、動 `design/` 已裁定的原則、解除使用者親口擱置的項目（如 observer mark）、開新里程碑（里程碑順序是設計決策，歸規劃者／使用者）|
| 回覆風格 | 通用風格見 [reply-style.md](reply-style.md)；使用者問「要不要」時附**可執行判準**（門檻數字）與後果，讓他能改數字；上呈的決策摘要 ≤ 30 行、不貼原文（[TEAM](../team-model/TEAM.md)）|
| 成本前提 | 量大的工作全給 codex（訂閱吃到飽），Claude 只留裁定、驗收、對使用者（2026-08-27 裁定，見 [TEAM](../team-model/TEAM.md)）|
| 時區 | Asia/Taipei |

領域詞彙常猜錯 → 開 `glossary.md`（見 [common/README](README.md)）；目前遊戲術語以 `design/` 各領域文件為準。
