# 活世界系統：小層生活

[本層入口](README.md)｜← [三層地圖藍圖](../roadmap-three-layers.md)｜原則：[design/principles.md](../../../../../design/principles.md)

## 目標

讓 Local 不只在打仗時有用：人會吃、睡、受傷、工作、使用住所與工具，也會因天候、火、黑暗、污染或資源短缺改變行動。生活模擬必須服務「人物故事、地方生產、冒險代價」三件事，而不是堆滿要玩家逐項照顧的量表。全案仍是單一秒制時鐘上的回合制；探索與戰鬥沿用既有 stride，不搬 RimWorld 即時 tick 或 Elin 協程。

## 三層責任與權威

| 三層地圖 | 責任與權威 |
|---|---|
| Region | 人口 Cohort、糧食與原料總帳、饑荒／疫病／季節等大局狀態。未展開地方的長期生活結果由此層代表。 |
| Site | 聚落庫存、產業配額、街廓用途、住房容量、公共衛生、工坊與服務。回答「這座城養得起多少人、缺什麼」，不排每個人的搬運路線。 |
| Local | 具名人物與當場 NPC 的工作步驟、預約、房間和環境互動，是眼前那份詳算的主場層；它不是 AI 或生活模組任意寫狀態的授權。 |

中層聚落經營決定要蓋什麼、投入多少人力與物資、期望產多少；小層決定具體誰在何處完成一筆工作、為何中斷、是否受傷與留下什麼持久改變。小層實產必須抵扣中層配額，不能「中層已產一次，小層再搬一次又產一次」。

健康、物品、關係、力量等跨系統狀態各由所屬領域規則唯一寫入；生活流程只能提交命令或效果請求，再接收結果，不為同一人物另存一份副本。

## 狀態、輸入、輸出與時序

1. 回合開始由 Site 投影場所邊界、可用庫存、工作單、人物名額與環境條件；Local 只拿本場需要的快照與持久物件。
2. 玩家與人物以同一命令格式提出移動、取物、製作、休息、治療、用餐、修理或互動意圖。命令先驗合法性，再排成可中斷的工作步驟。
3. 每個 Local 回合依固定順序處理：環境危害與需求累積 → 失能／危急覆寫 → 工作選擇 → 預約 → 移動與執行 → 消耗／產物 → 健康與關係事件。戰鬥 stride 變短時，各速率仍按實際 `Tick` 換算，不按回合數增加。
4. 完成、取消或中斷都產生帶來源的結果：耗時、消耗、產物、傷病、設施損毀、人物記憶與事件進度。
5. 回合尾端才把結構變更與歸約提交 Site；Site 再按自己的合法時點提交 Region。結果只能套用一次。
6. 離場時，具名人物、玩家改造、重要物品、未完成工作與因果旗標進持久層；姿勢、臨時路徑、普通雜物等易失狀態丟棄。未展開期間由 Site／Region 粗算，重返時只補持久物件，不逐分鐘重播。

## 規則及跨系統因果

- **需求是壓力，不是待辦清單。**飢餓、疲勞、安全、舒適可先收斂成少數軸；超過門檻才改工作評分，危急才強制求生。性格、文化、種族與健康狀態改權重，不另開特例流程。
- **健康是部位／狀態的合成結果。**傷口、疾病、疼痛、失血、疲勞影響工作、移動與戰鬥；治療需要時間、技能、場所與物資。死亡事實可在合法結算階段立即通知上層，但事件結構升降與實體銷毀仍只在回合尾端執行。
- **工作分成選擇與執行。**工作單說明目標、材料、工具、場所、技能、成果；執行拆成預約、前往、取用、加工、交付。預約避免兩人搶同一床、材料或工作臺；失去條件時可暫停、換人、降級或取消，不能永久卡死。
- **居住提供能力，不只加心情。**床位、遮蔽、溫度、光照、衛生、儲藏與私密性影響恢復、疾病、關係和工作效率。房間由牆與門形成的空間查詢得到；Site 只保存容量與品質歸約。
- **製作必須守恆。**配方是資料：輸入物、工具／工坊、工時、技能門檻、品質與副產物。品質可受製作者、材料與環境影響，產物帶來源；拆解與修理同樣記錄物質流。
- **環境能觸發連鎖。**雨雪影響通行與體溫，火與煙傷人並損壞建築，黑暗影響視野與工作，腐敗或污染引發疾病；嚴重到地方尺度時升格成 Site 事件，再改住房、人口、庫存與勢力需求。
- **人物經歷會回到社會。**完成工作增加技能與名聲；共同勞動、救治、搶奪資源或居住擁擠可改關係；匠人死亡會降低 Site 產能，饑荒則由 Region 配額約束個體命運。

## 既有／新增建議

**沿用既有：**Local 的牆門邊屬性、單格 occupant、稀疏物品、持久／程序／易失三層資料；高層權威、低層展開；事件升降格、observer LOD、離場 digest 與閉式補算；單一秒制時鐘及回合尾端結構變更。

**建議新增：**拆得走的 `Needs`、`Health`、`Work`、`Reservation`、`Inventory/Recipe`、`RoomEnvironment` 模組；Site 級工作單與產出配額；帶來源的一次性歸約收據；人物可解釋的「目前需求／為何做這件事／缺少什麼」快照。型別、配方、需求與環境效果都走 def，不擴大 `PlayableSession`。

## 驗收場景和待細化

**驗收場景：**一座缺糧小鎮下達烘焙工作；具名角色取得材料、預約爐具、因受傷中斷，另一人接手完成。玩家離開兩旬後重返：Region 糧帳、Site 產出、人物傷勢、已耗材料與成品只各算一次；同 seed、同命令結果一致。另一場火災會堵路、傷人、燒毀持久建物並升格成聚落事件。

**待細化：**需求軸與門檻、健康部位粒度、工作搶占與交接、房間重算成本、配方品質、火／溫度／疾病模型、粗算與完整模擬的無偏容許差、UI 顯示多少需求，以及哪些普通 NPC 值得升為具名持久人物。
