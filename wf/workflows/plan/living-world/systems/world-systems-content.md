## 目標

做一個能長期運轉、可追查、可加入內容的世界模擬器：世界自行演變、勢力行軍興衰，玩家可下沉生活。
**所有玩法真相只在 C++ core；Godot 只送意圖、取投影。**

## 三層責任與權威

| 層 | 權威狀態 | 做什麼 | 不做什麼 |
|---|---|---|---|
| Region | 世界、文明、勢力、領土、軍團、外交、經濟、年代 | 每旬推進整個世界；無人觀看也運轉 | 不保存每個人的走路格 |
| Site | 城鎮、聚落、戰場、組織、隊伍、產業與局部社會 | 每時推工作、建造、交易、戰術與群體事件 | 不另算 Region 已結算的戰爭 |
| Local | 個人、物品、地形、需求、技能、對話、逐格戰鬥 | 依探索／戰鬥採既定可變步長 | 不直接改遠方勢力；結果向上歸約 |

同一件事只有一個「主場層」可寫，其餘層只讀投影；升降層走既有 `project/reduce`，不得重算。

## 資料定義、腳本與內容包

### 定義分四類

1. **名詞 def**：地形、文化、信仰、勢力、單位、建築、物品、技能、工作、事件、任務、對話、人物；
   持久／內容引用存字串 id；runtime 可用強型別下標，enum 只留機制狀態。
2. **條件**：時間、地點、關係、知識、資源、標記、事件階段等可組合 predicate；讀狀態，不改狀態。
3. **效果**：生成／移動實體、改資源、授予技能、發事件等具名原子操作；在各自合法階段落地，
   只有 def／zone 結構追加強制延至回合尾命令緩衝。
4. **配方／圖**：AI goal→job→step、事件節點、任務圖、生成 pipeline。表決定組合，C++ 實作原子語意。

腳本只負責特殊編排：讀唯讀 Context、回傳條件或效果請求，不能摸 registry、檔案、Godot；亂數只准
Context 提供的可重放 RNG，禁用原生／全域亂數。
通用機制先資料化；無法表達才增 Lua hook。腳本、def 與素材同屬內容包。

### 內容包與世界規則自帶

每包有 `id/version/依賴/衝突/載入順序/def、script、asset、locale`。依賴須無環；缺包、版本不合、
id 衝突、未解析引用在進世界前 fail-fast。建世界時把包清單、raws、腳本與規則複製進槽且不再改寫。
素材可外置，但世界須存內容 hash；缺素材可降級顯示、不得改玩法結果。

## 狀態、輸入、輸出與時序

一次最小提交固定為：

1. 收玩家／AI／內容注入輸入，先正規化成帶 stable id 的 command。
2. 以當前 tick 與權威狀態驗證；拒絕也要留下有原因的 outcome，不能只記原始輸入。
3. **journal-first** 寫日誌；def 批次先做影子 Ruleset 驗證。
4. 一般效果在具名合法階段套用；def／zone 結構追加排回合尾。跨 zone 寫入只進信箱／命令緩衝。
5. 各層依主場權威推進；低層結果向上歸約，高層事件確定性展開到被觀察區。
6. 存 zone／manifest／角色檔，最後前推 commit marker；發布不可變 snapshot＋事件給 Godot／工具。

跨系統只走 stable id、命令、事件與查詢：如 Local 擊殺人物→Site 士氣→Region 戰局；
不得直接拿別系統容器或裸指標。

## 開局生成與進行中加入

- **開局**：seed＋包→驗依賴→凍結 raws／scripts→生成地理、文明、勢力史、聚落、人物與物品→
  一致性檢查→寫 genesis 與角色起點。
- **加入 def**：沿 M10 通道在回合尾端**只追加**，影子驗證後生效。script／內容包注入是 M11 新輪，
  依相同交易原則設計，不能假稱 M10 已涵蓋。
- **加入實體**：勢力有 origin，人物有位置，物品有持有者或 zone；不能有孤兒。
- **加入舊世界**：新內容不追溯改寫過去，只從加入 tick 起參與；如需補生成，必是有 id、有日誌的事件。
- **修改／刪除**：現行政策不變——禁止。未來若需要，另立「新世界分支＋遷移／轉換事件」候選，
  不在原世界原地覆寫，也不偷改 M10。

## 對現有 M10 逐項保留

| M10 | 本規劃怎麼承接 |
|---|---|
| 0a 內容 enum 守門 | 新 def 遵守；待清償只減不增 |
| 0b 關係斷言 | 不讓 golden hash 綁死內容 |
| 0c 玩家可存讀 | 成為世界 session 的唯一存讀入口 |
| 1 世界自帶 raws | 原範圍不變；未來另加內容包清單、腳本、世界規則快照 |
| 2 多角色分檔 | 世界共享；每角色只存控制／視角／私人知識與指向世界的 stable ref |
| 3a 日誌與協調器 | 唯一提交線；補拒絕 outcome、多角色選取／匯入 |
| 3b 全 def 注入 | 原全 def 範圍不變：只追加、回合尾、影子驗證；不含 script／包 |
| 4 勢力增長 | 保留 pioneer，分裂／小部族成長在人物與聚落齊備後加入 |
| 5 兵種／建築／AI 資料化 | 延伸為三層資料表，不改既有校準 |
| 6 人物／文化／物品 | 成為生活、關係、inventory 的首批模型 |
| 7 外部注入 | `inject/` 仍是首個入口；往後 UI 只是同一 command 的作者 |
| 8 全鏈驗收 | 擴成內容包、三層、多角色矩陣，不取代原六條 |

M10.3a 已知只證明單角色命令線；多角色重放、拒絕命令、截斷尾筆仍是前置缺口，不能繞過。

## 來源與界線

- ToME4 可借 zone 內容池、技能／物品／任務積木；不能借其大地圖定址。
- DF 指向世界自帶規則與歷史；TES／騎砍／Civ5 指向個人、軍團、文明體驗，均非 API 證據。
- aetheria 仍以 `ZoneKey`、事件主場、observer、純 C++ core 為權威。

## 驗收

1. 同 seed＋同內容包＋同完整日誌，冷重放世界 hash、三層摘要、人物與角色檔完全一致。
2. 世界離開玩家後跑 100 旬：勢力、聚落、人物與事件有因果歷史，無需載入所有 Local。
3. 開局與運行中各加入一包，涵蓋 def／script／勢力／人物／物品；成功全生效，壞引用整批零生效。
4. 同世界兩角色輪流遊玩，共享世界後果、私人知識不串；刪角色不傷世界。
5. Region 戰爭下沉到 Site／Local 再上提，總資源、傷亡、人物命運只結算一次且在容差內一致。
6. 改安裝目錄內容後舊世界結果不變；篡改 raws、script、日誌或包身分會 fail-fast。

## 待細化

- 內容包版本相容語意、腳本 bytecode／原文保存方式、允許的 Lua API。
- 開局歷史要模擬多久、何時只留摘要；注入包的補生成預算。
- 「修改模式」若立案，採另存分支、轉換事件或完整遷移工具；現階段皆不啟用。
