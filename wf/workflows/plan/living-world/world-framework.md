# 活世界：整體框架

## 世界要長成什麼

**使用者的目標是結合上古卷軸、騎馬與砍殺、文明 5、矮人要塞的奇幻世界模擬器，從大塊到細節都遵循三層地圖。** 這四作在此代表使用者指定的體驗坐標，本次不宣稱已逐一解析它們的原始系統。

世界先存在，人物在其中生活，玩家是能介入的人。玩家可以長途旅行、投身組織、帶領部隊、經營地方、探索古蹟、追求力量，也可以把事務交給別人。文明、政治、工作、資源、戰爭、生死與傳聞持續互相作用；任何一條人工主線都不能承擔整個世界的生命。

「活」有六條具體意思：人和組織有自己的需要與目標；行動花費時間與資源；結果會改變別人的處境；遠方仍然演化；回到舊地會遇到可解釋的改變；玩家可以查到關鍵原因，卻不自動知道全世界的祕密。

## 三層是同一件事的三種解析度

| 層 | 玩家看到的世界 | 模擬重點 | 主要架構參考 |
|---|---|---|---|
| 大地圖 Region | 地理、文明、國家、城市群、軍隊、交通與歷史 | 集體數量、資源流、政治關係、長期決策 | Endless Legend |
| 中地圖 Site | 一個地方的城區、設施、部隊、戰場與路口 | 平時經營調度，戰時方陣指揮 | 原案城建＋Total War 式回合制戰術 |
| 小地圖 Local | 街屋、房間、人物、工作、物品、地城 | 個人行動、生活、技能、局部互動 | ToME4／RimWorld／Elin |

地圖尺度、時間步長、網格與地址沿用 [outline](../../../../design/outline.md)；三層不是三款遊戲的資料各存一份。`WorldGraph` 連接大地圖，不新增第四種玩法解析度。政治、經濟、人物等「系統分層」也不能冒充地圖層。

## 共同骨架

| 共用概念 | 負責回答 | 不應混在一起的東西 |
|---|---|---|
| 內容定義 | 這世界有哪些種類與規則？ | 兵種與本局某一隊兵；文化與某一個國家 |
| 世界身分 | 這是誰、哪個地方、哪件事？ | 人物、職位、勢力、所有權各有身分，不能綁成同一 ID |
| 資源與狀態 | 現在有什麼、誰保管、已承諾多少？ | 庫存、流量、容量、預約不能用同一數字 |
| 需要與目標 | 想得到什麼，為什麼？ | 缺糧是事實，運糧是方案，商隊是執行者 |
| 命令與工作 | 要怎麼改變世界？ | 提案、通過、進行、完成、拒絕、取消分開記 |
| 效果與事件 | 真正改了什麼？誰能知道？ | 世界已發生的事、角色看見的事、傳聞與猜測分開 |
| 時間與歷史 | 何時生效、過了多久、能否續接？ | 個人幾步行動和世界一旬共享時鐘，不能各加一次時間 |

上述是責任邊界，不要求用一個巨大通用類別實現。跨系統共享窄介面；同層互動經共同上層或既有中介。派遣、建造、研究、訓練、治療、探索、談判都可使用共同的長期工作狀態，但各自的專屬規則分模組。

## 讓系統互相影響

設計要能回答完整因果鏈，不能只列孤立功能。例如：

1. **饑荒與遷徙**：乾旱減產 → 庫存與價格改變 → 商人改路／領主調糧 → 貧戶改工作或遷徙 → 治安與外交承壓。玩家可在大層調度、中層護送、小層救助同一批人；救助效果不能記三次。
2. **繼承與戰爭**：領袖死亡 → 職位與合法性改變 → 派系分裂或談判 → 軍隊與地方改 效忠 → 戰爭破壞生產 → 家庭承擔損失，形成可傳播的記憶。
3. **知識與環境**：探索遺跡取得知識 → 人物學習、組織傳承 → 新製法或法術改變生產與軍事 → 產生新的資源壓力與外交利益。不能拿到一本書就全世界瞬間解鎖。
4. **城建與守城**：城市規劃決定道路和城牆 → 中層圍城爭奪入口 → 小層修門或破壞機械 → 戰後留下損毀、重建需求與人口變化。

這些是建議的整體設計案例；具體門檻與制度留各系統細化。失敗、放棄、替代解法與無人介入都要有結果，不只設計成功分支。

## 規劃成熟的判準

跨系統推演見 [七個世界情境](world-scenarios.md)，制度取捨見 [規則選項](world-design-choices.md)。

先把框架和每個系統的責任寫清，再補跨系統情境與規則選項，最後才形成可派工規格。每條機制要有資料來源、改動權限、生效時點、離場行為、存檔要求、玩家呈現與可驗證後果。

「把研究全部放進文件」不等於規劃完善。參考中同義的能力合併；相衝的制度列選項；來源未證實的部分保留證據標記。既有 mark／獨特物件與 root 成長軸的實作擱置仍保留，完整願景可以討論其位置，不藉規劃直接啟動。
