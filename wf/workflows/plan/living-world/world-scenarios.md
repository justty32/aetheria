# 用完整世界情境檢查設計

[本層入口](README.md)｜← [世界框架](world-framework.md)｜[模擬契約](world-simulation-contracts.md)｜[權威分工](world-state-ownership.md)

## 目的

每份系統文件可以單獨說得通，但拼起來才會知道哪裡漏接。以下是未來的整合驗收要求，本次只做桌上推演；沒有執行遊戲或宣稱情境已能遊玩。案例用少數人事物方便追帳，完整世界仍按系統樹擴展。

## 一、乾旱到家庭遷徙

**起點**：上游連續乾旱，河谷糧倉有存量，山城依賴進口，一個家庭有傷者與工作承諾。

- 大層：水量改產能 → 庫存與需求改價格 → 政府配給／商人改路 → 居民決定留下或遷徙。
- 中層：倉庫、渡口與工坊承接配送，缺料工作停擺，護送隊爭奪有限運能。
- 小層：有人求職、照護、搬糧或偷竊；人物能力與關係影響選擇。
- 不介入：仍有消耗、到貨、死亡或離鄉，不等玩家進城才發生。
- 失敗分支：毀橋、商隊被劫、配給不足，分別留下貨物流向與傷亡原因。

**核對**：糧食總帳、在途貨、工作預約、家庭位置與政治反應各一份；小層拿走的糧會在上層消失。跨層補算不讓饑荒憑空痊癒。

## 二、領袖死亡到繼承戰爭

**起點**：多文化王國，有兩個合法候選人、地方領主、條約與已動員部隊。

- 小層的死亡先成為健康／人物已確認事實；政治規則按法律產生候選與分配，不由死亡動畫直接改國界。
- 大層更新職位、附庸、宣稱和命令權；政變或分裂是其後的政治過程，不必每次繼承都打仗。
- 中層出現效忠、接管工事、集結與圍城；小層可能有談判、營救、拘捕或背叛。
- 不介入：AI 也能接受繼承、談判、抗命與停戰；世界不因關鍵人物死亡失去推進者。

**核對**：國家、人物與職位 ID 分開；國庫、軍隊、附庸不能被兩個新國家各複製一份；同一死訊不重觸發繼承；私下消息不立刻全世界皆知。

## 三、城牆到親身守城

**起點**：玩家曾修建城門與外牆，攻方有補給和器械，城內有居民。

- 大層決定圍城、增援與補給；中層使用這座城實際的配置部署。
- 玩家下沉到小層修門、救人、破壞器械；未親自參與的戰區仍由中層／大層算。
- 守住、撤退、投降各有結果；戰後損毀、俘虜、流離人口、修理需求繼續存在。

**核對**：已交出兵力與戰區不重算；玩家久留小層也會在合法時點向上交結果；退出戰場不能消除傷亡。粗細結果比較用既有期望值規則，不要求玩家介入後完全同結果。

## 四、遺跡知識到社會改變

**起點**：古文明遺址、受限入口、一件文獻與具名研究者。

- 小層取得文獻需要旅行、工具、能力與風險；取走後不因重載再次出現。
- 中層的學校／神殿／工坊研究並傳授；有知識不代表已有生產設備與材料。
- 大層受新技藝、法術或教義影響，改資源需求、軍事能力與組織利益。
- 失敗分支：文獻毀損、研究者死亡、教會封禁；知識按已記錄的持有人與傳播路徑延續或失傳。

**核對**：取得、理解、可教、可用是不同狀態；不全世界瞬間解鎖；神祕力量仍有具名代價與效果來源。

## 五、工作中斷到人物經歷

**起點**：匠人接到一份工具訂單，材料有限，同一工作臺有兩人競爭。

- 中層下達工作與預算，小層預約、搬運、加工；工具壞掉或人物受傷可中斷。
- 接手、延期、取消必有材料與報酬處理，不留永久占用的工作臺。
- 大層看見產能和交貨變化；人物留下技能、信任、收入、傷病等有來源的經歷。

**核對**：AI 不自行加技能或物品；批次拆成個體有扣量，剩料歸還不重複；離場後工作可以粗算續接但不重領成果。

## 六、正在玩的世界加入新文明

**起點**：已有土地、人物、外交、兩個角色檔與完整歷史；注入包帶新文化、勢力、人物、物品。

- 先在影子資料驗依賴與引用；合法的追加在回合尾生效，舊 ID 不變。
- 大層出現有來源的開拓勢力；中小層展開它的建設、人物與文化內容；AI 真能使用新定義。
- 另一測例加入新劇情，驗 Lua 與效果的版本和保存；此為 M11／內容擴充範圍。
- 失敗分支：缺依賴、非法領地、重複 ID、壞腳本，整批拒絕並保留原因，不產生半個勢力。

**核對**：原 M10 全 def 矩陣逐項驗，不只這個示例；存讀、重放、多角色、拒絕命令與崩潰恢復分別檢查。更新全域內容不改舊世界。

## 七、長期無人觀看

**起點**：相同世界與輸入，比較玩家久留一地、頻繁換層、純大層推進三種觀察路徑。

追蹤人口結構、資源總量、國家存續、家系、交通、生態、知識、戰爭和事件。不同觀察路徑本身不能讓未介入的地方多產資源或改命；有近似誤差的項目要事前列明統計量、樣本與容差。

**核對**：重要的遠方事件按時影響外界；可延後細節才在查詢時補算；歷史、關係、AI 記錄有保存策略，記憶體不因每次看一眼就永久增加。全部精度保證須有反例檢查，不能只靠畫面看起來正常。

## 共同檢查方式

全批 spec 已將本篇一／二／四展開為 [三條因果鏈推演](../../../../design/spec/review/spec-integration.md)，七案共同對應 [驗證矩陣](../../../../design/spec/review/spec-verification.md)；均是文件推演，尚未執行遊戲驗證。

每案保留初始快照、輸入、時間、應改變與不應改變的欄位、允許的近似、玩家可知資訊。先證明正常路徑，再故意重送事件、打斷工作、換角色、破壞引用、調換無關物件順序，確認守門真的會抓錯。

各系統的細節門檻在自己的規格定；涉及多個系統的衝突先回 [規則選項](world-design-choices.md)，不要由某一份任務書私自選掉。
