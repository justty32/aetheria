# 三層模擬共同契約

[本層入口](README.md)｜← [世界框架](world-framework.md)｜[三層分工](roadmap-three-layers.md)｜規則：[principles](../../../../design/principles.md)｜用詞：[glossary](../../../../design/glossary.md)

## 目標

同一個世界可以粗算、細算、離場再回來，也能跨很久繼續演化。省運算只能省掉當下不重要的細節，不能省掉會改變世界的原因與結果。本檔是規劃契約，不代表現存程式都已符合。

## 權威、配額與交接

地圖主場與領域寫入權分開，詳見 [唯一寫入者](world-state-ownership.md)；AI、UI 與腳本只讀或提命令。

每個長期物件有穩定身分與所屬世界。地點、人物、勢力、職位、物品、事件的身分分開；所有權和位置是可變關係。地址與時間型別沿用既有規格，禁止用單一座標欄位兼任不同尺度。

大層掌握長期總量與約束；一部分展開到中層、小層後，該份模擬由目前主場層負責，粗層標明「已交出多少、從何時開始」。統一交接記錄須能表達：來源、目的、區間、交出的狀態與配額、尚未完成的工作、已確認的結果。

建議把「被細算的範圍」視為有期限的責任交接，而非複製世界。收回時確認來源與版本、結算差額、解除交接；重送同一結果不能再扣人或加錢。三層都必須遵守以下守恆：

| 類別 | 需要對上的帳 |
|---|---|
| 人口／部隊 | 原有人數＝留在粗層＋展開的人＋移出／死亡等已記錄變化 |
| 物資 | 期初＋生產＋輸入－消耗－輸出－損失＝期末；轉運中的貨有保管者 |
| 行動時間 | 細層已過區間不再由粗層補一次；未算區間仍要推進 |
| 個人例外 | 玩家或具名者的特殊結果從所屬統計配額扣抵，不能白送另一份存活 |
| 事件 | 每個結果有來源與處理狀態，跨層面孔不各自完成一次任務 |

不要求粗細兩次戰鬥逐步完全相同；依既有校準規則要求期望值無偏、誤差有界。進出地圖本身不得提供收入、治療、逃過死亡或重領物品的利益。

## 一條時鐘、多種頻率

時間單位、旬界、各層和平／交戰步長只引用 [時間模型](../../../../design/simulation/time-model.md) 與 [時鐘權威](../../../../design/simulation/time-clock-authority.md)。系統可以低頻決策、高頻推進，但不能各自決定現在幾點。

推薦共用排程責任：

1. 收集這段時間的合法命令與到期工作，固定順序與亂數來源。
2. 各主場層推進自己負責的範圍；觸及中斷條件就停在那個時刻。
3. 在有名稱的結算階段套用結果。收入、消耗、建造、人物、外交的先後必須有因果依據。
4. 到既有回合尾端處理結構變更，沿用場強、LOD、事件升降與逐出順序。
5. 提交可保存的一致狀態，再交還玩家操作權。

這是責任順序，不預先覆蓋現有 callback 次序；細化時對照每個 pass 的讀寫欄位。跨過數旬的旅行或等待，仍要遇到戰爭、斷糧、約定到期等重要事件；不能跳到終點後再宣稱途中都算過。

## 遠方仍在生活

| 解析度 | 算什麼 | 升降時保留什麼 |
|---|---|---|
| 詳算 | 個人位置、工作步驟、戰術選擇、局部環境 | 長期狀態與未完成工作；細節依資料層分類 |
| 粗算 | 人群／機構收支、人口結構、任務進度、戰爭與遷徙 | 配額、組成、時間游標、重要事實 |
| 暫不常駐 | 可由時間與輸入重建的部分延後算 | 持久差額、外來事件、規則版本、上次結算時刻 |

「沒載入」不能等於「完全不影響其他地方」。遠方商隊到貨、戰線推移、領袖死亡等對外結果，要能在權威排程中按時發布；延後的只是尚無人查詢、也不會提前影響外界的細節。發現未結算依賴，先補齊依賴再答查詢。

遠方人的身分、經歷與重要關係可保留摘要，不必常駐完整行為器。從統計中展開人物時，依既有 significance 規則抽取；已存在的人不能重新抽姓名、年齡或所屬。如何保存家庭與世代分布，交人物系統細化。

## 存檔與內容變化

沿用程序／持久／易失三層資料，不為了方便把所有現場物件照單全存。工作承諾、人物命運、庫存差額、已領獎勵與地形改造等不能因卸載而消失；暫態生命與位置依既有規則重建，新增持久需求須先明定其分類。

同 seed、基底規則與同一份完整歷史應可重放。被拒絕的命令、角色切換與內容加入都要有足夠語意，不把「收到輸入」當「完成效果」。跨平台數值、容器順序、亂數流仍受原則八約束。

M10 的全型別追加不能只驗載入器：新定義若被 AI、任務、生成器或 UI 使用，其查詢與快取都要接續到新版本。既有 ID 不位移；非法引用先整批拒絕，不能留下半個文明。

## 成本與失敗出口

每個系統聲明工作量依哪些量成長：活躍人物、場所、候選命令、關係邊、歷史長度或世界面積。先量測再分配預算，不把本案局部生成毫秒預算誤套到整個世界的年代生成。

- 限制每次搜尋的候選與重試，超出時保留合法的原計畫或明確回報失敗。
- 決策記錄保留近期細節，長期可摘要；不能刪除重放所需歷史來省記憶體。
- 生成與排程失敗要能指出輸入與階段；不能靜默少生一座城或吞掉工作。
- 隔離測試用沙盒與真世界；AI 預演不能消耗真正的物品或亂數流。

## 驗收情境

同一批輸入分別採持續詳算、離場粗算、頻繁進出、存讀中斷四種路徑。確定性項目逐項比較；近似項目事前列統計量、允許誤差與多種子檢驗。至少覆蓋人口、庫存、戰損、人物身分、建築、條約與任務。

另用負向案例證明檢查有效：重送一次戰果、刪一筆角色生命週期、重複使用同一物資、打亂容器順序、使依賴成環，都應被拒絕或被測試抓到。這些是未來驗收要求，本次不執行遊戲測試。
