# 規則選項與建議方向

[本層入口](README.md)｜← [世界框架](world-framework.md)｜[整合情境](world-scenarios.md)｜[既有原則](../../../../design/principles.md)

本檔把容易互相打架的選擇放在一起。**三層世界模擬器的方向已定；下面是規劃建議，不是已獲批准的新玩法或實作指令。** 不要求使用者現在回答所有問題，先保留推薦、理由與會牽動的地方。

## 已定的邊界

三層地圖、既有四鄰接與尺度、單一秒制時間、純 C++ 核心／Godot 呈現、內容種類資料化、結構變更在回合尾、粗細守恆與無偏、世界自帶規則與可重放歷史，均保留。引用參考不自動解除這些限制。

使用者已確認中地圖回歸原案：平時地方經營，戰時 Total War 式方陣指揮，仍為回合制。下列出手序是待比較細節，不再把 VCMI／Wesnoth 當主定位。展開見 [中層藍圖](roadmap-three-layers.md)。

## 需要先比較的政策

| 問題 | 建議方向 | 代價／替代選項 | 細化所在 |
|---|---|---|---|
| 中層怎麼輪到誰？ | 先保留現有命令與行動點；比較單位速度輪替、整側交替、雙方先下令再結算 | 三者不能混用；會改集火、反應、AI 搜尋與同一段世界時間的表示 | 戰爭；先做規則桌上推演再選 |
| 中層一枚棋子代表誰？ | 部隊／分隊是常態，具名軍官以引用附屬，個人詳算在小層 | 選全單兵會把 Site 尺度改成 Local；兵堆也不能忽略組成與傷勢 | 戰爭、人物 |
| 城建與生活誰算生產？ | 中層派工作與預算，小層詳算領出的份額，餘下粗算 | 全由中層算會讓個人工作沒有後果；兩層各算會憑空增產 | 經濟、生活、共同帳本 |
| 普通人要不要全存個體？ | 保留人口群組；重要人物、家庭與已形成的經歷逐步持久化 | 全個體成本高；只存人口數又無法延續關係與世代 | 人物、模擬契約 |
| 所有物品要不要逐件模擬？ | 普通同質物用批次；個別品質、裝備、具名經歷才用實例 | 轉換必有守恆記錄，不能生成新實例後不扣批次 | 力量／物品、經濟 |
| 國家要不要等於統治者？ | 國家、人物、職位各有身分；以關係圖表達統治 | 比直接共用 ID 多一層查詢，但可支援繼承、攝政與組織延續 | 政治 |
| 法律與繼承只有一種嗎？ | 以制度資料支援不同文化／組織；候選資格、分配、後果分開 | 不先做每種特殊制；每種制度都要能解釋合法性與資產去向 | 政治、人物 |
| 交通與市場多真實？ | 地方庫存＋有容量／時距的運輸；錢與實物分帳 | 比全球共享池貴；但封鎖、護送、飢荒與地理才有意義 | 經濟、旅行 |
| 魔法可以推翻物理嗎？ | 可以有超常效果，但每項要明寫代價、來源、作用範圍與粗細對應 | 未必物質守恆，但必須能對帳；不能拿「魔法」掩蓋重複結算 | 力量、環境 |
| 世界歷史要算多長？ | 世界設定決定年代範圍；只細化影響當代的因果與重要人物 | 全年表逐日細算成本高；只有隨機遺跡又缺原因 | 環境、故事、內容 |
| 敘事者能否憑空造危機？ | 模擬先產生原因；敘事只挑呈現時機。額外事件也必須具名入史 | 想做難度導演可另列設定，不能暗改 AI 資源或已知事實 | 故事、AI |
| 主線完結後世界是否停？ | 建議主線／角色篇章可結束，世界可續玩 | 若另做競技勝利模式，可獨立設定，不能把 4X 終局鎖定套進所有存檔 | 故事、呈現、內容 |

## 先前擱置的事

observer mark／獨特物件追蹤與 root 成長軸目前仍未獲開工指示。本次完整規劃可描述其用途，但不能把 ToME 的「發現就釘選」或人物歷史改名後悄悄當成已採用。

建議細化時分開三件事：M10 已要求的穩定人物與物品身分、一般故事歷史、會主動維持遠方細模擬的 mark。前兩者不應無故被第三者卡住；確實需要 mark 的效果要明列依賴。root 成長軸則先記錄所有會長大的資料與成本，尚不規定新分片方案。

## 如何把選項變成完整規格

S0–S11 已展開；跨規格分歧與代表情境集中於 [全批裁定清單](../../../../design/spec/overview/foundations/spec-decisions.md)。本篇保留原方向，不把新建議默認為已批准。

對每項選擇使用同一張表：提案、保留的既有要求、改變的玩家行為、三層資料歸屬、生效時點、失敗／取消／離場／存讀結果、AI 怎麼使用、代表情境與反例。

流程是先比較規則，再定資料與算法，最後才開實作任務書。未定數值可以留參數，但「誰算、何時算、哪裡存」不能以待調參為由含糊帶過。這些文件可繼續細化，並不構成現在開工的授權。
