# 一份狀態，只由一套規則改動

## 地圖主場與系統寫入權是兩件事

「這件事目前在 Local 詳算」不代表人物、生活、AI、戰鬥四個模組都能各存一份人物血量。地圖主場決定在哪個解析度推進；下表決定哪套領域規則可以驗證並改動。AI、UI、任務與腳本都只能查詢或提出命令。

這是設計上的唯一寫入責任，不要求所有欄位塞進一個物件。資料可按 zone 儲存，各系統仍透過授權介面與主場提交線改動。

| 狀態 | 唯一負責的規則 | 其他系統如何使用 |
|---|---|---|
| 地形骨架、氣候與自然場 | 世界環境 | 生成器、行軍、經濟、生活讀快照；改地形走環境效果 |
| 勢力、職位、法律、控制權與條約 | 政治 | 戰爭交勝負證據；人物交死亡／繼承觸發，不能自行換城主 |
| 庫存、批次、運輸保管與支付 | 經濟的物資帳本 | 製作、軍事、生活先預約再消耗／產出；裝備引用物品，不複製庫存 |
| 具體物品身分、品質與裝備狀態 | 物品規則（內容／力量的物品子題） | 帳本追蹤保管與數量；戰鬥、生活提出磨損、使用與轉移請求 |
| 人物身分、家庭、關係與職涯 | 人物 | 政治任命、工作成果、事件經歷以具名效果提交；AI 不私改忠誠 |
| 傷病、需求、健康進展 | 生活中的健康／需求規則 | 戰鬥交傷害，法術交效果，人物讀生命狀態；死亡再通知人物／政治 |
| 技能、知識、力量與能力效果 | 力量與知識 | 工作、探索、戰鬥交練習或獲知證據，統一驗證成長與代價 |
| 工作進度、預約、取消與交接 | 工作規則 | AI 選工作，聚落派工作，生活執行；預約數量由同一帳本確認 |
| 旅行進度與世界位置 | 旅行規則 | 軍隊、商隊、人物共用移動合法性；精細移動提交已過區間 |
| 戰鬥行動、命中與戰場結果 | 對應層的戰鬥規則 | 透過健康／物資規則套效果；戰後向上提交，不直接改政治 |
| 世界事實、任務與傳播記錄 | 事件／歷史規則 | 收到其他領域的已確認結果才記事實；任務後果仍請求領域規則 |
| 個人／勢力知識 | 情報規則（故事子題） | 從見聞與傳播更新，AI／UI 讀各自可知內容，不讀全知世界 |
| 解析度、交接範圍、提交序列與世界時鐘 | 共同模擬協調器 | 各系統登記到期工作與輸入輸出，不自行再造一個時鐘 |

## 一次跨系統操作

以「製作一把劍」為例：工作規則取得預約 → 物資帳本扣材料 → 力量／製作規則決定合規品質 → 物品規則產生實例或批次 → 帳本記入庫與保管 → 人物獲得工作經歷 → 歷史記已發生的事。任何步驟失敗，要依事先定好的提交／取消規則處理，不留下已扣材料又無工作紀錄的半套結果。

**批次不等於逐件物品**：普通同質資源可以批次 ID＋數量存在。只有展開成具體物品時才發個體 ID；從批次拆出必扣量，併回要符合品質／來源等可合併條件並註銷原引用。具名物或有持久個別經歷的物品不任意併回。精確政策在物品系統細化。

## 各主場層如何使用

粗算時，健康與生產規則操作人群統計；詳算時，同一領域規則以個人與現場工作作輸入，扣抵高層交出的配額。具體公式可以不同，但結果要符合守恆與校準契約。

人物的所屬地點、旅行區間與當前主場必須可追查；可拋棄的是已明定可重建的局部姿態、路徑或暫態格位置，不能把「人究竟在哪裡」整件事丟掉。普通物、個人持有物、角色控制資料也必須明確區分。

驗收時查「誰真的寫入」，不只查資料型別存在；任一系統新增直接改別領域容器的旁路，都要重新檢視此表與提交流程。
