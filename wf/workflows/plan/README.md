# plan — 動工計畫工作流

← [WORKFLOWS.md](../../WORKFLOWS.md)｜[INDEX](../../INDEX.md)

**什麼時候用**：方向已定（調查做完、使用者已裁定要做），要把它**展開成可派工的動工計畫**——
拆輪次、排依賴、劃互斥線、定每輪的 Done when。

> 與別的工作流的界線：
> **investigation**＝盤點現況（不提方案）；**spec**＝方案還要討論；
> **plan**＝方案已定，展開成輪次與任務書的**藍圖**；**feature-dev**＝照任務書動手。
> plan 的產物是藍圖，**不是任務書本身**——任務書照藍圖逐輪開進 `wf/inbox/`，
> 這樣每輪開工前還有一次「照現況修正」的機會。

## 流程

1. **先讀對應的調查報告**（[investigation/](../investigation/README.md)）——沒有調查先去做調查。
   計畫裡的每個斷言都該有調查佐證，不要在計畫階段重新考古。
2. **定一句話方案**：整個計畫能不能壓成一句話？壓不出來表示方案沒收斂，退回 spec。
3. **拆輪次**：每輪一個變因、一個可驗證的 Done when（見
   [one-variable 原則](../../OPS-NOTES.md)）。標明**輪與輪的依賴**與**可並行的線**。
4. **劃互斥線**：並行線各自可寫哪些路徑，寫進計畫；
   **存檔版本號與 CMakeLists 新增檔一律單線獨佔**（撞過，見 [KNOWN-TRAPS](../../KNOWN-TRAPS.md)）。
5. **列裁定點**：計畫裡凡是要使用者拍板的，集中一檔、附建議預設值，
   並同步登記 [WAIT_USER](../../WAIT_USER.md)。**不擋路的裁定點不阻塞開工。**
6. **寫進本資料夾**（一計畫一組檔，`<主題>.md` 為總覽，過 8 KB 按子題拆），
   在下面清單加一列。
7. **派工照 [dispatch 協定](../../OPS-NOTES.md)**與計畫的互斥線執行；
   計畫與現實不符時**改計畫檔**，不要讓任務書偷偷偏離藍圖。

## 計畫的固定骨架

總覽檔照這五節：

| 節 | 內容 |
|---|---|
| **一句話方案** | 整個計畫壓成一句話 |
| **輪次地圖** | 波次 × 輪次表：每輪一行（變因、Done when、依賴、互斥線）|
| **全局約束** | 版本號政策、不動的東西、跨輪不變量 |
| **裁定點** | 指向裁定檔；哪些擋路哪些不擋 |
| **完成判準** | 整個計畫的端到端驗收（不是各輪 Done when 的總和）|
