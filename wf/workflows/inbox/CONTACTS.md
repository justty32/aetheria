# CONTACTS — 通訊錄（已知 agent 的地址）

← [inbox README](README.md)

**地址 = inbox 資料夾位置。** 要寄信給某個 agent，先在這裡查它的 inbox 路徑和它負責什麼。
寄信方式見 [README](README.md)；信裡記得寫**回信地址**。

> 這份是**方便的快取，可能不全**。權威永遠是對方資料夾自己的 `AGENTS.md`／`README.md`。

## 本專案的分工

aetheria 採**規劃與實作分離**的協作模式（使用者於 2026-08-15 訂定）：

| 角色 | 是誰 | 做什麼 | **不做什麼** |
|---|---|---|---|
| **Opus 5 規劃者** | 設計 session | 寫 `design/` 的設計文件、定架構、開任務書、**回頭審閱實作** | **不寫實作程式碼** |
| **實作 agent** | 使用者另外開的 session | 依 `wf/inbox/` 的任務書寫 `core/`／`bridge/`／`godot/` 的程式碼與測試 | 不自行改 `design/`（有異議寫信回報） |

流程是一個循環：

```
規劃者寫設計 + 任務書 → 使用者開實作 agent → 實作 agent 做完寄信回報
   → 規劃者審閱實作、更新設計 → 開下一份任務書 → …
```

## 指揮關係

**Opus 5 規劃者是指揮者**（使用者 2026-08-16 訂定）。實作 agent 依規劃者的任務書與裁定行事；
有異議寫信回報，但**不自行改變優先序、不自行開新里程碑**。

規劃者的裁定**優先於實作 agent 的判斷**，包括「這樣寫比較好」這種技術意見——
有意見寫進回信，照做在先。唯一例外是**撞到現實**（編不過、效能達不到、庫不支援）：
那時候停下來寫信，附證據，不要硬幹。

## 同步規約（兩個 agent 共寫同一個 repo）

`SESSION-LOG.md`／`WAIT_USER.md` 是兩邊共寫的。**整段重寫會靜默蓋掉對方的條目**——
已經發生過一次（規劃者寫的「M0.5 已寄出」被實作端的提交整條移除，沒有替代條目，
於是活狀態憑空消失）。

三條規則：

1. **`SESSION-LOG.md` 的「最新進度」分成兩個具名區塊**：
   `### 規劃者` 與 `### 實作者`。**各自只寫自己那塊，永遠不碰對方那塊**，
   連「順手整理」都不行。跨區的事寫信，不要直接改對方的區。
2. **in-flight 必須有記錄。** 開始做一份任務書時，在自己的區塊寫一行「X 實作中」；
   做完換成下一個狀態或整條刪掉。**任何時刻都不該出現「沒人在做事」的假象**——
   session 隨時可能斷，SESSION-LOG 是唯一的交接面。
3. **信件不修改，只新增。** 已寄出的信不回頭改內容（搬進 `done/` 時補相對連結深度除外）。
   要更正就寄新信。

這三條是[原則](../../../design/principles.md)「同層物件永不直接溝通，一切互動經共同上層或
共用物中介」套在文件上：兩個 agent 不共寫同一段文字，各自寫自己的區、靠信件中介。

## 不空轉規則

做完一份任務書、寄出回信之後：

1. `wf/inbox/` **有**收件人是你的新任務書 → 直接做。
2. **沒有** → 做「待辦池」（下一節）最上面那項。
3. **待辦池也空** → **停下來**，在 SESSION-LOG 自己的區塊寫「待任務書」。
   **不要自己開新里程碑、不要自己擴大範圍**——里程碑的順序是設計決策，歸規劃者。

## 待辦池（規劃者維護，實作者依序取用）

空閒時做這裡的，做完一項就從清單刪掉。**這些都是已核准的，不必再問**：

- `.gitignore` 的 `build/` 改成 `build*/`（故障注入會開 `build-xxx/`，現在擋不住）
- 補 `core/` 現有公開型別缺的「標頭三行說明」（`cpp-conventions.md` 要求，`version.h` 沒有）

## 共用收件匣

**兩個角色共用 aetheria 的同一個收件匣** `~/repo/game_dev/aetheria/wf/inbox/`。

這偏離了 README「一個 inbox 一個 agent」的預設，是刻意的：
兩個角色在**同一個工作資料夾**輪流上工，各自另立地址沒有意義。
辨識靠信件開頭的**寄件人／收件人**欄位，不靠資料夾。

規約不變：**信在頂層 = 未處理，辦完 `mv` 進 `done/`**。
進來先掃頂層，只辦「收件人」是自己的那幾封。
